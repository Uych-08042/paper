# Stage-136 同裁剪第二峰整段闭环

Stage-135 在预选失跟窗口新增 3 次恢复，28 个稳定窗口均未触发。Stage-136 检查逐帧应用这些规则后，累积的历史和裁剪变化是否带来整段收益。 [Stage-135 结果复核](STAGE135_RESULTS_REVIEW.md)

| 组别 | 写回下一帧搜索状态的框 |
| --- | --- |
| 原生 SGLA | Hann 第一峰对应框 |
| 仅分差 | 有不同的第二峰框且相对分差 ≤ 0.20 时选第二峰，否则沿用第一峰 |
| 完整规则 | 保留分差要求，同时要求两框 IoU ≤ 0.20、第二峰与历史外推框的 IoU 优势 ≥ 0.10 |

三个组使用同一原生权重和首帧模板。都在自己上一帧的输出框上裁剪，每帧前向一次，两峰来自同一次响应。完整规则的历史外推直接继承 Stage-135。三组从同一首帧出发，分别独立写回。在第一次换框之前，处理组必须复现本轮原生输出。阈值保持冻结。

28 个已消耗开发视频，每组 29,047 个跟踪帧及相同数量的物理搜索，三组共 84 条新轨迹、87,141 次搜索。用一张 L20 或 L40 重跑三组。与归档是相同设备和运行环境时，额外核对本次原生轨迹。当前环境变化时以本次同卡原生组为配对基准，续跑切卡需单独输出目录。

## 结果判读

- AUC 按现有成功率协议逐视频计算并等权汇总。三组两两配对，按视频重采样得到开发样本的描述性区间。
- 报告低 IoU 帧、持续至少 32 帧的失跟、最长失跟长度占比、未恢复事件，以及原生无确认失跟视频中新出现的确认失跟和最差 AUC 变化。
- 每条轨迹记录改选总数、首次改选和最长连续改选。逐改选记录同时保留同一次裁剪的两个候选 IoU，便于定位当帧误选。该记录也涵盖由前序改选改变的状态。

本轮用完整开发轨迹检验累积效果。独立确认、其他数据集和训练迭代均留待后续。

## 运行

```bash
bash tools/run_stage136_peak_closed_loop.sh
```

默认输出 `output/stage136/same_crop_peak_closed_loop_v1`，以 `STAGE136_GPU` 指定逻辑设备，默认 0。每条视频分支完成后保存，重复执行将校验并复用本次实验中已完成的分支。结果包 `stage136_results_*.txt` 含决策、配对统计、逐视频结果和失跟事件。逐改选详情单独保留为 `stage136_switches.csv`。
