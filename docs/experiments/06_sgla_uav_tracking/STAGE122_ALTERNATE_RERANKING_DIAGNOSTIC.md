# Stage-122 备用搜索的候选供给与评分重排

状态：**已实现并通过本机合成缓存测试，正式逐帧诊断待服务器运行。** 使用 Stage-121 已完成的 L40 结果，覆盖 28 个开发视频、两个评分器种子、56 对轨迹及全部 358 次实际替换。CPU 读取已有轨迹和评分器，图像读取、GPU 搜索、训练及确认集推理均为零。

## 要验证的问题

备用裁剪既能提供一个新框，也能改变其他三框的关系特征。前者可能通过选择备用框改善跟踪，后者可能在备用框未获选时改变输出。Stage-121 的逐轨迹归档只能看到总体次数和分数。56 条备用轨迹中，27 条未触发，AUC 都和对照相同；11 条启用但从未选中备用槽位，共 14 次替换，其中只有 0174／2313 的 AUC 变化；其余 18 条曾选过备用槽位，AUC 分别有 5 条升、8 条相同、5 条降。这些分组来自事后轨迹行为，用于说明为何需要逐帧核对。

## 分析步骤

1. 对齐生成共享和备用共享。核对首次替换前的完整缓存前缀，记录首次替换、首次前三槽分数差、首次输出框差及首次前三槽裁剪差。检查哪次替换和第一次输出分叉发生在同一帧。
2. 所有实际替换均列入账本。当前帧只有在两边预测框历史、生成器输入以及前三个候选的父框、裁剪、响应图、基础特征和解码框一致时，才纳入评分归因。轨迹分叉后的非匹配状态单列。
3. 按原权重重算两个完整候选集合的四个分数，再用同样的决胜规则，在共同的前三框中分别找最高分框。将实际输出差异分成备用框获选、原第 4 框被挤掉、共同框重排及其余完整集合决胜差异。另报告补出或移除的好候选，其中好框定义为 IoU ≥ 0.5。
4. 在完全匹配的帧上，单独替换或恢复平均 IoU、最大 IoU、平均中心距离、平均尺度差、Hann 相对排序这五项关系特征，含各自的平方项。记录哪一项单独足以复现前三框的改选，以及恢复哪项足以让前三框回到原选择。单项都不改变选择时仍可能存在联合效应。
5. 用真值核对各帧 IoU 和原 AUC，并列出第一次输出分叉后的最多 31 帧表现。该窗口记录两条实际轨迹的后续情况。其间可能再次触发并处于不同历史，单次替换对未来的作用无法从这个窗口单独归因。

0174／2313 和 0089／2312 用于解释相反例子，报告始终保留全部开发轨迹。完成状态表示缓存诊断完整，当前方法的采用结论仍以 Stage-121 完整对照为准。 [Stage-121 结果](STAGE121_RESULTS_REVIEW.md)
