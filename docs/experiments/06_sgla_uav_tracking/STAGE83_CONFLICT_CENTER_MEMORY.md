# Stage-83 冲突前搜索中心短时保留

Stage-79 显示一次选错就能把后续搜索带偏。Stage-82 的同历史对照未支持继续使用当前混合尺度。Stage-83 沿用原始尺寸规则，单独检验短时保留冲突前的搜索中心能否减少完整轨迹失跟。 [Stage-79 结果](STAGE79_RESULTS_REVIEW.md) · [Stage-82 结果](STAGE82_RESULTS_REVIEW.md)

## 固定机制

对去重后的合法候选比较 PPO 前两名。当首选与次选的概率比不大于 1.10、两个框的浮点 IoU 不大于 0.20，且中心距离至少为两个框面积平方根均值的 0.50 倍时，触发短时保留。所有门槛在运行前固定，触发不使用 GT 或未来帧。

设冲突发生在第 t 帧。当前发布框仍由冻结 PPO 选择。缓存进入 t 时最新预测框的中心。之后 q0／q1 始终用最新预测中心，q2／q3 在 t+1 和 t+2 使用缓存中心，宽高都沿用原候选规则。t+1 的原规则已经给出同一中心，直接运行原路径。t+2 仅当取整裁剪实际变化时采用缓存中心。保留期间不续期，随后回到原规则。

三臂使用相同的原生 SGLA 权重、模板、解码及各自的预测历史。冻结 PPO 仍按实际候选作决定，保留中心仅通过候选搜索影响后继决策。原生 SGLA 每帧一次搜索，原尺度 PPO 与短时保留 PPO 每帧各四次搜索。

## 全轨迹与判读

12 个开发视频，两个既有 PPO 种子，共 60 条完整轨迹、229,925 次搜索和 1,609,475 次 block 调用。三臂在同一 GPU 从首帧初始化并跟到视频结束，原生与原尺度 PPO 同时做 Stage-76 复现核对。新训练、在线 GT、额外搜索和确认集推理均为零。

主比较为短时保留对原尺度 PPO。逐视频等权，种子先在视频内平均。开发门槛保持至少 +0.5 AUC 点、视频配对区间下界大于零、低 IoU 和最长失跟比例不劣于原尺度 PPO、原生稳定视频零新增失跟。另报告逐种子恢复和未恢复事件，以及触发次数、实际变化裁剪和只有保留对提供好框的帧数。该计数比较同一次搜索的两个候选对，可说明候选由哪一对提供，无法推断原滞后搜索的反事实表现。28 组确认集仅绑定指纹，留待方法定型。

## 运行

```bash
cd ~/workspace/paper
mkdir -p output/stage83
nohup bash tools/run_stage83_center_memory.sh > output/stage83/run_stage83.log 2>&1 < /dev/null &
```

使用已分配的 L20 或 L40。需要 Stage-76、77、82 原始运行目录和原生 SGLA 检查点。可用 `STAGE76_ROOT`、`STAGE77_ROOT`、`STAGE82_ROOT`、`STAGE83_ROOT`、`STAGE83_GPU` 和 `CHECKPOINT` 覆盖。续跑绑定相同运行指纹与物理 GPU，换卡需单独输出目录。用 `cat output/stage83/run_stage83.log` 查看结果包路径，回传 `stage83_results_*.txt`。已完成目录可用 `--pack-only` 校验导出。
