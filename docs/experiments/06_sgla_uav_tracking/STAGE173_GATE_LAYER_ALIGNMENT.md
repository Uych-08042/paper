# Stage-173 门控评估层与实际执行层的对齐诊断

Stage-172 的 33 个取样起点中有 23 个，门控评估的收益提议层和排序器实际推荐的层不同。Stage-173 从同一跟踪状态比较这两个层各自的风险预测和实际后效。

## 固定对照

复用 Stage-172 的 33 个在线事件取样起点和 Stage-171 的 6 个定点起点，共 39 个起点。两个来源分别汇总。每个起点从对应 Stage-170 历史恢复首帧模板、父框和最近最多 16 帧统计量。三个分支分别在起点执行原生层、收益提议层和排序推荐层。之后统一沿用原生 SGLA 选层，各自写回预测框并续跑 128 帧。

全部 117 条分支按一次裁剪、七个 Transformer 块和一次预测头审计，总计 15,093 次搜索。收益、退化和排序模型及阈值复用 Stage-167 校准。对提议层和排序层分别记录预测收益、下降量和门控分。提议和排序相同时，两个分支须逐帧一致。同运行身份下核对起点的三个层编号和提议门控分，跨设备单独记录复现偏差。

## 读结果

三种决策规则共享此次的起点和真实续跑结果。表格模拟原提议分通过后执行提议层、原提议分通过后执行排序层，以及用排序层自己的门控分通过后执行排序层。第三种规则暂用原门槛。三种规则分别记录放行数、阻止的有益动作和放行的有害动作，计数门槛为平均 IoU 差 0.01。`stage173_outcomes.csv` 在风险模型原先拟合的 32 帧窗口内，比较两种风险预测对排序层实际退化的绝对误差。

`stage173_paired.csv` 在同一批有效起点直接比较规则变更，按视频等权汇总 32、64、128 帧的效应。优先读 Stage-172 取样组，再看其中门控提议与排序不同的子组。核心验证是对齐评估后能否减少有害放行，同时保留有益换层。若出现净收益，再以独立校准确定门槛并验证完整视频。样本来自原提议门控已经通过而且可匹配的状态，结论适用于这类机会。

## 运行

沿用前几轮设置的 `STAGE170_ROOT`、`STAGE171_ROOT` 和 `STAGE172_ROOT`。与源运行不同的 L20／L40 设备使用独立的 `STAGE173_ROOT`。

```bash
mkdir -p output/stage173
nohup bash tools/run_stage173_gate_layer_alignment.sh > output/stage173/run_stage173.log 2>&1 < /dev/null &
tail -f output/stage173/run_stage173.log
```

脚本显示总体进度，完成后生成 `stage173_results_*.txt`。
