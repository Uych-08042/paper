# Stage-175 失跟与恢复事件附近的同状态续跑

Stage-174 的 100 个主起点只有一次新增未恢复失跟。该起点的整窗平均 IoU 差仍为正，均值退化标签为零。Stage-175 收集动作相关的失跟和恢复标签，为后续事件监督检查样本支持。

## 起点与对照

使用 Stage-170 固定冷却加排序策略的已封存失跟与恢复时间。每个失跟起始帧或恢复起始帧，在前 1 至 4 帧和前 5 至 16 帧各选最近的可用起点。恢复起点须已确认失跟，窗口须覆盖存档恢复及其后 32 帧宽限和恢复确认。排除 Stage-173／174 已回放起点以及同一序列的重复帧。各起点续跑 128 帧，片尾不足时使用至少 32 帧的共同窗口，另报告完整 128 帧结果。曾作定点诊断的源组和 Stage-174 已知严重退化所在源组单列统计。

每个事件起点尝试匹配一个普通起点。普通起点与其同视频、同原门控状态、同长度，起点前 16 帧和续跑期内无存档失跟事件。按固定哈希顺序选择，记录匹配失败。事件时间与普通窗口资格仅用于离线抽样。

两分支在起点执行原生层或固定的 Stage-167 排序推荐层，此后分别反馈自身预测框并统一用原生选层。使用相同运行身份时逐点核对归档原动作的框和门控分。调用预算仍为每帧一次裁剪、七个块和一次预测头。

## 事件标签与读结果

用共同的已发生 IoU 前缀恢复失跟状态。按原指标定义，连续三帧低 IoU 确认失跟，连续三帧 IoU 至少 0.5 确认恢复。排序分支新增失跟指该分支确认的事件在起点后的时段不与任何原生分支失跟重叠。对起点前已经确认的同一起始事件，原生分支恢复且有足够的后续观察，排序分支在原生恢复后 32 帧内仍未开始对应恢复，记为丢失恢复。到共同窗口终点排序仍处于失跟、原生已处于跟踪时，记为新增未恢复失跟。无效 GT 的窗口剔除。已到窗口终点的标签仍受后续未观测帧限制。

主事件风险是新增未恢复失跟或丢失恢复。报告同时检查有事件风险但整窗 IoU 降幅小于 0.05 的情况，以及整窗 IoU 不降、均值退化标签为零的情况。匹配起点比较按源组等权的事件风险标签比例，仅描述此次抽样能否富集事件。主支持来自完整 128 帧窗口和非定点源组。若两个留出折均有事件风险且合计至少覆盖三个源组，则支持尝试事件监督。此轮只采集标签和检查支持。

## 运行

沿用 Stage-170、173 和 174 的输出路径及原始 checkpoint。GPU 运行身份变化时使用独立的 `STAGE175_ROOT`。

```bash
cd ~/workspace/paper
mkdir -p output/stage175
nohup bash tools/run_stage175_event_risk.sh > output/stage175/run_stage175.log 2>&1 < /dev/null &
tail -f output/stage175/run_stage175.log
```

脚本输出总体进度，支持缓存续跑，结束后生成 `stage175_results_*.txt`。`stage175_summary.csv` 汇总有效标签，`stage175_matches.csv` 和 `stage175_paired.csv` 提供匹配对照。
