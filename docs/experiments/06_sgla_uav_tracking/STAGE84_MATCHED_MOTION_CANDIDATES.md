# Stage-84 固定四候选与运动生成四候选

用同历史回放检验，在每帧四个候选槽位、相同尺寸和相同冻结 SGLA 下，根据过去预测框生成搜索中心能否改善候选供给。Stage-82 曾发现更换尺度布局可能丢失原有好框。Stage-83 的额外中心保留在完整轨迹上退化。本轮将改变限定在搜索中心，分别统计新得到和失去好框的帧。 [Stage-82](STAGE82_RESULTS_REVIEW.md) · [Stage-83](STAGE83_RESULTS_REVIEW.md)

## 固定对照

| 臂 | 搜索父框 |
|---|---|
| 固定四候选 | 最新或滞后中心与最新或历史宽高交叉组合 |
| 运动生成四候选 | q0 原样保留，其余三个槽位用预测位置和互补覆盖选择中心。每个槽位保留固定臂的宽高 |

两臂都在同一 GPU 用当前帧、首帧模板和 Stage-76 已记录的同一段预测历史运行。覆盖 12 个开发视频的两个原尺度 PPO 种子，共 24 条历史、27,050 个非初始化状态，逐帧纳入。任何一臂的输出都不写回历史。两臂均不执行选择器；GT 仅进入离线打分。确认集未参与。

### 生成规则

1. 取最多五个历史框。少于四个时复用固定布局。用历史框面积平方根的中位数作单位，计算中心位移的逐坐标中位数，速度上限为每帧一个单位。
2. 用估计速度把各历史中心外推到当前帧，取逐坐标中位数作预测中心。预测点的绝对中位差乘 1.4826，限定在 0.25～1.0 单位之间，用作横、纵偏移幅度。七个假设点由最新中心、滞后中心、预测中心和预测中心的四个轴向偏移组成。
3. 若最新外推点与更早外推点的中位数相距超过 0.5 单位，提高滞后位置的权重。常态下最新／滞后／预测的权重为 2／1／3，跳变时为 1／3／2。四个偏移点分别为 0.5。假设中心限定在画面范围内。
4. 从固定 q0 开始，按顺序为每个剩余槽位选一个中心。每个裁剪对假设点的支持按离取整后裁剪中心的距离衰减，高斯尺度为该裁剪边长的四分之一。已选裁剪对每个点取最大支持。每次选择使总加权支持增加最多的裁剪。同一帧优先选取整后尚未出现的裁剪。没有新裁剪时使用该槽原来的父框。

这些值是首轮预设的几何规则。宽高按槽位锁定，后续可以把中心作用与尺度作用分开讨论。

## 预算与判读

每臂每状态四个逻辑槽位，共 108,200 槽位／臂。同帧浮点父框完全一致时复用同一次原生推理。即使取整裁剪相同，浮点父框不同仍各自执行，以保持框坐标映射正确。两臂物理搜索合计上限 189,350，实际调用及有效裁剪数写入报告。固定臂取整裁剪与裁剪像素哈希必须逐帧复现 Stage-76，输出框和层差异单独记录。两臂的正式比较使用本次同卡回放结果。

主指标为每帧四个已解码候选中的最佳 IoU，以及最佳 IoU ≥ 0.5 的帧比例。先对每条历史取均值，再在每个视频内平均种子，最后按视频等权。视频配对 bootstrap 使用 20,000 次采样。候选供给通过门槛要求最佳 IoU 差的 95% 区间下界大于零、至少七个视频改善、好框比例净增加。另报告新增与丢失好框的帧数。通过只支持进一步测试选框与闭环稳定性。

## 运行

在服务器仓库的 `sglatrack-test` 环境执行。使用已分配的 L20 或 L40。

```bash
cd ~/workspace/paper
mkdir -p output/stage84
nohup bash tools/run_stage84_motion_candidates.sh > output/stage84/run_stage84.log 2>&1 < /dev/null &
```

使用 `STAGE76_ROOT`、`STAGE84_ROOT`、`STAGE84_GPU` 和 `CHECKPOINT` 可覆盖默认值。Stage-76 原始运行及其绑定的上游收据留在原处。相同运行指纹和物理 GPU 可从已封存的轨迹缓存续跑，换卡使用新输出目录。运行结束后用 `cat output/stage84/run_stage84.log` 查看回传包路径。回传包含 decision、paired、video summary 和 scope。完整逐帧表留在服务器，由 `--pack-only` 校验哈希后打包摘要。
