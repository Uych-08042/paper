# Stage-95 恢复失败的裁剪覆盖与完整响应诊断

Stage-94 的四次未匹配恢复，在原 PPO 恢复首帧均缺少 IoU ≥ 0.5 的输出候选。Stage-95 检查候选不足时，目标是否仍在搜索区域、响应图能否解码出好框，以及好框是否对应可自动提取的独立峰。结果用于决定是否进一步修改 SGLA 的单峰解码或搜索区域生成。

## 固定样本

绑定 Stage-94 决策 `e57c25f2abbb560eb388a080c5d99d749a0bb62614eae1cc27b14efcb7d4b44c`，覆盖全部 25 个原 PPO 恢复事件。4 个未匹配事件和 21 个已匹配事件均进入诊断。

每个事件固定提取 PPO 失跟起点前一帧、失跟起点、恢复前一帧、恢复帧和恢复后一帧。若 Stage-94 记录窗口内第一次筛选历史缺好框而 PPO 有好框，追加该帧。按序列、种子和帧去重后共 137 个时刻。事件定义和首次缺好框的时刻使用既有开发标注，因此这些时刻只用于离线诊断。

每个时刻分别从原 PPO 和筛选历史轨迹重建此前预测框历史，使用原始首帧模板和同一冻结 SGLA 重放四种裁剪。两组分别使用其自身历史，GT 只在前向结束后计算指标。模型的输入随历史变化，同帧对比不能唯一分离某个早期动作的长期影响。

预算为 274 个历史状态、1,096 次搜索、7,672 次骨干块调用。每个状态缓存完整响应、尺寸和偏移图，已完成状态可复用。

## 解码与诊断

复用原 CENTER 全格点解码、原生裁剪和形状指标，并复用 Stage-28 的峰提取规则。分别在原响应和 Hann 加权响应上提取 3×3 局部极大值，按分数排序，以解码框 IoU > 0.5 去重，保留最多五个峰。这是本轮固定的探针预算。GT 只用于评价已提取的框。

| 顺序 | 状态类别 | 条件 |
|---|---|---|
| 1 | `selected_good` | 原轨迹选择的槽位在重放时 IoU ≥ 0.5 |
| 2 | `outer_choice_missed` | 其他槽位的单峰输出有好框 |
| 3 | `weighted_peaks_have_good` | 加权响应的保留峰中有好框 |
| 4 | `raw_peaks_have_good` | 原响应的保留峰中有好框 |
| 5 | `dense_good_outside_kept_peaks` | 全格点有好框，但前述保留峰未覆盖 |
| 6 | `covered_dense_lacks_good` | 至少一种裁剪保留目标中心且覆盖 ≥ 90%，全格点仍无好框 |
| 7 | `crop_support_limited` | 前述条件均未满足，目标裁剪支持有限 |

无效 GT 单独记为 `invalid_gt`。同时保留每种裁剪的覆盖率、原图可见比例、好框分数排名、目标是否有局部峰、中心误差和宽高比。离线替换尺寸或中心的 IoU 仅诊断几何误差，不进入跟踪。类别按顺序互斥分配，其余指标仍完整保留。

若缺候选主要落在第三或第四类，可继续验证多峰候选的选择与闭环收益。若主要落在第六类，需进一步检查表征和定位，不能仅凭这一类别认定尺寸是唯一原因。若主要落在第七类，优先检查历史驱动的搜索区域。事件关键帧的统计不代表整个数据集中的发生率，均不设置方法采用门槛。

## 来源与硬件

运行前核对 Stage-76、89、93、94 与确认组封存边界。新重放必须精确复现原裁剪输入，包括像素哈希，且通过原生解码和调用计数检查。

支持 L20 和 L40，在当前分配卡上成对重放两种历史，记录 GPU 型号、UUID 和与 Stage-93 的差异。逐状态报告原输出与重放输出的最大框误差、好框可用性是否变化。决策中的 `source_correspondence_pass` 要求所有状态框误差 ≤ 原协议容差且好框可用性未变化。未通过时，输出解释为当前硬件上的固定历史重放，需先核对差异再解释旧失败。新重放不产生完整闭环结果。

## 服务器执行

同步新文件后，在原 `sglatrack-test` 环境执行。

```bash
bash tools/run_stage95_response_diagnostic.sh
```

输入默认为既有 Stage-76、89、93、94 目录，原 V1 checkpoint。可用同名 `STAGE*_ROOT` 环境变量指定其他目录，`STAGE95_GPU` 默认 0。输出为 `output/stage95/recovery_dense_response_v1/`。运行后脚本打印结果包路径，回传包内含 decision、25 个事件和类别汇总。状态及裁剪明细和 NPZ 缓存保留服务器。

需要后台运行时，先创建输出根的父目录，把日志放在该父目录。

```bash
mkdir -p output/stage95
nohup bash tools/run_stage95_response_diagnostic.sh > output/stage95/run_stage95.log 2>&1 < /dev/null &
tail -f output/stage95/run_stage95.log
```

同一运行的代码、来源与硬件身份受 manifest 绑定。中断后保持相同身份可续跑，硬件身份变化时通过 `STAGE95_ROOT` 指向新的输出目录。完成后可用 `bash tools/run_stage95_response_diagnostic.sh --pack-only` 再次校验和打包。

本机已通过五项 CPU 测试，覆盖完整解码与峰提取、尺寸失真、裁剪外目标、无效标注、137 个固定时刻、共同入口重放与缓存复用、哈希篡改拒绝。网络前向由测试观测器提供，真实 SGLA GPU 重放待服务器运行。
