# Stage-101 全部尺寸触发的匹配回放与短后继诊断

## 本轮问题

Stage-100在线短暂尺寸调整pulse比gated低0.6221 AUC，虽然补回3次PPO恢复，却又丢失2次。0304和0169严重受损，0226与0307／2171获益。pulse只在4.31%的跟踪帧改变裁剪，降低频次仍未保护原有能力。

本轮在相同过去状态上检验：取消某一次尺寸调整，是否改变当前候选、PPO选择和最终外观选择，以及差异如何传入后续搜索。保留SGLA及原PPO／外观写入机制，新增训练、完整新轨迹和确认推理均为0。旧模型、实验代码和产物保持不变。

## 全量当帧匹配

绑定Stage-100决策`9b237b9c93ad05f7e9fbcf38d203c38ad33cfad432ff184c6a3069f353054915`及原生缓存兼容回执。先验证完整产物、来源和代码，再重建Stage-100全部40个四候选单位的gated／pulse记忆与决策，读取pulse的全部1,834个实际触发帧。

每个触发从同一条pulse轨迹截取截至该帧以前的预测框、原首帧外观anchor、过去外观写入、尺寸引用及上一帧分歧状态。比较两项处理：

| 处理 | 当帧尺寸 | 当前选择及之后状态 |
|---|---|---|
| `keep` | 保留原可信尺寸调整 | 原PPO及外观决策 |
| `skip` | 仅这次改回普通尺寸 | 在新候选上重算同一PPO及外观决策 |

q0／q2的父框保持不变，q1／q3恢复普通历史尺寸。每个处理仍执行或复用四个搜索槽位。对两项处理逐项核对q0／q2的父框、候选、特征、裁剪哈希、选层与调用一致，确保观察到的当帧变化来自本次尺寸处理及随后选择。

当前GT只在输出完成后评价。统计当帧选框IoU、最佳候选IoU、好候选是否漏选、PPO槽位、外观最终槽位和写入资格；候选明细保存四框的父框／输出坐标、raw／Hann峰值和目标裁剪覆盖。无效GT状态保留回放记录，排除对应效果均值。

这里的“全部”指Stage-100实际触发的完整集合。不会只挑0304或0169，也不在新的反事实结果中挑最有利案例。1,834帧来自同视频的相关状态，汇总先按同种子单位平均，再同视频平均，最后视频等权；不把帧当作独立样本计算显著性。

## 预先固定的短后继起点

反事实图像推理以前，只用已封存Stage-100来源选择锚点。每个有触发的单位至多选以下三种角色，同帧合并：

1. 首次实际pulse触发，作为不看结果的时间起点。
2. 首次观察到gated IoU≥0.5且pulse IoU<0.2的帧之前，最近一次实际pulse触发。
3. 首次观察到pulse IoU≥0.5且gated IoU<0.2的帧之前，最近一次实际pulse触发。

另外覆盖pulse相对gated新丢失的两次PPO恢复：0307／2172／471与0076／2172／1477，各取参考恢复帧以前最近一次实际触发。它们可与上述锚点合并。全40单位上限122个唯一锚点，实际数量由来源计算并写入manifest，不能在看到本轮效果后更换。

这些“观察到的获益／损伤”来自两条已经分叉的完整来源轨迹，只用于选择诊断起点，不预先认定因果。GT参与该离线分层与评价，之后的跟踪决策不读GT。所选事件已被反复用于设计，不构成独立确认。

## 共同首帧与自身后继

每个锚点默认推进16帧，长度沿用Stage-86。两次新丢失恢复的锚点至少推进到原PPO恢复帧后17帧，以涵盖原十五帧窗口及连续三帧判定，遇视频结束截断。分支不被称为完整视频成绩。

两支共用该锚点各自已经完成的当帧匹配结果，不再次推理首帧。keep从这次正常启用尺寸开始，skip只在本次撤销尺寸调整；从下一帧起**两支都使用同一个Stage-100 pulse控制器**，根据各自实际输出和写入重新判断分歧。

因此skip不是永久关闭尺寸更新，也没有跳回gated轨迹。它仍可能在自己的后续分歧开始时再次触发。两支的预测历史、外观记忆、尺寸记忆和分歧状态都随自身输出更新，不从来源复制未来记录。只撤销一次调整后是否修复或破坏后继，才是本轮的局部干预问题。

报告短分支平均／末帧IoU、低IoU比例、有好候选帧比例、失跟次数和后续实际启用次数。按照锚点角色汇总时先在同种子平均，再同视频平均；一个锚点可属于多种角色，角色之间不视为独立试验。

## 判读边界

当帧skip补出好候选，支持该起点下尺寸替换损害了公开候选供给；当两组都有好候选却最终选框差，需结合PPO槽位及外观最终槽位判断选择变化。单次当前IoU的正负不能替代后继表现。

当帧差小但后继差大，说明后续状态反馈需要进一步核对；它不自动证明某条外观或尺寸记忆是唯一原因。来源中最后一次触发也不必然是整段损伤的唯一原因。16帧及已固定恢复延长窗口仍可能遗漏更长的影响。

本轮没有方法采用门槛，完成状态`COMPLETE_MATCHED_SCALE_TRIGGER_DIAGNOSTIC`。结果用于设计有证据的SGLA搜索状态机制，不直接调冷却或阈值，不将诊断起点当在线触发器，不打开28组确认集。

## 缓存、硬件与预算

与Stage-100型号、UUID和软件身份一致时，keep的当帧及短后继复用原pulse切片并逐帧审计；skip当帧新推理，短后继复用该首帧。换L20／L40或UUID时，keep和skip都在当前卡重放，仍共用相同的来源过去状态，报告keep相对来源的框误差。换卡后的结论条件于来源状态，不能当作新卡完整轨迹结果。

设匹配触发数`M=1,834`，唯一锚点数`A`，各锚点的首帧以外后继帧数合计`S=Σ(last−first)`：

| 当前条件 | 新搜索 | 新骨干块调用 |
|---|---:|---:|
| 原身份复用keep | `4×(M+S)` | 新搜索×7 |
| 换卡两处理均重放 | `8×(M+S)` | 新搜索×7 |

当帧部分同卡固定7,336次新搜索；后继实际预算根据源锚点预先计算并在启动时打印。首帧已计入匹配回放，不重复计费。缓存数量`2M+2A`，分为points和branches；训练、完整新轨迹、确认推理始终为0。转换／重建过去状态没有额外网络调用。

运行写入独立Stage-101目录，绑定全部Stage-100缓存、表、计划、兼容回执和冻结PPO。中断后同身份可校验续跑，换卡须新目录。原Stage-100不用重跑或改写。

## 产物与服务器命令

七表为`trigger_summary`、`trigger_video`、`anchors`、`branches`、`branch_summary`、`triggers`、`candidates`，另有decision和NPZ。结果包包含decision及前五张汇总表；1,834条逐触发记录、14,672条候选记录及NPZ留服务器，必要时可进一步读取。

同步本轮新文件，激活`sglatrack-test`，在仓库根目录执行：

```bash
bash tools/run_stage101_trigger_replay.sh
```

默认来源Stage-76、89、93及已完成的Stage-100，默认输出`output/stage101/matched_scale_trigger_v1`，使用原V1 checkpoint与逻辑GPU0。可通过`STAGE76_ROOT`／`STAGE89_ROOT`／`STAGE93_ROOT`／`STAGE100_ROOT`、`CHECKPOINT`、`STAGE101_GPU`指定来源和卡号，`STAGE101_ROOT`指定新输出目录。

后台执行：

```bash
mkdir -p output/stage101
nohup bash tools/run_stage101_trigger_replay.sh > output/stage101/run_stage101.log 2>&1 < /dev/null &
tail -f output/stage101/run_stage101.log
```

完成后回传脚本打印的`stage101_results_*.txt`。已完成运行可用`bash tools/run_stage101_trigger_replay.sh --pack-only`只校验并重新打包。
