# Stage-165 先计入退化风险，再提议 SGLA 层

Stage-164 的局部匹配丢掉了 0176 的恢复。Stage-165 使用四帧收益对照的 16 维 L6 投影和 8 个历史统计，沿用 Stage-162 的长历史退化模型。仍使用 Stage-159 的 328 个起点、28 个开发视频、两折源组划分和同一批后 32 帧分支结果。

## 对照

| 方案 | 提议层 | 换层起点 |
| --- | --- | --- |
| 原四帧收益对照 | Stage-159 按预测收益提议，Stage-162 的退化量参与跨起点排名 | 原有 64／4 个起点 |
| 同起点重提议 | 对 L7–L12 的非原生层逐层计算收益减退化，取分数最高的层 | 与四帧对照完全相同 |
| 重提议并重新排序 | 同样逐层计入退化风险 | 用新分数重排原有可换层起点，每折仍选 64／4 个 |

原提议为原生层的起点继续走原生层。收益模型直接读 Stage-159 的归档系数，退化模型复现 Stage-162 的同一拟合，在每折训练源组上预测所有层的退化量。执行前逐点核对归档提议、收益预测、退化预测和旧换层决策。比较中每个起点最多执行一个备选层。

## 已完成的缓存诊断

使用后续标注事后挑选安全正收益分支。每折最多选 64／4 个，允许少选。下表是相对原生的后 32 帧平均 IoU 上限，单位为 IoU 点。

| 事后可选范围 | 28 个视频 | 剔除 0176 |
| --- | ---: | ---: |
| 只允许原提议层 | +0.484 | +0.316 |
| 原可换层起点内允许六层重选 | +0.831 | +0.677 |
| 允许所有起点参与六层重选 | +0.879 | +0.727 |

固定提议的事后上限分别用了 63 和 62 个名额，六层方案两种范围均用了 68 个。两种重提议方法用拟合模型的留出预测决定动作。事后上限单独写入 `stage165_oracle_bounds.csv`。

## 运行与判定

正式比较读取 Stage-121 原生轨迹、Stage-159 的分支与模型缓存以及 Stage-164 的完整结果，在 CPU 上运行。后台日志定时刷新总体进度条，完成后自动打包 `stage165_results_*.txt`。

```bash
mkdir -p output/stage165
nohup bash tools/run_stage165_layer_reproposal.sh > output/stage165/run_stage165.log 2>&1 < /dev/null &
tail -f output/stage165/run_stage165.log
```

主比较要求重提议并重新排序保留 0176 和对照已有的恢复，无新增持续低 IoU 或丢失原生恢复。总体以及剔除 0176 后，均需优于四帧收益对照。同起点重提议用于判断收益来自换了哪一层，还是来自换了哪些起点。通过后再用训练视频确定在线阈值，并验证完整轨迹。
