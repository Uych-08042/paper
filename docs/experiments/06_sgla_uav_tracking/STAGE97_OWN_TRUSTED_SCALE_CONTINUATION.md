# Stage-97 自身可信历史尺寸的匹配后继试验

Stage-96 显示，搜索输入尺寸及其与中心的配合，会影响恢复时的候选供给。Stage-97 将尺寸更新写成仅依赖自身历史的在线规则，并检查从相同起点出发的后续跟踪。这一轮把输入几何诊断推进为可执行的 SGLA 搜索状态改动。

## 更新规则

两组使用相同的冻结 SGLA、PPO 选择器和 Stage-93 历史外观决策。每帧各执行四次搜索。搜索中心来自本分支此前实际输出的中心，尺寸也由本分支此前输出更新。

| 分支 | q0、q2 的尺寸 | q1、q3 的尺寸 |
|---|---|---|
| control | 最新预测尺寸 | 最近五个预测框宽高的对数中位数 |
| trusted_scale | 最新预测尺寸 | 最近十二帧内、最多五个通过可靠性检查的预测框宽高的对数中位数 |

可靠性检查复用 Stage-92／93 的响应与几何规则，要求最终选中框可写入外观记忆，且对应外观描述符为有限值。资格来自当前模型观测，尚未经 GT 确认。当前帧输出在本帧选框结束后进入尺寸记忆，下一帧才能使用。可用记录少于两条时，按 control 的历史尺寸计算。

十二帧时效、最少两条记录沿用现有外观记忆设置，最多五条沿用现有几何历史长度。规则在本轮结果产生前固定。它能保留历史尺度候选的一种可信尺寸假设，是否能保护恢复能力由后继试验检验。

## 相同起点与各自滚动

绑定 Stage-96 决策 `7185c1dc58f0f1695039a3082507e103e0fa212e6f1e12031c81305583a6a28c`。沿用 Stage-94／95 的全部 25 个原 PPO 恢复事件，包括 4 个原历史外观分支未保留的恢复和 21 个已保留恢复。

每个窗口从既定 PPO 失跟起点前 32 帧开始，至原恢复帧后 15 帧窗口最后一次可能的连续三帧恢复判定，按视频边界截断。25 个窗口合计 3,162 帧。窗口可能重叠，按不同试验起点单独推进。起点可能已经包含先前累积误差，因此本轮检验固定起点后的可改善空间。

两组从同一条历史外观来源轨迹复制截至起点前的预测框、外观 anchor 与过去写入的描述符。尺寸记忆也由这些过去预测框和既有写入资格重建。此后两组各自由自己的输出生成下一帧搜索、外观记忆和尺寸记忆。更新规则只读取过去和当前图像，GT 在分支预测结束后用于评价。

## 评价与产物

主要评价在原 PPO 恢复帧起至其后十五帧内，是否开始连续三帧 IoU ≥ 0.5。报告 control 和 trusted_scale 的恢复数、相对 control 的新增与丢失恢复，分别统计原未保留与已保留队列。

同时报告窗口平均／末帧 IoU、有好候选的帧比例、低 IoU 帧比例、窗口末尾未恢复状态、尺寸规则引用帧数和写入数，以及相同自身历史下实际改变父框和取整裁剪的帧数。恢复资格均在窗口内部计算。窗口均值先在同一视频内平均，再汇总视频，重叠窗口不视为独立视频样本。本轮没有显著性采用门槛，完整轨迹 AUC 留待后续检验。

产物包括 `stage97_windows.csv`、`stage97_video_summary.csv`、`stage97_summary.csv`、`stage97_frames.csv`、各分支 NPZ 和 decision。结果包包含前三张汇总表和 decision，逐帧及分支缓存留服务器。

## 预算和复用

共 50 条分支、6,324 个分支帧、25,296 个逻辑搜索槽位。与 Stage-93 硬件和软件身份完全相同时，control 复用原轨迹窗口并逐帧审计，trusted_scale 新增 12,648 次搜索、88,536 个骨干块调用。换卡时两组均在当前卡重跑，新增 25,296 次搜索、177,072 个块调用。支持 L20、L40。

control 在原身份复用时，恢复匹配时刻必须重建为原 Stage-93／94 记录。报告 control 对原轨迹的最大框误差，换卡后由该读数检查旧行为的对应关系。缓存、代码、来源与 GPU 身份由 manifest 绑定，可在固定身份下续跑。

训练、完整新轨迹和确认集推理均为零。PPO 对新的搜索尺寸分布保持冻结，本轮检验这一条件下的规则效果。

## 服务器运行

同步新文件后，进入原仓库并激活 `sglatrack-test` 环境。

```bash
bash tools/run_stage97_trusted_scale.sh
```

默认输入为已有 Stage-76、89、93、96 根目录，使用原 V1 checkpoint 和逻辑 GPU 0。可用 `STAGE76_ROOT`、`STAGE89_ROOT`、`STAGE93_ROOT`、`STAGE96_ROOT`、`CHECKPOINT` 与 `STAGE97_GPU` 指定其他路径和卡号。

输出默认为 `output/stage97/own_trusted_scale_continuation_v1/`。结束后回传脚本打印的 `stage97_results_*.txt`。已完成运行可用 `bash tools/run_stage97_trusted_scale.sh --pack-only` 校验和重新打包。

后台运行可执行：

```bash
mkdir -p output/stage97
nohup bash tools/run_stage97_trusted_scale.sh > output/stage97/run_stage97.log 2>&1 < /dev/null &
tail -f output/stage97/run_stage97.log
```

中断后若 GPU 身份变化，用 `STAGE97_ROOT` 指定新目录。

## 本地验证

两项 CPU 测试通过，覆盖尺寸引用的因果时序与过期、无效描述符拒绝、中心和当前尺度槽位、外观 hook 清理、完整来源与中途续接一致性、未来标注隔离、两种预算模式的采集发布、缓存续跑和篡改拒绝。网络输出由合成观测器提供，裁剪、解码、特征与记忆更新使用实际实现。真实 GPU 结果待服务器运行，本机 SSH 当前未通过服务器认证。
