# Stage-177 原生提议状态下的换层机会审计

Stage-176 的 16 个普通起点没有达标的有益替代。三个靠换层避免未恢复失跟的起点，旧门控都提议保留原生层。本轮检查能否用切换前的可见信号，在正常情况下保持原生，并为少数困难帧打开备选层。

## 来源与扫描

从 Stage-170 轨迹中取 Stage-176 未纳入的 12 个源组，其中 11 个视频长度允许至少 16 帧历史和 128 帧后效窗口。它们仍属于此前使用过的开发集。只纳入 Stage-167 收益提议等于原生层的状态，排除 Stage-173 至 Stage-176 已使用的起点。每视频将有资格的帧按时间顺序分成至多 32 组，每组按固定哈希抽一帧。样本抽取和排序使用源轨迹与因果信号。真值只用于后效评估。另对三个已知挽救点及 0348 第 362 帧扫描特征，单列复查。

用一次原生前向获取当前帧原选择器的前两名分差。历史响应使用当前帧之前的最近 16 个 Hann 峰值，包括最近四帧均值与前 12 帧均值。历史难度分为 `1 − 最近四帧均值 + max(0, 前12帧均值 − 最近四帧均值)`。值越大表示近期响应偏弱或下降。

## 等配额对照

每个至少有两个合格扫描起点的源组，四种规则各选两个起点。比较固定哈希均匀对照、较小选择器分差、较高历史响应难度及两者名次的等权联合。配额排序仅服务于离线对照。重叠起点共享一次双分支续跑。两组在起点分别执行原生层和同一个冻结排序器推荐层，随后各自反馈预测框并统一使用原生选层 128 帧。

沿用 Stage-176 的受保护定义。受保护且整窗 IoU 提升至少 0.01，或避免未恢复失跟，或挽回恢复，计为有益换层。报告有益起点与源组数、新增失跟、丢失恢复、窗口末未恢复与平均 IoU。任一规则所选起点的标注窗口不完整时，整个源组从四规则的主对照中一并剔除，以维持配额一致。

若联合分在至少三个源组找到受保护收益、比均匀对照找到更多有益换层、新增失跟与丢失恢复均不增加、无新增未恢复失跟，且平均 IoU 同时优于均匀对照和原生续跑，则支持之后校准在线阈值。此轮保持模型和评分器冻结，结论限于留出的开发状态。

## 运行

同步代码并沿用 Stage-170、173 至 176 的输出目录。更换 GPU 运行身份时使用独立 `STAGE177_ROOT`。

```bash
cd ~/workspace/paper
mkdir -p output/stage177
nohup bash tools/run_stage177_native_proposal_audit.sh > output/stage177/run_stage177.log 2>&1 < /dev/null &
tail -f output/stage177/run_stage177.log
```

脚本显示总体进度并生成 `stage177_results_*.txt`。扫描和续跑可分别断点恢复。先读 `stage177_scan_support.csv`、`stage177_summary.csv` 和 `stage177_paired.csv`。
