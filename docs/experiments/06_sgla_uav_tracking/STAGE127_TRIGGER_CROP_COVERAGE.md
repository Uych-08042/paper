# Stage-127 备用搜索触发帧的裁剪覆盖诊断

**服务器核查已完成。** 固定 Stage-125 的 346 个完整起点，主要看其中 333 个没有 IoU ≥0.5 输出框的起点。直接读取 Stage-121 既有轨迹里的四个实际裁剪，用原始帧尺寸和同一取整规则核对后，与标注逐一求交。 [Stage-127 结果](STAGE127_RESULTS_REVIEW.md) · [Stage-125 结果](STAGE125_RESULTS_REVIEW.md)

## 指标和判读

主指标是每个起点的四个裁剪中，覆盖目标画面内部分最多的那个的覆盖率。只计算实际图像像素，把补边排除在外。另记覆盖完整标注框的比例、标注框在画面内的比例、目标中心是否进入任一裁剪，以及搜索输入缩放后目标宽高。

| 分类 | 含义 |
| --- | --- |
| 标注框整块在画面外 | 按画面边界单列 |
| 四个裁剪与目标均无交集 | 图中有目标区域，但四个裁剪都未到达 |
| 最高覆盖率大于零且低于 10% | 只取到极少部分 |
| 最高覆盖率至少 10% 且低于 90% | 部分覆盖 |
| 至少一个裁剪覆盖画面内目标的 90% | 如该点仍无好输出，再结合输入中的目标尺寸和位置检查 |

同时提供 346 点总体和 333 个无好输出点的计数，以及每个触发点、每个槽位的明细。本诊断可以直接确认几何覆盖不足的比例。即使覆盖充分，较大的裁剪也可能让目标在缩放后过小，遮挡或其他外观困难不能由坐标反推。

## 运行

同步脚本后，在已保存原始产物的服务器仓库根目录执行。用现有实验 Python 环境即可，无需 GPU、读图或重跑 SGLA。

```bash
bash tools/run_stage127_crop_coverage.sh
```

脚本使用已封存的 Stage-76／89／93 标注来源、Stage-121 轨迹和 Stage-125 起点清单，与 Stage-124 记录的四个预测 IoU 逐点核对。默认输出到 `output/stage127/trigger_crop_coverage_v1`，也可用 `STAGE127_ROOT` 指定。终端先打印覆盖率汇总，再打印完整的 `stage127_results_*.txt` 路径。
