## 具有明确含义的误差分解

对状态i和候选层l，真实质量为y_il，预测为p_il。令m_i为六层真实质量均值、d_il=y_il−m_i；预测也作相同分解。则有精确恒等式

MSE(p,y) = mean((mean_l p_il − mean_l y_il)^2) + mean(((p_il−mean_l p_il) − (y_il−mean_l y_il))^2)。

两项分别为共同均值误差与层间相对误差。恒等式来自中心化残差跨层求和为零，不需要独立性或高斯假设。预测某帧整体容易或困难，与预测该帧哪一层更好，是不同能力。

共同均值是当前六候选的质量代理，不等于图像语义上的难度、遮挡或干扰物。即使共同分量占比很大，也不能仅凭该比例断言它造成了训练退化。还要观察相对误差、排序与常数控制。

总体标签方差进一步拆为各状态均值的方差与层间残差能量。pool级统计包含视频之间的差异，不能先对每个视频减去均值后再将其冒充全训练池方差。

## 正确区分训练数据口径

Stage-194每折完整fit池为19×48=912状态，而训练为1024次有放回抽样。不能把这1024次当作1024个不同状态。

本轮重建原256×4抽样序列并与模型metadata中的draw哈希核对，输出每个fit状态被抽到的次数。误差分别在以下集合计算。

| pool字段 | 含义 |
| --- | --- |
| fit | 全部912个fit池状态 |
| held | 全部912个留出状态 |
| fit_draws | 按1024次实际抽样重复计权，最接近实际训练经验分布 |
| fit_seen_unique | 实际见过的fit状态，每个只算一次 |
| fit_unseen | 属于fit视频，但本轮未被抽到的状态 |

未见状态的误差不能直接等同于训练优化失败。原history的每步batch损失单独导出，不以首末两个不同batch判断收敛。

## 预测与选择控制

全部常数控制仅根据fit源组或其实际训练抽样计算，held标签不会确定常数。

| 名称 | 含义 |
| --- | --- |
| trained | 既有冻结路由预测 |
| initial_half | 原零初始化路由的六个0.5预测，仅作误差控制 |
| fit_label_mean | fit池逐视频宏平均的每层真实质量常数 |
| fit_draw_label_mean | 按实际训练抽样次数加权的每层真实质量常数 |
| fit_prediction_mean | 将训练后的路由在fit池输出取逐视频均值，去掉逐帧变化 |
| native_L9 | 原生固定L9选择 |
| oracle | 同状态真值最优层，仅作供给上界 |
| uniform_expectation | 六层均匀随机选择的解析期望，不新增随机执行 |

分别报告MSE、共同／相对误差、相对零残差预测的skill、相对L9的优势预测误差、成对排序准确率、以真实差值加权的排序准确率、regret与选择频率。真实相等的层对不作为必须正确排序的样本，预测相等记半分；1e-8仅用于数值相等判断，不是放行门槛。差值加权避免额外选择“有意义差值”的经验阈值。

对诊断常数和oracle，若L9与最大值数值相等，则保留L9。trained仍使用原实现的torch.topk，不能把新平局规则冒充原模型动作。

error_summary是完整pool状态统计；error_video用于逐视频追查。policy_summary先在各源组各种子上汇总，源组为独立单位。paired先在源组内平均两个种子，再对38源组bootstrap，区间为探索性的名义区间。

## 原有完整轨迹与数值一致性

覆盖4模型×38源组×48状态，共7296次很小的CPU路由预测。留出状态的候选标签和最优值须与原GPU读出相符。CPU与GPU的std／线性运算可能在近似平局处改变动作，因此单独输出动作不一致数、响应间隔和被选框IoU差。不一致不会被静默替换或强行归因于算法。

另外读取76条既有仅R自身轨迹，检查其中真正固定选层的轨迹是否与已有的同层完整控制逐帧一致。当前已有L9与fit最佳固定层的控制。没有独立固定L10／L11等完整控制时，记录“无控制”，不能声称已经实测等价。

这些源轨迹具有完整视频AUC。新增policy表只评价缓存状态的即时IoU，两者不可混用。本轮没有采集自身轨迹上的新视觉特征，不能直接评估那些状态上的六层质量误差。

## 如何依据结果选择下一步

- 若实际fit_draws上训练后MSE仍明显差于可实现的常数均值控制，先检查优化与监督尺度，不直接认定视觉信息无效。
- 若共同均值拟合改善而相对误差、排序未改善，进一步验证分支差异监督；已有Stage-158～170收益回归不能被忽略。
- 若实际见过状态良好、未见和held状态较差，优先检验泛化与状态支持。
- 若即时排序确有增量，而完整自身轨迹仍退化，再检验闭环相对效用与自身状态训练。
- 如果现有模型与固定路径无差别，则不将其写成动态计算贡献。

以上是分支判断，尚未预定审计结果，也没有给新方法采用门槛。

## 运行

在具有完整Stage-194产物的服务器运行，不需要原始图片、原始SGLA权重或可见GPU。需要现有环境的CPU PyTorch接口及NumPy。

```bash
conda activate sglatrack-test
cd ~/workspace/paper
bash tools/run_stage195_router_objective_audit.sh
```

自定义来源目录时设置STAGE194_ROOT。后台运行如下。

```bash
export STAGE194_ROOT="$PWD/output/stage194/module_ablation_v1"
export STAGE195_ROOT="$PWD/output/stage195/router_objective_audit_v1"
mkdir -p "$STAGE195_ROOT"
nohup bash tools/run_stage195_router_objective_audit.sh > "$STAGE195_ROOT/run.log" 2>&1 < /dev/null &
echo $! > "$STAGE195_ROOT/run.pid"
tail -f "$STAGE195_ROOT/run.log"
```

保留一个总体进度条，后台定时刷新。源数据只读。中断后的未完成CPU统计会重算，已有最终结果可直接核验。输出计划绑定CPU Torch版本，环境或实现改变时使用新的STAGE195_ROOT。

完成后自动生成stage195_results_时间戳_PID.txt，包含decision和9张表。直接回传该文件即可。

```bash
python -B tools/stage195_router_objective_audit.py --output-dir "$STAGE195_ROOT" --check-results
```
