# Stage-110：由数据支持的搜索区域生成

日期：2026-11-15。状态：代码与本地合成测试完成，等待服务器正式运行。当前没有Stage-110实验成绩。

用户要求正面检验固定“最新／滞后中心×最新／历史尺寸”之外的候选生成依据。本轮把研究重点转向**历史信息能否预测目标状态和误差范围，并在相同SGLA搜索预算下生成更有效的输入**。Stage-109的提交门控重训暂不作为下一轮主线；旧结果和模型保留。

本轮先建立候选生成证据：预测依据→误差范围校验→搜索区域分配→真实SGLA候选供给。采用可审计的小型统计学习模型，不要求先引入复杂生成网络。概率建模思想可参考[PrDiMP](https://openaccess.thecvf.com/content_CVPR_2020/html/Danelljan_Probabilistic_Regression_for_Visual_Tracking_CVPR_2020_paper.html)，本轮不是该方法的复现，也不能据此预设有效。

## 1. 来源和固定采样

绑定Stage-109决策`1094eac91bf60b49ab1073a2f59779b7956449d15332f260d5b6acbd58702d80`及Stage-103完整来源。使用全部28个已消耗开发源组、40个视频／种子单位×两种核验来源，共80个上下文。源轨迹只读，各候选生成方法使用同一历史、当前图像、模板和原生SGLA权重。

每个上下文在`t>=5`的全部跟踪帧中，先固定等间隔最多96个拟合身份；从剩余身份按PCG64均匀无放回抽取最多24个评价身份。采样只看帧号与上下文，不使用线上冲突资格、GT、失败角色、模型分数或新结果。短池不补样，缺GT的评价状态保留并报告缺失。拟合时仅排除无法形成有效监督标签的记录。

上限7,680个拟合记录、1,920个评价状态，各状态评价六个四搜索集合。与Stage-109不同，本轮不只采样提交有变化的状态，也不要求32帧后继窗口；本轮没有后继分支。

拟合与评价身份在每个上下文内不重合。源组留出还保证评价某组时，该组全部拟合样本不进入新预测包。旧轨迹和PPO已经用于开发，留组隔离只针对本轮新模型，不代表整个上游训练流程均重新隔离，更不是独立确认。确认集继续封存。

`manifest.json`在新拟合和GPU搜索前封存设计、每个上下文采样身份、随机种子、来源及拟合输入指纹。`sampler_seed`与`actor_seed`分别记录，避免Stage-109抽样导出表的同名字段问题。

## 2. 从过去信息学习位置、尺度和不确定范围

预测输入32维，仅取当前帧之前的信息：

- 最近至多五个自身预测框的四步中心位移与宽高对数变化，共16维；
- 这些变化的均值、标准差及最近转折，各4维，共12维；
- 历史长度比例、上一帧实际选框的raw峰／Hann峰、上一帧是否通过外观写入，共4维。

位移以最近预测框面积平方根归一化。输入固定裁剪至±10，不包含当前帧GT／图像特征、源组身份或当前四次搜索结果。生成发生在本帧SGLA搜索前。

监督目标为当帧GT相对最近预测框的中心位移和尺寸比：

`y = [Δcx/side, Δcy/side, log(w_gt/w_last), log(h_gt/h_last)]`。

每个留出源组有一个预测包：

1. 将其余源组按排序后每三组取一组作为校准组，其余作模型拟合组。正式28组条件下，每包18组拟合、9组校准、1组留出。
2. 用固定ridge=1拟合四维均值。只用拟合组，另作三折源组预测，取得未用其自身组拟合的残差。
3. 根据拟合组的上述残差，回归四维`log(error²+1e-4)`，预测条件误差尺度。另估计一套与当前输入无关的固定误差尺度。
4. 在独立校准组，根据四维最大标准化误差的源组平衡90%分位数，分别校准固定尺度和条件尺度。校准标签不更新均值／尺度系数，也不接触留出组。

所有加权按源组→种子→来源模式→记录平衡。宽度是经验误差范围；90%指校准目标，不承诺时间相关数据上的有限样本覆盖保证。模型采用对角高斯工作假设，未学习完整相关性或多峰状态密度。没有SGLA／PPO更新，也没有模型结构、正则或阈值搜索。

## 3. 由预测形成搜索集合

对预测均值与误差尺度，使用共同的32个固定反向配对高斯场景，形成联合中心与尺寸假设。将预测中心约束在图像范围内、宽高约束在1像素至图像尺寸内；然后形成低成本父框提议池。所有提议生成均不运行SGLA。

保留原q0父框作为共同工程约束，其他三个槽位从池中逐步选择。每次选择增加“假设状态得到有效覆盖”代理得分最多的区域，优先避免与已选区域发生相同的取整裁剪；无法提供新裁剪时保留q0副本并由合法动作规则处理。

代理得分综合假设中心相对裁剪中心的距离，以及父框尺寸与假设目标尺寸的对数差。它没有被预设为真实SGLA质量；裁剪范围更广也不自动代表目标更可辨识。**真实终点是这些区域经过SGLA后解码出来的候选质量。** q0保留、高斯场景和软覆盖形式仍是预声明假设，本轮不声称完全无人工先验或四次搜索最优。

## 4. 六组同预算对照

| 组 | 搜索区域来源 | 检验问题 |
|---|---|---|
| fixed | 原中心×尺寸四布局 | 原启发式基线 |
| motion | 原Stage-84运动外推＋覆盖规则 | 相对已有算法生成是否增加价值 |
| learned_constant | 学习均值＋经校准的固定误差尺度＋分配 | 学习预测、使用平均误差范围的基线 |
| learned_uncalibrated | 学习均值＋条件尺度，校准倍率固定1＋分配 | 校准作用对照，不称其区间已有90%覆盖 |
| learned_calibrated | 学习均值＋校准条件尺度＋分配 | 本轮主要生成方法 |
| calibrated_random | 与主方法完全相同提议池，随机选三个新裁剪 | 分配准则是否优于随机使用同一池 |

六组各四个逻辑槽位，保留同一个q0；新学习组的三个额外父框的中心和尺寸均可变化，不锁定原q1／q2／q3语义。四是本轮控制搜索调用的预算，不是“目标只有四种运动状态”。

完全相同的浮点父框在同状态内复用SGLA观测；仅取整裁剪相同而父框不同，仍各自搜索，保持坐标映射一致。六组24逻辑搜索、共享q0后至多19次物理搜索／状态，最大46,080逻辑搜索、36,480物理搜索、255,360搜索块调用。实际重复更多则物理调用更少，表中逐状态记账。

首次支持L20／L40，自动绑定型号、UUID与软件。续跑必须相同运行身份，换卡另开`STAGE110_ROOT`；除型号和UUID外的配置／权重／软件变化拒绝。同运行时fixed所有候选框、特征、裁剪与层须复现来源；换卡来源差异单列，六组同卡共同实测。此处预算不包括模板初始化，中断后重做未保存项会增加实际消耗，不给部署速度结论。

## 5. 预定证据和判读

第一层检验预测：学习均值的中心误差是否低于最近中心和恒速外推，尺度误差是否低于保持最新尺寸；固定／未校准／校准区间的四维联合覆盖率与范围大小如何。覆盖率不能脱离区间宽度解释。

第二层检验实际供给：主要比较`learned_calibrated−fixed`的最佳已解码IoU；必要比较motion、learned_constant、learned_uncalibrated和calibrated_random。报告有IoU≥0.5候选的比例、新增好框与丢失旧好框、有效裁剪数、最大GT裁剪覆盖和目标输入像素尺寸。先平均各来源上下文，再模式、种子和源组等权，保留历史／扩展及两种来源分层。

第三层仅作兼容性观察：用同一冻结PPO在各候选集合中影子选框，记录实际选框IoU和有好框却漏选的比例。这些动作不写回历史；旧PPO是在旧布局上训练的，不能用其单独退化直接否定新生成集合，也不能把影子收益称为新完整策略收益。

输出五个主要控制比较×三个指标×最多九个分层，共最多135条配对。给出源组均差、中位数、胜平负和留一敏感性，不把相邻帧当独立样本计算显著性。状态为COMPLETE表示固定实验完成，不设最终方法采用门槛。

若预测／校准与同预算真实供给都出现可重复的积极证据，才有依据进入下一轮“旧／新生成器×旧／匹配训练选择器”的完整闭环对照，并检查稳定与恢复保护。候选更分散、单个失败窗口改善或oracle上限提高，均不能替代这条证据链。

## 6. 运行

将本轮代码同步到服务器，激活原`sglatrack-test`环境，在仓库根目录执行：

```bash
cd ~/workspace/paper
bash tools/run_stage110_proposals.sh
```

远程断开后继续运行：

```bash
mkdir -p output/stage110
nohup bash tools/run_stage110_proposals.sh > output/stage110/run.log 2>&1 < /dev/null &
echo $!
tail -f output/stage110/run.log
```

默认输出`output/stage110/calibrated_search_proposals_v1`，使用原V1权重`output/checkpoints/train/sglatrack/deit_distilled/sglatrack_ep0297.pth.tar`。支持`STAGE76_ROOT`、`STAGE89_ROOT`、`STAGE93_ROOT`、`STAGE103_ROOT`、`STAGE109_ROOT`、`STAGE110_ROOT`、`CHECKPOINT`及`STAGE110_GPU`覆盖。

首次运行会先校验来源，再冻结采样与输入，拟合28个预测包，采集六组共同状态搜索，最后校验并生成`stage110_results_<UTC>_<pid>.txt`。文件包含decision和8表，回传该TXT即可。模型、拟合输入、提议缓存、SGLA观测及收据保留在服务器。

```bash
bash tools/run_stage110_proposals.sh --pack-only
```

该命令只校验和重新打包。完整缓存续跑不重新GPU搜索，CPU会审计已保存预测包。脚本不自动commit／push；nohup不延长平台作业时限或GPU租期。
