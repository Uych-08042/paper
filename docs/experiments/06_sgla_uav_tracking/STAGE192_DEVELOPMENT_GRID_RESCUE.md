# Stage-192 跨开发源组的网格候选与写回收益

Stage-191 的持续挽救集中在 `0173` 一次失跟。Stage-192 在 Stage-170 和 Stage-188 的 38 个已有开发源组上，分别测量原生搜索中的好框供给、漏选和一次纠正的长期效果。

## 名册与配对

- 每个源组至多纳入一个失跟窗，取第一个有完整后 128 帧、且窗内 IoU 均有效的原生失跟起点。在前向和候选评估之前冻结入选名册，包括所有没有完整事件窗的源组及其资格统计。
- 每组至多另取一个原生稳定窗，要求锚点与后 128 帧均为 IoU ≥ 0.5，与所选失跟窗互不重叠。有失跟窗时选择距离最近的合格稳定起点；无失跟窗时选择合格起点的中位位置。没有合格窗口的源组仍列在支持表。
- 每个窗口只重放原生父框和原生选层。同一个 CENTER 网格分别写回 Hann 首选和用真值选出的最佳框。之后各自按原生方式续跑，沿用 Stage-191 的事件判定。固定使用同一 GPU 比较两个分支，原运行身份完全一致时，可复用锚点已经精确复现的原生续跑。
- 38 个源组均来自已使用过的开发数据。另报去除 Stage-191 的 `0173` 和 `0107` 后的结果。每个源组在每类窗口中最多贡献一条配对，确认集继续封存。

## 判读

先读 `support`，确定实际纳入的失跟窗和稳定窗。`summary` 分别给出网格有好框、Hann 有好框、网格有框但漏选、受保护挽救、新增失败、后效及去掉收益最大源组后的结果。稳定窗中的写回仍可能改变轨迹，单独查看事件和均匀配对的后效损失。真值选框仅测一次改选能达到的上界。若收益在去掉已知两个个案后仍出现在多个源组，再开发可在线使用的选框规则。

## 运行

需要既有 Stage-76、89、93、121、170、188、191 产物、原始 SGLA 权重和数据。同一运行身份下通常只需对改变了写回框的分支新增续跑。另一个 L20 或 L40 可重跑当轮配对，耗时可能增加。

```bash
mkdir -p output/stage192
nohup bash tools/run_stage192_development_grid_rescue.sh > output/stage192/run.log 2>&1 &
tail -f output/stage192/run.log
```

日志显示总体进度，结束后打印 `stage192_results_*.txt` 路径。
