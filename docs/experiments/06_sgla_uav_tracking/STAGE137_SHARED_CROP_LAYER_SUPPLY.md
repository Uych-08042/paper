# Stage-137 同裁剪的独立候选块供给诊断

Stage-136 的同图改选在完整视频中引入新失跟。Stage-137 回到原生轨迹，检查额外候选块能否在同一个搜索裁剪里生成原选块缺少的好框。 [Stage-136 结果](STAGE136_RESULTS_REVIEW.md)

## 固定样本与计算

- 采用 Stage-134 的 47 个起点。Stage-133 的 8 个原选块全网格无好框起点是主分析组。其余 11 个失跟起点和 28 个稳定窗口起点作对照。好框定义为 IoU ≥ 0.50。
- 所有块读同一个原生父框对应的裁剪和初始模板。每个起点只跑一次 L1–L6，L7–L12 各自直接读取同一份 L6 特征，再各自用原 CENTER 头及 Hann 解码。其中原选择器选中的块作基准。每个起点只做一次裁剪，六块输出均不写回跟踪状态。
- 总计 47 次搜索裁剪、282 次公共前缀块、282 次候选块、282 次预测头和 47 次选择器。检查实际模块调用和裁剪哈希。原生权重冻结，无训练、续跑及新整段轨迹。

## 判读

主指标是原选块全网格无好框的起点中，有多少能从其他候选块的 **Hann 第一峰标准解码**直接拿到好框。另列只在其他块的某个格点存在好框的情况。按真值取六块中最好的框是诊断上界。原选择器第二名和跨块最大 Hann 峰只作为容易实现的比较，检查它们能否找到这些机会，以及会否把稳定点的好框换掉。

本轮用一张 L20 或 L40 执行六块。与 Stage-134 硬件相同时，核对原选层、峰格点、响应图和输出框。换卡时仍核对裁剪，并报告本轮原选块的框差和实际网格分类。同裁剪里确认其他块具备补框能力后，再验证可观测触发与短程后效，最后进入同额外预算闭环。

## 运行

```bash
bash tools/run_stage137_shared_crop_layers.sh
```

默认输出 `output/stage137/shared_crop_layers_v2`。首次服务器运行通过模型身份核对后，权重摘要调用在首个窗口前报错。修复后使用新目录以保留旧清单，实验口径沿用本协议。可用 `STAGE137_GPU` 指定逻辑 GPU，默认 0。实验按起点提交缓存。脚本校验结果并生成 `stage137_results_*.txt`，包含分组汇总、逐起点和逐层结果。
