固定日期：2026-11-15。状态：实现及五项本机测试完成，正式服务器GPU分支待运行。

## 1. 固定来源与起点

绑定Stage-114 decision `cb1665a027fbb6e7db9c5394eb6d14969134c946d3001552ce41c65ff90ae282`及Stage-113/112完整来源。只研究28开发视频×两个评分种子＝56条generated_shared轨迹，复用四个外层生成包和对应八个generated4共享评分器；评分标准化、SGLA权重、原生解码、首帧模板和所有算法参数冻结。

每条轨迹按原缓存与当前GT计算三个互斥角色，取各角色第一次出现的帧，不按后继效果筛选：

| 角色 | 起点条件 |
|---|---|
| first_good_q0_lost | q0 IoU≥0.5、原选择IoU<0.2、实际输出与q0不同 |
| first_medium_q0_lost | 0.2≤q0 IoU<0.5、原选择IoU<0.2、实际输出与q0不同 |
| first_bad_q0_rescued | q0 IoU<0.2、原选择IoU≥0.5、实际输出与q0不同 |

所有56×3＝168条角色支持记录完整保留：匹配帧总数、首次位置、是否有包含起点在内的完整32帧。若不存在或视频末尾不足32帧，记录原因，不缩短窗口或后验另挑起点。相同轨迹/帧合并一个起点并保留角色列表。N由服务器原缓存统一计算并在首次图像推理前封存，不预填未知数量；上限168起点。

GT在这里用于**已消耗开发证据的条件诊断选点**，不构成线上门控或独立确认。模型原外层留出边界保持，28确认源组继续封存。本轮不训练SGLA、共享评分器、生成器或PPO，不扩大候选数。

## 2. 两条实际后继

每个起点从原轨迹恢复此前最近最多五个预测框、上一帧4×24特征、上一帧选择与可信资格位。只在起点导入这个共同状态；随后两臂各自滚动，不再借用来源未来。

重新初始化原始首帧模板，在当前GPU上重新观测一次起点的四候选及共享评分，形成公共点缓存。两条分支共用这些实际观测：

- `policy`：起点沿用本卡重新计算的原冻结共享评分选择。
- `q0_once`：仅起点强制选择q0，从下一帧恢复原冻结生成/共享评分规则。

动作更改同时改变当前发布框、提交框、上一帧被选响应和重新计算的可信资格位，反馈与实际选择一致。它是一次完整q0动作处理，**不是仅修改中心、尺寸或单一资格位的纯因子实验**。没有外观记忆重排、在线模板更新或额外恢复分支。

两条32帧分支的当前输入相同，后续父框、生成输入和候选均由各自实际历史产生。逐帧审计固定评分和动作、仅一次强制标记、特征/解码、实际提交、下一帧生成，以及新调用掩码。两条NPZ及收据均落盘后，才计算这对分支的评价指标。

## 3. 当前硬件上的控制与来源桥接

首次支持L20或L40，自动绑定实际型号/UUID及冻结软件。所有公共点和policy/q0_once控制都在当前卡新观测。来源历史是明确固定的条件起点，不等于在新卡重跑整视频。

运行身份与Stage-113完全相同时，policy分支32帧的父框、候选、特征、响应/几何图、动作和输出必须精确复现原缓存，排除计时字段。首次换GPU/UUID可单独绑定，其他软件、权重或配置变化拒绝；桥接表报告policy对来源框/候选/特征最大误差及动作变化数。

换卡后起点角色可能改变，仍保留原来封存的全部起点，不按新结果删除或改选。表中同时列出旧/新q0与policy IoU、匹配角色是否保留、实际强制动作是否改变输出。两分支间的首次框/父框/裁剪分叉帧也会记录。32帧的来源漂移可能包含后续反馈放大，不能全部归为一次浮点误差。

同一输出根续跑必须相同GPU/UUID及软件；换卡重新指定`STAGE115_ROOT`，不混合未完成分支。

## 4. 指标、层次平均与结论边界

主要读数为`future_mean_iou`：**只平均起点之后31帧**。另报后续低IoU比例、好候选可用率、漏好比例、末帧IoU，以及单列的起点IoU和窗口失败事件数。选点已按当帧GT定义，起点改进不能直接当作新的后继证据。

给出每起点q0_once−policy的差值，按三个角色分别汇总，也列所有去重起点。先同一视频/评分种子内平均起点，再视频内平均有支持的两个种子，最后视频等权；all/historical/expanded分列。缺角色/缺有效未来的支持数量要显式报告，不将其填为0。全体起点混合伤害与救援条件，不能只看混合均值决定方案。

后续平均IoU差给视频层条件bootstrap，seed23150、10,000次、名义95%区间与胜平负。它条件于固定模型、已消耗源组和GT选出的角色，未纳入重新训练/重新选点的不确定性，不是确认性显著性或上线采用门槛。

32帧是局部后继，不是完整AUC或全视频稳定/恢复保护。窗口内未观察到原参考恢复，不等于永久失去恢复；不能将不同起点重叠窗口当成独立视频样本。若本轮改善，再设计可公开计算的风险条件及完整轨迹验证；不能把GT选出的q0动作直接写成可部署方法。

## 5. 计算和保存

N个起点对应N公共点、2N短分支、64N个分支帧曝光。公共点只搜索一次，两个分支首行复制观测；之后各31帧重新搜索四候选。

| 账本 | 上限/定义 |
|---|---|
| 新搜索调用 | 每起点最多4＋2×31×4＝252，总上限252N |
| 搜索块调用 | 每次搜索7块，最多1,764N |
| 分支逻辑搜索曝光 | 2×32×4＝256N，含复制的起点观测 |
| 模板初始化 | 每起点公共点和两分支各一次，共3N |
| 缓存 | 每起点3份NPZ/3份receipt，共6N个文件 |

帧内完全相同浮点父框仍去重，实际调用由`executed`和`new_executed`审计。branch首行`new_executed`全False，只在公共点桥接账本计费一次；不能把两份复制观测重复计成GPU调用。源缓存调用、模板初始化和搜索调用分开理解，不宣称所有GPU开销只有搜索块。

完整点/分支缓存保留原响应、尺寸/偏移图、候选/父框、特征/评分、生成状态、原policy选择、实际选择、资格及调用掩码。已提交缓存与收据复用，无重复推理；未提交的点/分支从其共同起点重新执行。报告统计唯一已提交产物，故障重试实际运算另计。来源文件与模型不写入，不自动commit/push。

九表为sampling_scope、anchors、scope、branches、contrasts、summary、paired、bridge、branch_frames。自动TXT包含decision及前八表，逐帧表和完整缓存留服务器。sampling_scope固定168行；其余数量在准备阶段封存N后由报告账本核对。

## 6. 服务器运行

需要原sglatrack-test、原SGLA checkpoint、VisDrone-SOT图像和完整Stage-76/89/93/112/113/114及校验引用的上游产物。同步本轮代码后执行：

```bash
cd ~/workspace/paper
mkdir -p output/stage115
nohup bash tools/run_stage115_q0_continuation.sh > output/stage115/run.log 2>&1 < /dev/null &
echo $!
```

查看进度：

```bash
tail -f output/stage115/run.log
```

默认输出`output/stage115/matched_one_q0_continuation_v1`，可覆盖`STAGE115_ROOT`、`STAGE115_GPU`、`CHECKPOINT`及六个来源根变量。换卡另设新根，例如：

```bash
export STAGE115_ROOT="$PWD/output/stage115/matched_one_q0_continuation_l40_v1"
nohup bash tools/run_stage115_q0_continuation.sh > output/stage115/run_l40.log 2>&1 < /dev/null &
```

完成后自动核验并生成`stage115_results_<UTC>_<PID>.txt`。仅重新核验/打包完整结果：

```bash
bash tools/run_stage115_q0_continuation.sh --pack-only
```

nohup可以脱离SSH，但不延长平台作业时限。本轮没有完整视频新AUC或方法采用结论；下一步根据分角色的实际后继收益/代价决定是否开发风险约束。
