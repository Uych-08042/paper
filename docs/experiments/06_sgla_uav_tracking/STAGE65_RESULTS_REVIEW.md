# Stage-65结果复核：有害接管与退化历史中的候选不足并存

日期：2026-11-03，Asia/Hong_Kong。来源为[用户上传原件](results/stage65_results_20261103T081800Z_253219.txt)，沿用[固定协议](STAGE65_CACHED_SAME_STATE_SELECTION.md)，接续[Stage-64完整轨迹结果](STAGE64_RESULTS_REVIEW.md)。

**本轮确认了有良好q0却被错误替换的具体状态，也显示退化历史在恢复附近可能已没有良好公共候选，换当前评分器不足以当帧挽回。** 后续新增价值应同时关注有效状态的接管保护和弱证据状态下的推进；不能把当前三级可靠性标签或单一重排序当作已经解决持续失跟。

状态`COMPLETE_CACHED_SAME_STATE_SELECTOR_DIAGNOSTIC`仅表示诊断完成，没有新方法PASS或新的完整视频成绩。Stage-64原始reliability−quality的−4.3668 AUC保留，本轮不修改其模型、阈值和结果。

## 1. 实际完成范围与共同输入含义

96条Stage-64自身轨迹提供108200个保存状态；另24个原生fit history／recrop参考提供27050状态，共135250个状态出现次数。每个状态的四个公共解码框由q0／Hann／quality／reliability分别选择，541000个缓存框出现次数、541000次被报告的选择规则应用。它们不是独立样本或新增网络搜索。

Stage-64已付出的432800次搜索和旧L40 fit参考的108200个公共框均复用；新增网络、图像读取、训练、模型、完整轨迹为0。旧4评分器的拟合系数仅数值重建核对，不保存或采用新系数。source runtime及模型来源指纹与Stage-64一致。

每条状态内部四规则输入相同，影子选择不推进下一帧。不同`state_policy`仍有不同自身历史，即便视频和帧号相同也不是共同起点。E的quality／q0在本轮只有影子选择，不能写成新执行的E完整政策。

分歧率高但平均IoU差小，不能将不同候选索引直接算成有意义改框，也不能认为小均差没有持续后效。Stage-63已给出少数单次选择的32帧后效，本轮没有再次执行后继干预。

原生quality在自身历史的当前平均IoU为0.671970，reliability自身为0.625095，差0.046875。在reliability历史上改用quality只增加0.001055；quality在两种历史上的差为0.045821，两项相加精确等于自身差。反向以quality历史分解时，同状态评分差为0.000903。**这是保存状态上的代数记账，不能写成某个因素造成了97%以上损伤的因果比例。**

reliability保存历史上逐帧事后最好的四框IoU均值也只有0.641975，低于quality自身历史的0.671970。它限制了“只在这些既定输入上重新选框”的当帧空间；不限制较早改变选择、形成新历史后的未来收益，更不是一个已执行的oracle跟踪政策。

### F01：可以直接观察到有害替换，值得做显式接管保护

原生0003的H历史窗口中，q0连续37个状态均良好。Hann与quality也37个都良好；reliability却只有36个良好，另1个低IoU，属于良好q0被替换成低框。在固定q0历史上，reliability有2次同类替换；quality历史上有1次。

实际R历史窗口已有5个状态四框全低；q0有31个良好、6个低，R选30个良好、7个低，并有1次良好q0降为低框。quality／Hann在该R历史上都只能选31个良好、6个低。说明同时存在可避免的当帧替换和已经退化的输入，不能靠末尾换规则把整个窗口恢复。

Stage-64首次失效锚点为138，但窗口计数本身没有给出那次有害替换的精确帧。本机未读取逐帧表，不能直接指定“138帧q0良好且是唯一根因”。

### F02／F03／F06／F07：0226并非失效时刻已有好框却一直不选

原生0226在94～154，四种实际历史都没有一个良好公共框；E两种子在97～157也一样。此时不能期望只改四框选择得到IoU≥0.5。

到309～369，原生0／Q历史重新有33个良好候选状态，H／R历史却61个状态四框全低。两类历史的四种影子选择结果因此完全不同。Q历史上q0选32个良好，quality与reliability都只选31个；R历史换成quality仍0个良好。没有证据支持“在reliability到达339时直接换quality就能恢复”。

R在F02自身历史上的窗口平均IoU0.1859反而高于同状态Q的0.1813，但Stage-64完整R轨迹未恢复、Q轨迹恢复。这保留了即时均值与持续结果不等价的证据；它没有定位更早哪次中心／尺寸变化造成后来差异。

### F04／F05：0307需要保护恢复所依赖的状态

0307的H历史在444～504有39个良好候选状态，q0在其中35个良好。Hann选35个良好（丢失2个良好q0，同时救回2个替代机会）；quality只选30个、丢失5个良好q0且没有救回；reliability选31个、丢失4个且没有救回。这里仍有提高接管判断的空间。

但Q／R各自实际历史在同一窗口都没有良好候选；Q选53个低IoU、R选45个低IoU。较差历史上的影子评分不能当帧创造恢复框。更早的356～416也呈分化：H有31个良好候选状态，Q只有9个，R为0。需要在失效／恢复演化中保护输入状态，不能只在原恢复帧加一个评分规则。

### F08：E0304的改善伴随较好的进入历史，并非当前评分持续最优

E0304／2132的R历史在1063～1123有61个状态提供良好候选，q0有60个良好；R选择60个良好、均值0.7283。相同R历史上的Hann影子选择61个全良好、均值0.7706，反而更好。

原H历史只有19个状态有良好候选，Hann与R各选17个良好，均值0.2709／0.2605。因此Stage-64该种子完整+28.2761 AUC不能解释成“R在每个当帧都更会选”；本窗口未定位更早形成良好历史的关键干预，也未证明把Hann移到该好历史后会实现完整视频同样收益。

### F09／F10：恢复机会仍被漏选，q0保护不是全部方案

E0307／2132的H历史在441～501恰有1个良好候选状态，四影子规则却全都选0个良好。与Stage-63已定位475帧q2的唯一机会吻合：原Hann、q0及本轮两评分器都未抓住它；Stage-63一次接受q2的32帧持续收益仍保留。仅保护q0不能覆盖这个非q0机会。

R自身在该窗口61个状态四框全低；2133的F10两历史都无良好候选，R历史也全低。需要保留“识别稀少恢复机会”和“避免先前历史恶化”两条要求，不能将全部案例归为同一种排序错误。

第二列并非新控制器的拒绝阈值；64维任一维超界本来可能常见。第三列是先在单轨迹内计算候选对最大坐标绝对值的99%分位数，再种子／视频平均，不是全部帧合池的一个P99。

**fit native history与held-out native Hann按来源控制复现同一批原生历史。** 同一个视频在一折是fit、另一折是held-out，采用不同模型scale及fit参考区间。因此这对表的标准化差异包含跨折参考变化，不能说它们的原始输入轨迹发生了迁移；两行三级标签同值比例也完全相同。其他自身政策另有历史变化，但本表没有隔离两种作用。

Hann尾部53.56高于R的47.51，完整成绩却好于R；尾部统计不能独自识别有害政策或证明外推是唯一原因。两个目标在留组原生H历史上的对应目标绝对预测误差都高于拟合内参考，提示评分泛化仍有改善空间。quality与reliability单位不同，不直接比较其绝对误差大小断定校准优劣。

三级效用相同但连续IoU不同的相对q0候选对，宏比例约53.17%～64.69%。这确实显示当前三级标签把大量连续差别压平，但不证明所有差别都有长期价值，也不证明它是Stage-64失败的唯一原因。

条件率均按有支持的视频平均，不是全池帧比。例如E R历史上R的`low_given_good_q0=8.49%`，全帧宏`q0_good_to_low_fraction`却仅约0.139%。二者分母、权重不同，不能互换，也不能忽略少量支持造成的比例放大。关注窗口的整数计数更适合描述具体病例。

## 5. 对下一轮的具体建议

研究主线仍是SGLA因果历史上的稳健接管与状态推进。下一轮宜做一个有明确处理差异的小原型：在连续质量选择基础上，增加当前q0绝对可靠性判断，限制缺乏充分证据的替换；保留非q0恢复通路，必要时另列弱候选状态推进的独立控制。

现有模型只回归相对q0的分数差，q0分数固定为0，不能据这个0推断“q0可靠”。新可靠性判断应使用可在线取得的绝对响应／历史／几何信息，在原生fit侧训练和确定规则；不能用本轮GT事件帧号或在全部开发结果上挑阈值。需匹配连续质量、单纯提高接管门槛和增加状态判断的对照，区分新增判别信息与减少干预次数的效果。

0003和0307较好历史提供保护需求，E0307唯一机会保留非q0救回需求；0226／E0304显示弱候选阶段仍需关注尺寸／中心和后继可用性。可以先做上述接管原型，不要求先把所有原因证明完毕；候选本身不足可作为后续独立改进点。已有相似方法不否定这个具体增量价值。

本次未实现或启动Stage-66，未修改Stage-65、旧评分器或SGLA权重，也未重跑旧阶段。
