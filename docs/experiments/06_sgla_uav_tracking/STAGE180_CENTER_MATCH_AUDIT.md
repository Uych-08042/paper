# Stage-180 当前帧 CENTER 目标匹配证据审计

Stage-179 移除选择器 logits 的第一主成分后，留出组的后效排序仍接近均匀。本轮从原生 SGLA 当前帧的 CENTER 响应与回归图提取信号，复用已经测得的同状态续跑标签。

## 单帧采集

沿用 Stage-178 的 265 个起点、首帧模板、历史父框和原生选层。每点执行一次原生前向，从网络已有输出读取 `score_map`、`size_map` 和 `offset_map`，按原 Hann 窗加权。核对原生分支、父框、预测框、Hann 峰值及单次调用预算。复用原解码规则重建网格上的回归框，核对主峰框。模型、选层策略与续跑标签均沿用归档。

固定三类无真值信号。峰竞争强度为保留的次峰与主峰的分数比，局部峰和框 NMS 沿用 Stage-28 的定义。回归位置不一致度为用主峰偏移修正格点位置后，双线性插值得到的加权响应相对主峰的下降。近邻框不一致度为主峰周围 3×3 网格内，响应至少达到主峰一半的其他格点所解码框与主峰框的加权 IoU 差。联合分固定取三项均值。另记录原始响应与 Hann 主峰的距离，以及主次峰框的 IoU 供解释。

## 标签与判断

检查两个问题。第一，信号能否辨识目前的固定排序候选会带来受保护收益、挽救恢复或造成失跟。第二，信号能否辨识同一起点在五个非原生层中至少存在一个受保护的有益候选。用 Stage-176、177、178 已有后效标签，只纳入完整 128 帧窗口。Stage-176 的既有诊断组、其他组和 Stage-177 留出组分别报告。各项按同源组内可比较状态的排序一致率评估，报告可比较对和有支持的源组数，均匀基线计 0.5。信号较高表示原生响应更疑难，预设方向为更可能需要备选；对换层伤害采用相反方向。四个已知点单列。

只有运行身份相同才计算主关联。设备变化时仍可提取原生响应和检查原生框变化。信号若在多个独立源组有一致方向和足够标签支持，再进入等配额的候选放行对照。此轮不重新续跑，也不学习在线门槛。

## 运行

沿用 Stage-170、176、177 和 178 的目录，以及原始 checkpoint。GPU 运行身份变化时使用独立 `STAGE180_ROOT`。

```bash
cd ~/workspace/paper
mkdir -p output/stage180
nohup bash tools/run_stage180_center_match_audit.sh > output/stage180/run_stage180.log 2>&1 < /dev/null &
tail -f output/stage180/run_stage180.log
```

脚本记录总体进度，支持逐点缓存续跑，完成后生成 `stage180_results_*.txt`。优先查看 `stage180_dispersion.csv`、`stage180_association.csv` 与 `stage180_sentinels.csv`。
