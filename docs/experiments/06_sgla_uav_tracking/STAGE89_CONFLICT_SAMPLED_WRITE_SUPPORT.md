# Stage-89 候选冲突抽样与开发源组扩展

Stage-88 的 144 个窗口仅有三个备选分支与 PPO 的后续平均 IoU 相差至少 0.05，且同属一个源视频。低 IoU 帧比例还发现了平均 IoU 差阈值遗漏的退化。Stage-89 固定候选与续跑方式，改变开发样本覆盖及窗口抽样。

## 开发队列

保留 Stage-76 的 12 个源组及原双种子。用 VisDrone-SOT 训练集的 Stage-79 清单排除 28 个确认源组，再从历史开发排除名单中按固定哈希顺序选取额外 16 个不同源组。每组取字典序最早且可容纳 16 帧窗口的片段。追加组按固定顺序均衡分配给原四个折与种子组合，每段只跑一条冻结 PPO 轨迹。报告单列原队列和追加队列。追加组对这轮 PPO 是未参与 Stage-74 拟合的源组，仍属开发数据。

## 冲突与普通窗口

沿用 Stage-88 的固定四候选与 Hann 响应最强的不同备选。对比 PPO 实际选框与该备选。用前一预测框面积的平方根归一化两候选中心距离。

- 冲突组要求归一化中心距离 ≥ 0.50，且两候选 Hann 峰值绝对差 ≤ 0.05。
- 普通组要求归一化中心距离 < 0.50。每条轨迹每组最多取三个起点，先从冲突组按固定哈希顺序取，再取普通组。组内和组间续跑窗口不重叠，支持不足时保留实际数目。
- 每个起点的一臂保留 PPO 原选择，一臂只替换当帧写入。其后各自按冻结 PPO 续跑 15 帧。采样只读预测和响应。首帧用初始化框，其他标注只用于评价。

40 条基准历史最多产出 240 对窗口。相同 GPU 型号复用历史组 Stage-76 缓存，异型号重跑历史组。每个被采样起点先精确复现固定布局，再补跑备选，新增最多 15,360 次诊断搜索，另计新收集的完整基准轨迹。

## 判读

分别统计后续 15 帧平均 IoU 相差至少 0.05、低 IoU 帧数相差至少 4/16、以及起点 IoU < 0.2 时仅一臂连续三帧达到 IoU ≥ 0.5 的案例。报告窗口数和源组数，避免把双种子或相邻时间当成独立证据。在同时有两类窗口的源组上，比较冲突组与普通组的差异案例发生率。按视频聚合后做配对区间。本轮用于验证取样能否提供更充分的诊断支持，无训练，确认集不参与。

## 服务器运行

激活 `sglatrack-test` 并同步代码后，在仓库根目录执行。

```bash
bash tools/run_stage89_conflict_sampling.sh
```

默认读取 Stage-76 和其绑定的 Stage-74 模型，以及原 VisDrone-SOT train 路径。L20 或 L40 均可用，L40 若与原 Stage-76 不同型号会增加历史基准重跑。运行目录绑定 GPU UUID。换卡后使用新的 `STAGE89_ROOT`。完成后脚本打印结果 TXT 路径。
