# Stage-105 共同起点的搜索历史与外观写入交叉干预

2026-11-14已完成259起点／1,036短分支，状态`COMPLETE_MATCHED_GEOMETRY_MEMORY_COMMIT_DIAGNOSTIC`。以下保留固定设计，实际成绩、正反例及复核范围见[Stage-105结果](STAGE105_RESULTS_REVIEW.md)。使用原SGLA与冻结四候选PPO，候选生成、权重和阈值不变，只在一个固定起点改变提交给后续帧的状态。 [Stage-104结果](STAGE104_RESULTS_REVIEW.md)

## 要回答的问题

Stage-104发现两条不同路径：错误描述子可能进入外观记忆；输出即使被拒绝写入外观记忆，仍会进入普通搜索历史。0176／2172第251帧与0304／2172第1083帧均有这种几何反馈；另一方面，有些严重首败帧四个候选已经全部不好。

本轮直接测量后继：固定同一个过去状态和当前观察，分别把当前同状态pair框用于几何提交、用于外观写入，或同时用于两者。若后续效果不同，才能更明确地判断应修改哪条状态更新路径。

这是一次性提交机制的条件诊断，没有新方法采用门槛，不提供新的完整视频AUC。

## 四组仅在第一步不同

设`t`帧原四候选核验发布的框为`b4`，同一过去状态下原pair选择的框为`b2`。两者来自当前已有四个SGLA输出，不使用GT选框。

| 组 | t帧发布输出 | t帧提交普通搜索历史 | t帧外观写入的候选及资格 |
|---|---|---|---|
| `keep` | b4 | b4 | 原四候选核验的选择与资格 |
| `geometry_pair` | b4 | b2 | 原四候选核验的选择与资格 |
| `memory_pair` | b4 | b4 | 同状态pair的选择与资格 |
| `both_pair` | b4 | b2 | 同状态pair的选择与资格 |

四组`t`帧发布框完全相同。这样，后继差异不会被当帧改了评价输出所混淆。原四候选核验的资格与实际外观写入分别保存在`memory_write`和`memory_committed`，几何提交另存`geometry_box`，不把它们混成一个输出字段。

外观组重新应用pair原有写入资格：可能写入pair描述子、拒绝本次写入，或与原路径完全相同。没有从已有队列中按GT清洗历史，也没有强制把任意pair框写入。几何组提交当前pair框，不是直接停在上一帧中心。

从`t+1`开始，四组均恢复各自来源的原四候选核验和原提交规则，按自身状态推进，总窗口最多32帧，最后31帧为主要后继观察。没有在整个窗口持续覆盖决策或强制pair选择。

**处理对象是普通历史状态整体。** 原实现既用这段历史生成四个父框，也用它计算PPO的时序特征、外观使用条件和写入资格。因此几何提交干预同时改变这些派生量，不能把所得效果唯一归于裁剪中心。网络骨干、SGLA原生选择结构和PPO参数均冻结。

## 起点覆盖及冻结

来源为Stage-104决策`f923f8d0138e1e77458ce8f54f1f1058518f321d1980fb0f66cfa72f0ae6e2da`及其Stage-103来源。仍覆盖全部28个已消耗开发源组、40个既定种子单位；两个新四候选来源各40条，共80个来源上下文，不抽选单个视频或种子。

每个上下文使用相同的起点规则：

1. 纳入Stage-104记录的首次额外框替换、首次与完整pair输出分叉、首次丢好、首次引入低IoU。
2. 对首次失败及新增pair稳定单位失败，纳入目标前最近一次替换，以及目标前一帧。最近替换可能恰在失败当帧，按固定记录处理。
3. 对全部新增丢失的PPO／pair恢复，纳入参考恢复前一帧，以及截至参考帧最近一次丢好；若没有丢好则用最近替换，仍没有则用参考帧。
4. 从完整来源缓存中补入首次好框补回，作为收益控制，不能只围绕有害替换设计实验。

同一上下文中起点重合时合并，保留全部角色和恢复事件身份。每个窗口为`[t,min(t+31,视频末帧)]`，不根据新结果延长。服务器先用CPU审核80条来源、冻结去重后的起点、角色、末帧和预算并写manifest，再启动新GPU搜索。每个上下文都会打印起点数量。

起点包含离线GT定义的丢好／补好和已知失败、恢复结果，是已消耗开发证据上的诊断抽样，不能当成线上触发器或独立验证。干预的候选选择、外观写入、后续PPO和搜索历史更新不读取这些GT。

## 共同观察、真实后继与硬件

从来源恢复`t−1`以前的普通框历史、实际写入队列及原首帧anchor；网络重新用原始首帧图像和初始GT框初始化。V1没有在线模板更新或需要另行恢复的神经历史缓存。

当前GPU重新计算一个共同的`t`帧四搜索观察和四描述子；四组共享这一观察。从`t+1`开始每组都重新执行四次SGLA搜索，不能把原缓存的响应或框搬到改变后的裁剪上。

- 同型号、UUID和软件身份与Stage-103全部相同时，`keep`整段候选、查询、选择、输出、裁剪、引用和资格必须复现来源，最大框误差0。
- L20／L40或UUID变化时，四组和共同观察全部在当前卡重新推理，记录`keep`相对旧来源的框差；仍条件于同一个旧来源过去快照。比较基准是当前卡`keep`，不把新分支与旧卡分支直接当同卡实验。
- 权重、配置及软件差异继续拒绝；只允许型号／UUID变化。首次启动自动识别当前卡，不需要提前修改固定型号。中断后换卡必须指定新的`STAGE105_ROOT`，不能往旧manifest混写。

## 预算与状态审计

每次搜索7个执行块。长度为L的一个起点，四组逻辑上记录`16L`搜索；由于第一帧共同观察只执行一次，实际新增为`4+16(L−1)=4(4L−3)`。完整32帧起点为500次新搜索、3,500块。全部预算由冻结后的起点计算，不预先猜测去重数量。

每个起点保存一个共同观察和四个分支缓存，共五个有回执NPZ。已提交缓存只读校验后复用；续跑不重复已有推理。重复首帧模板准备、描述子池化及图像读取仍有代价，本轮不作部署延迟或能耗结论。

逐帧重演PPO、四候选核验、过去外观队列、实际外观写入、几何提交和下一父框；校验取整裁剪、head／selector／block调用形状与decode误差。干预第一帧后`commit_intervention`必须恢复为false，几何与外观提交都回到该分支自己的原决策。

报告干预是否真正改变了几何或记忆；若pair与原选择、资格或描述子相同，对应处理可以不生效，不把无效处理当成功保护。所有组的第一帧完整原核验输出必须相同。

## 指标、角色与恢复

主要看`t+1`至窗口末帧的平均IoU、低IoU比例、好候选供给比例和有好框却漏选比例，另报末帧IoU、第一帧原输出／pair IoU、有效后继帧数，以及相对当前卡keep的首次输出／裁剪／PPO／写入／引用分叉。

预定比较为几何组、记忆组、共同组各减keep；交互为`both−geometry−memory+keep`，另报两个因素的顺序平均效果。后继低IoU和漏选比例的正差表示更差。

总体按唯一去重起点汇总；另按角色分层，同一角色在同一起点只记一次。先平均单位内起点，再平均视频内既定种子，最后视频等权。区分历史12组和追加16组、两个来源核验。角色窗口重叠、来源拟合和视频均已消耗，报告是条件诊断统计，不以帧数或窗口数假装独立样本；不设新的通过门槛或泛化置信声明。

恢复保持原规则：连续三帧IoU≥0.5的起点位于`[参考恢复帧,参考帧+15]`。每个起点／来源／事件／处理单独记录。若32帧窗口未覆盖参考帧之后17帧且未找到恢复，记`right_censored`，不能算完整恢复失败。较早丢好起点可能离恢复很远，原样保留这一边界，不延长到结果有利为止。末帧起点没有未来时后继指标不适用。
