# Stage-133 原生 SGLA 单搜索失跟诊断

Stage-131 的多搜索方案在完整开发视频上低于原生 SGLA。Stage-132 进一步观察到，搜索区域改变后，新候选即使没有获选，也可能改变输出框与后继搜索。本轮回到原生 SGLA 的单搜索轨迹，检查失跟从哪里开始，以及当前裁剪内的响应和回归结果是否已经提供了可用的替代框。 [Stage-131](STAGE131_RESULTS_REVIEW.md) · [Stage-132](STAGE132_RESULTS_REVIEW.md)

## 固定输入与读表

使用 Stage-131 原生结果所复用的 Stage-121 L40 轨迹缓存，覆盖 28 个开发视频、29,047 个跟踪帧和 19 个原生失跟事件。逐帧校验原生父框为上一帧输出，搜索调用为一次，缓存 Hann 最高分格的解码与已存原生框一致。最后核对逐视频 AUC 和失跟事件数。使用旧缓存与标注，新增网络搜索、图片读取、训练及轨迹均为零。

对同一个原生裁剪比较三组输出。原生 Hann 加权最高分格给出基准框，原始响应最高分格用于检验取消 Hann 权重的当帧影响，所有格点解码框的最高 IoU 用于估计这张响应图能提供的候选上限。所有格点最高 IoU 使用当帧真值，只作为事后诊断。原始响应最高分的指标也沿原生轨迹的裁剪逐帧计算，称为固定状态 AUC。只有后续独立闭环实验才能测到改选以后搜索区域的变化。

每个低 IoU 帧（IoU 小于 0.2）记录该帧的表现。原始最高分若达到 IoU 0.5，表示仅改变峰排序在这张图上即可取到好框。若达到 0.5 的框出现在其他格点，则另记潜在候选。全网格都没有好框时，再按目标在裁剪有效图像区域的覆盖比例区分无交集、覆盖不足和覆盖充分。覆盖充分要求覆盖至少 90% 且真值中心落在有效裁剪内。充分覆盖仍无好框涵盖表征、响应定位和回归，现有证据只能定位到裁剪内部。用原本为好框却被原始最高峰换成低 IoU 框的数量衡量潜在副作用。

- `stage133_summary.csv` 记录各类的全帧出现次数、失跟起点数与涉及视频数。事件依据原评估口径，连续三帧低 IoU 确认失跟。
- `stage133_events.csv` 逐事件记录起点、确认、终止、恢复和起点的候选支持。
- `stage133_anchors.csv` 记录起点前 3 帧、前 1 帧、起点、后 1 帧与后 2 帧，以及恢复前 1 帧与恢复首帧。保留原始响应和 Hann 响应各自的前五峰是否含好框、输入尺度、裁剪覆盖与补边比例。
- `stage133_video.csv` 保留全部视频的原生 AUC、固定状态原始响应 AUC、由低转好及由好转低的帧数。关注效果是否由少量视频主导。

优先根据失跟起点的证据选择一项等预算干预。若好框在原始响应最高峰而被 Hann 压低，先验证选择机制。若主要是裁剪无交集或覆盖不足，优先检验单搜索裁剪几何。若覆盖充分且缓存格点无好框，进一步定位表征和回归。

## 服务器运行

在存有 Stage-76、89、93、121 和 131 产物的 Linux 仓库根目录执行。

```bash
bash tools/run_stage133_native_failure_audit.sh
```

默认输出目录为 `output/stage133/native_failure_audit_v1`。通过 `STAGE133_ROOT` 可指定新的独立目录。脚本会打印 `stage133_results_*.txt` 的结果包路径。
