# Stage-100 完整视频中的在线尺寸短暂调整

2026-11-14执行补充：历史原生q0四槽缓存检查问题已通过[兼容入口](STAGE100_NATIVE_CACHE_COMPAT.md)解决，服务器完成188条逻辑完整轨迹。pulse比gated低0.6221 AUC，开发保护未通过，详见[完整结果复核](STAGE100_RESULTS_REVIEW.md)。下文原设计和执行入口保留为来源，不重复运行。

## 研究问题

Stage-99在25个指定起点窗口中发现：原规则／只调整一次／持续更新恢复21／23／20次。一次调整保留全部原有恢复，但0085仍出现中途精度下降。起点由已有分支分叉记录确定，不能直接据此宣称在线算法有效。

本轮把SGLA搜索区域构造改动放入完整视频，检验一个固定、仅依赖自身观测的启停规则。所有新轨迹从首帧目标框初始化，之后独立跟踪到视频结束，不在失跟、恢复或旧事件锚点处重置。SGLA原网络与首帧模板、四候选PPO、外观选择和写入资格均保持冻结，无新增训练。

## 在线规则

每帧搜索前，从本分支过去预测框计算两套父框：

- 普通尺寸：q0／q2取最新预测尺寸，q1／q3取最近五个预测框宽高的对数中位数。
- 可信历史尺寸：q0／q2保持原值，仅将q1／q3尺寸替换为近十二帧内、最多五个有资格框的对数中位数；至少两条，不足则回到普通规则。

有资格的记录沿用Stage-97：原有外观写入规则允许最终框写入，且相应描述符为有限值。“可信”是在线资格名称，不保证GT准确。当前帧输出在选框完成后写入，最早下一帧使用。

两套父框使用同一份自身历史中心。若可信尺寸会改变q1或q3的**取整裁剪几何**，记当帧存在尺寸分歧`R(t)=1`；仅浮点父框不同而实际裁剪相同，不触发短暂调整。此判据只使用此前尺寸记录、此前预测及当前图像高宽，不需要先对两种布局分别推理。

短暂调整组在`R(t)=1`且`R(t-1)=0`时启用可信尺寸一帧。下一帧恢复普通规则；分歧仍存在时不重复启用。出现一帧无分歧后，再次出现分歧即可触发。初始化`R(0)=0`，整段视频中不额外重置。例：分歧序列`0,1,1,1,0,1`对应调整`0,1,0,0,0,1`。每次调整后的实际输出照常进入预测历史与外观记忆。

十二帧、五条、至少两条及资格沿用旧设计；本轮没有新增阈值搜索或冷却时长。它是一个待检验的启停原型：分歧可能只是正常尺度变化，也可能频繁消失后重现，必须报告触发频率及性能。

## 五组完整轨迹

| 组 | 搜索与选框 | 数量 |
|---|---|---:|
| `native` | 原生单搜索SGLA | 28 |
| `ppo` | 原固定四候选PPO | 40 |
| `gated` | 固定四候选＋Stage-93筛选历史外观，普通尺寸 | 40 |
| `continuous` | 筛选历史外观＋持续可信历史尺寸 | 40 |
| `pulse` | 筛选历史外观＋在线短暂尺寸调整 | 40 |

四候选各组每帧均执行四次SGLA搜索，无第五次搜索或恢复支线。continuous沿用Stage-97的资格规则，有足够引用即持续使用，即使该帧取整裁剪未变化也不额外关闭；pulse只在实际裁剪分歧开始时启用。因此两组比较包含启用资格和持续方式的整体差异，不能解释成单独改变一个持续时间参数。

范围固定为Stage-93全部28个已消费开发源组、40个已有PPO单位：原12组各两种子2171／2172，追加16组各沿用来源的一个种子。每个单位各走自身实际输出，三组几何更新的记忆也由本组输出形成。每个新几何组在相对gated首次父框变化以前，预测、候选、外观描述、写入及选择均须一致，首帧模板描述也须一致。

28组独立确认清单继续封存，本轮不读取确认图像或执行确认推理。Stage-99指纹绑定为`ccc86856f8b6fdd7a3c195a373cbb10b32c6890ed54ea184db4d1383e7161310`，该结果仅作为设计来源，事件时刻和结果不进入在线控制器。

## 评价与预定门槛

主要比较pulse−gated和pulse−continuous；同时报告pulse−PPO、pulse−原生SGLA、continuous−gated。各视频先平均已有种子，再按视频等权汇总。保留all／historical／expanded三队列，按视频重采样10,000次；两项主要AUC比较提供97.5%各自区间作为两比较家族校正，其他区间为名义95%。这些区间条件于冻结PPO和已消费开发集，不涵盖重新训练的不确定性。

报告完整轨迹AUC、低IoU比例、最长失跟比例、原生可靠帧AUC、失跟／恢复／未恢复事件、有好候选帧比例。完整评价既包含稳定段也包含所有原失败段，不能只挑恢复窗口。重点关注0226、0307、0076的恢复和0085的中途损伤，全部28组均保留在表中。

分别以本轮PPO和gated为参考，对齐其完整轨迹的全部恢复事件。恢复仍要求参考恢复首帧起十五帧内开始连续三帧IoU≥0.5。保护检查按具体事件集合比较：不允许把一个原已保留PPO事件丢掉，再用另一个恢复抵消成相同损失总数。

开发检查固定为：

1. pulse对gated宏AUC至少+0.5点；两项主要AUC家族区间下界均大于0。
2. pulse相对gated的低IoU与最长失跟比例不增加，原生可靠帧AUC不下降。
3. 在gated稳定和PPO稳定视频中均无新增失跟。
4. gated自身原有恢复全部保留；相对gated未新增丢失的具体PPO恢复事件。
5. pulse确实至少改变一次实际裁剪。

全部通过才报告`PROMISING_ONLINE_SCALE_PULSE_DEVELOPMENT`，否则`REVIEW_ONLINE_SCALE_PULSE_DEVELOPMENT`。这仍是开发证据，不等于独立确认或已成立的论文方法。不能因为只通过恢复数就放过稳定性和AUC损伤。

## 产物

输出`analysis/stage100_decision.json`及六表：

- `policy_summary.csv`：三队列五组宏指标和保护计数。
- `paired.csv`：视频配对差与区间。
- `video_summary.csv`、`seed_video.csv`：视频及种子层指标。
- `scope.csv`：每条轨迹的调用、分歧帧、分歧开始次数、启用帧、实际裁剪变化、外观换框和来源误差。
- `recovery.csv`：分别以PPO／gated为参考的具体事件对齐。

分支NPZ保留逐帧父框、实际裁剪、候选、动作、外观记录、尺寸引用和在线状态。`scale_episode_start`在各组均记录诊断性分歧开始，只有pulse将其作为实际启用动作；continuous的实际启用可能覆盖整个分歧期间。`scale_active`记录可信尺寸实际引用，避免把诊断资格当作执行。

## 服务器执行

同步本轮新文件，进入仓库并激活`sglatrack-test`环境后执行：

```bash
bash tools/run_stage100_online_scale.sh
```

默认来源为已有Stage-76、89、93、99根目录，输出`output/stage100/online_scale_episode_pulse_v1`，使用原V1 checkpoint和逻辑GPU0。可通过对应`STAGE76_ROOT`／`STAGE89_ROOT`／`STAGE93_ROOT`／`STAGE99_ROOT`、`CHECKPOINT`、`STAGE100_GPU`修改输入，通过`STAGE100_ROOT`选择新输出目录。

关闭SSH后继续运行：

```bash
mkdir -p output/stage100
nohup bash tools/run_stage100_online_scale.sh > output/stage100/run_stage100.log 2>&1 < /dev/null &
tail -f output/stage100/run_stage100.log
```

nohup维持远程断连后的进程，节点／作业被平台回收仍会终止。完成后回传脚本打印的`stage100_results_*.txt`，包含decision和六表。已完成运行可执行`bash tools/run_stage100_online_scale.sh --pack-only`重新核验和打包。
