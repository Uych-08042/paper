# Stage-151 改选写回后的中心与宽高交叉对照

Stage-150 中，0089／1159 的灰度框当帧更准，写回后却从次帧开始落后。0085／690 的灰度框当帧 IoU 只有 0.2896，写回后则恢复。Stage-151 检查这两类后果是否由改选框的中心移动、宽高变化或两者共同造成。 [Stage-150 结果](STAGE150_RESULTS_REVIEW.md)

## 实验设计

沿用 Stage-150 全部 14 个改选起点和已缓存的两个原始框。四路只在生成下一帧搜索区域时使用下表中的初始框。中心和宽高分别交换，混合框按原始浮点坐标构造，避免额外截边改变预设中心。

| 分支 | 初始搜索父框的中心 | 初始搜索父框的宽高 |
| --- | --- | --- |
| `regression` | 回归 | 回归 |
| `gray_center` | 灰度 | 回归 |
| `gray_size` | 回归 | 灰度 |
| `gray_once` | 灰度 | 灰度 |

后继各路每帧只调用一次原生 SGLA 搜索，按 Stage-150 的固定回归评分器选框，再用自己的输出继续。原始两路也在当前同卡重跑，合计预定 1,428 次后继搜索。同一运行身份下校验原始两路逐帧与 Stage-150 缓存一致。首次换卡仍在新卡上配对重跑四路，并记录原始两路相对旧缓存的坐标差和一致帧数。

## 判读

- 下一帧分别记录可用裁剪覆盖、输入中的目标短边像素数、全网格最佳 IoU、候选池最佳 IoU 和实际回归选中框 IoU。全网格和候选池的真值上限只用于事后定位。这样可以区分网格未给出好框、提取漏掉好框和回归漏选。
- 后续 8／32 帧报告逐起点平均 IoU 与连续 3 帧好框或严重低 IoU。完整窗口按源组先平均再等权汇总，记录固定宽高时换中心、固定中心时换宽高的差和两者交互。末帧起点保留在窗口记录里。
- 这是已触发开发样本上对单次写回几何的诊断。结果可定位裁剪和选框发生变化的位置，整段 AUC 与独立源组泛化仍需另行评价。

## 执行

同步代码后，用训练服务器的 `sglatrack-test` 环境，提供 Stage-150 完整产物及其来源目录、原 SGLA checkpoint 和 VisDrone-SOT 图片。首次可用 L20 或 L40，运行中断后同目录需保持同一 GPU 运行身份。

```bash
mkdir -p output/stage151
nohup bash tools/run_stage151_write_geometry.sh > output/stage151/run_stage151.log 2>&1 < /dev/null &
```

默认输出 `output/stage151/write_geometry_cross_v1`。完成后回传该目录下的 `stage151_results_*.txt`。
