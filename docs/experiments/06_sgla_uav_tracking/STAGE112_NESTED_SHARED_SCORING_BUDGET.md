# Stage-112：匹配候选评分训练与搜索数量对照

固定设计日期：2026-11-15。状态：本机实现和合成测试已完成，正式服务器结果待运行。

Stage-110显示算法生成集合的最佳候选IoU改善，Stage-111显示旧PPO换序无法完成适配。用户随后提出“四个只是预算条件，不能当作最优数量”。本轮同时检验：**匹配新候选的质量训练能否减少错选，以及搜索从2增加到4/6/8时，供给和实际选框怎样变化。**

本轮新增监督质量评分训练、源组共同留出和SGLA候选采集。PPO仍作为冻结控制，完整自身轨迹评价接续进行；本轮提供当前状态的选择与预算证据，不报告新完整AUC。

## 1. 固定来源及共同留出

绑定完整Stage-111 decision `61d3d1e808b8df3f317489c2b9f0dc4d69fe7f65a5e7f8e04d2aa492c39b13f5`及其Stage-110/103来源。SGLA V1权重、首帧模板、原生解码和搜索规则保持原样。28个已消耗开发源组、40个旧视频/种子单元、两种来源历史，共80上下文；28个确认源组继续封存。

按源组名排序，在历史12组和扩展16组内分别轮转分成四个外层fold。每fold留出3历史+4扩展=7组，其余21组供新模型学习：

| 对象 | 可用组 | 评价组是否进入 |
|---|---|---|
| 生成器均值/条件误差拟合 | 21组中14组 | 否 |
| 生成器误差范围校准 | 21组中另7组 | 否 |
| 两种新评分器及标准化 | 全部21训练组 | 否 |
| 当前状态评价 | 留出的7组 | 仅在选择保存后附标签 |

生成器内部沿用Stage-110固定算法和超参数：ridge=1、三折源组残差、条件尺度、90%经验范围校准及32个反向配对高斯场景。**重新拟合四个外层生成包**，不能直接复用Stage-110其他组的生成缓存；那些包可能用过当前外层评价组标签。每包额外记录全部七个外层留出组，不只记录内部模型的单个held-out名称。

旧PPO、来源历史和其他上游产物已经用于开发。新模型的共同留出不意味着整个历史生成流程都实现独立交叉验证，本轮不是封存确认。

## 2. 固定采样与重新采集

沿用Stage-110的96个等间隔拟合身份与24个不重合评价身份，身份只依赖帧号/上下文。

- 训练上下文：从原96个拟合身份中，等间隔取24帧作为评分器训练状态。生成器仍使用训练源组的原96帧拟合记录。
- 评价上下文：保留原24个评价身份，覆盖全部1,920个共同状态；不按旧错选、GT或模型结果筛选。
- 每fold有1,440个评分器训练状态和480个评价状态，总共采集7,680个fold/状态，其中5,760用于评分器训练、1,920用于外层评价。
- 在各fold模型和相应旧历史下，重新获得原固定四布局与算法生成最多八布局的SGLA观测。完全相同浮点父框共享观测；原fixed q0与生成q0相同。

生成父框先写NPZ/收据，随后读取图像并搜索；评分器训练标签只从训练源组获得。外层评价的所有规则/评分必须先保存预测NPZ，再附评价标签。

每状态12个逻辑槽位（fixed4+generated8），最多11次唯一搜索。整个采集上限为92,160逻辑搜索、84,480唯一搜索、591,360搜索块调用；另有7,680次首帧模板初始化和相应图像读取。完全相同父框更多时调用减少；模板调用和故障重试不能冒充免费。

新fold生成器的14拟合/7校准与Stage-110的18/9不同，因此不能要求其生成框或0.670099最佳IoU精确复现。所有对照本轮同卡重新观测。原fixed在运行身份无差异时必须逐字段复现Stage-103，否则记录硬件差异与框误差。

## 3. 评分器及结构控制

两种新网络都预测四个当前候选的GT IoU，用同一加权MSE目标、同一状态标签、同一批次顺序、标准化和更新预算训练。不是将旧PPO权重换一个排列，也不是新PPO训练。

| 模型 | 结构 | 参数 | 是否依赖非q0槽位 |
|---|---|---:|---|
| concat | 256→32 Tanh→4 Sigmoid | 8,356 | 是 |
| shared | 每候选64→32 Tanh→1 Sigmoid，参数共享 | 2,113 | 不编码q1/q2/q3身份 |

原24维响应/几何描述加8维候选关系，再加入32维平方项，保留64维；K=4时精确沿用原描述函数。K=2/6/8时关系均值按实际候选数计算，不补零框伪装四候选。共享模型在q0固定、其他候选同步交换框/特征时，其分数应随候选一起交换。

64维标准化只在当前fold、当前生成方案的训练状态上拟合，并跨四个槽位共享；concat使用同一标准化后再展平，shared逐候选输入。标准化后裁剪至±10。训练按源组→种子→来源模式→记录平衡，各状态四个候选等权。

固定种子2312/2313、hidden32、20epochs、minibatch128个状态、Adam LR3e−4、β=(0.9,0.999)、epsilon1e−8、全网梯度范数裁剪1；保留最后一步，不按评价结果挑checkpoint。没有额外q0保护损失或评价阈值搜索。每模型1,440个训练状态、240次更新；共32个评分器、7,680次评分优化更新（GT均有效时）。均值/尺度/校准的统计拟合另记为四个生成包。

两种网络hidden相同但参数量不同，不能将比较解释为完全相同容量的纯排列消融。Sigmoid输出以当前IoU为拟合目标，未另行证明分数的概率校准或未来收益含义。

## 4. 对照与候选数量

| 输入集合 | 评价规则 |
|---|---|
| fixed，K=4 | q0、Hann、旧PPO、匹配训练concat、匹配训练shared、GT oracle |
| generated，K=4 | 同上 |
| generated，K=2/6/8 | q0、Hann、同一个K=4训练的shared、GT oracle |

两个训练种子单列为`model_seed`，来源轨迹原种子仍是`seed`。汇总先在同上下文内平均训练种子及状态，再平均来源模式、原种子、源组。所有28组、历史/扩展及matched/pairwise均完整报告。

生成器先按Stage-110软覆盖增益贪心选到最多8个区域，K=2/4/6/8严格使用同一序列的前缀；共同q0不变，不按最终K重新寻找有利集合。四是预定主预算；不预设最优，不根据四条曲线事后宣布一个最佳K。K=2/6/8使用同一个K=4训练模型，评价的是该模型的数量迁移，不代表各K分别训练后的最优结果。

更多候选的oracle最佳IoU按前缀不会下降，但实际选框可能下降；更大集合同时改变关系特征和评分竞争。需要将“供给变好”和“选得更好”分别报告。

## 5. 主要比较、成本与下一阶段

预定主要比较为generated_4上的`shared_minus_hann`当前IoU。必看共享模型对q0、旧PPO、concat；以及generated_4/shared对fixed_4/shared。另报2/6/8相对4的差值，不将K搜索当确认性结论。

指标包括实际选择IoU、候选最佳、漏好、有害q0替换、oracle regret、逻辑搜索次数、唯一父框搜索次数及搜索耗时；给出源组均差、中位、胜平负和最小留一均差。本轮COMPLETE仅表示执行完成，没有最终方法采用门槛。

计时在每个唯一父框搜索前后同步GPU，包含该搜索观测及解码；按某集合内实际唯一父框的观测耗时求和。**不包括图像读取、模板初始化、提议生成和评分器成本，不是端到端部署延迟。** q0控制为同预算诊断也按整个已采集合计费；单独部署q0原本只需自己的搜索，不能据此宣传与新方法等成本。训练、评价、跨K和跨生成器共享观测，整体实验调用量与单策略调用量分开解释。

接续优先取得完整自身轨迹：评分器/生成器冻结后，让各控制沿自己的历史推进，检查AUC、原稳定视频损伤及恢复保护，再在同架构/预算控制下检验PPO的后继价值。若本轮同状态选框仍落后q0/Hann，应先检查训练支持与评分误差，不通过增加K或只看oracle掩盖。共享结构的排列不变性不保证其准确性。

## 6. 运行与产物

需要服务器原环境、完整Stage-76/89/93/103/110/111产物和原SGLA checkpoint。支持首次L20或L40，自动绑定型号/UUID和软件；同根续跑必须同运行身份，换卡另设新`STAGE112_ROOT`，不混合未完成观测。

```bash
cd ~/workspace/paper
mkdir -p output/stage112
nohup bash tools/run_stage112_shared_scoring.sh > output/stage112/run.log 2>&1 < /dev/null &
echo $!
```

默认输出`output/stage112/nested_shared_scoring_budget_v1`。可用`STAGE112_ROOT`、`STAGE112_GPU`、`CHECKPOINT`及六个来源根变量覆盖。训练评分器在CPU NumPy上进行；新候选采集需要GPU。

完成后自动核验并打包`stage112_results_<UTC>_<PID>.txt`。只打包既有完整结果：

```bash
bash tools/run_stage112_shared_scoring.sh --pack-only
```

预计七表行数：fold_support4、sampling_scope320、training_scope32、collection_scope7,680、state_decisions59,520、policy_summary216、paired486。主报告记录四个生成包、32个评分器、实际搜索/块调用、来源误差、零PPO/SGLA更新与零确认推理。保留manifest、generator_fit_inputs、模型、proposals/observations/predictions及收据，Git结果txt不能替代完整服务器缓存。

完整缓存续跑会复核生成器数值及旧观测，再复用已封存评分器和搜索；单个未完成CPU评分模型从固定种子重算，已保存模型不重新训练。中断后的额外实际运算另记，报告统计的是唯一已提交产物。脚本不自动commit/push，nohup不延长平台作业时限。
