# Stage-125 备用搜索触发后的短程闭环

**正式 GPU 短分支已完成。** 比较在相同触发状态下使用原评分、重训关系评分或重训独立评分，是否改善之后 31 帧的跟踪。 [结果复核](STAGE125_RESULTS_REVIEW.md)

## 固定起点与对照

取 Stage-121 记录中 358 个实际启用备用搜索的状态，使用 Stage-124 的两种留出评分器及两个固定模型种子。起点选择规则是全用，只有视频末尾不足 31 帧的 12 点截断并单列，不纳入主配对。其余 346 点来自 17 个视频，涵盖全部 9 个补出好框的起点。原记录在 q0 的 IoU <0.2 时选中好框的原始触发记录仅 2 个（有完整窗口），救援子集的估计支持有限。

| 条件 | 触发帧选择 | 接下来 31 帧 |
|---|---|---|
| 原评分 | Stage-121 原评分 | Stage-121 原评分、生成与备用规则 |
| 关系评分 | Stage-124 留出关系评分，两种子分别运行 | 同上，按该条分支自身历史 |
| 独立评分 | Stage-124 留出独立评分，两种子分别运行 | 同上，按该条分支自身历史 |

每个起点共享过去和四候选。起点可改变选中的搜索状态和当帧分数，后者可能使下一帧的备用搜索触发发生变化。原评分从下一帧起恢复。若两个条件在起点选中同一槽位且发出同样的下一帧备用请求，它们的后继输入相同，共享一条实际轨迹。两套模型种子均保留，逻辑评价共 1,730 条短分支。未改变 SGLA 权重或训练模型。

完全相同的 GPU 运行身份下，复用 Stage-121 的起点和原路线窗口，核对初始分数与 Stage-124、逐帧回放候选构造和原评分。若只换 GPU 或卡 UUID，则用保存的共同历史在新卡重新观察起点，所有续程在该卡重跑，并记原始起点和重观测的框差、动作差。软件、模型或配置的漂移仍由原运行身份校验拒绝。最多四次搜索／帧，记录实际去重和缓存调用。完全匹配运行身份时新搜索上限 171,616 次，换卡重观测时上限 215,904 次。

主指标是从起点后一帧开始的 31 帧平均 IoU，独立评分与原评分、重训关系评分分别配对，先按原来源种子平均起点，再按视频等权。单列后续低 IoU 帧数、原路线持续至少三帧为好框的窗口是否丢失、原先选中好框的起点是否丢失，并按备用新增好框和原记录救援分层。连续三帧达到 IoU ≥0.5 是本轮短窗口指标，完整视频恢复评价另行验证。

本轮覆盖 Stage-121 实际访问过的已消耗开发状态。起点一次切换的结果用于解释后继作用，不能当作持续在线切换方案的完整 AUC。 [Stage-124 结果](STAGE124_RESULTS_REVIEW.md) · [Stage-121 结果](STAGE121_RESULTS_REVIEW.md)

## 后台运行

同步脚本到保存 Stage-76／89／93／112／121／124 产物和原始检查点的服务器仓库。在原环境中运行：

```bash
mkdir -p output/stage125
nohup bash tools/run_stage125_trigger_continuation.sh \
  >> output/stage125/run.log 2>&1 < /dev/null &
```

完成后日志会打印 `output/stage125/alternate_trigger_continuation_v1/stage125_results_*.txt`。脚本支持 `--pack-only` 校验并重新打包。用 `STAGE125_GPU` 选择 CUDA 逻辑设备，用 `STAGE125_ROOT` 指定单独的输出根。输出根的断点续跑须使用同一张卡。
