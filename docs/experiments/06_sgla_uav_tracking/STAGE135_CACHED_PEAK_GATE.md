# Stage-135 同裁剪第二峰改选条件

Stage-134 在 19 个失跟起点和 28 个原生稳定窗口上各保存了两条短程分支。Stage-135 从这些窗口重新选择原生框或 Hann 第二峰，检查当帧响应和历史框能否区分有益和有害的改选。每个窗口最多改选一次，后续 32 帧直接使用对应的已缓存分支。 [Stage-134 结果复核](STAGE134_RESULTS_REVIEW.md)

## 固定比较

| 规则 | 采用 Hann 第二峰的条件 |
| --- | --- |
| 原生对照 | 始终取原生第一峰 |
| 强制第二峰 | 有不同的第二峰框就采用 |
| `close_score` | 第一与第二峰的 Hann 加权分数差不超过第一峰的 20% |
| `close_conflict` | 分数条件成立，且两框 IoU ≤ 0.20 |
| `close_conflict_history` | 前两项成立，且第二峰框与历史外推框的 IoU 比第一峰框高至少 0.10 |

历史外推使用前两个已提交框的中心位移作为速度，位移长度最多为上一框宽高几何平均的 0.50 倍。外推框沿用上一框宽高。历史只有一个框时直接用该框。三条规则采用固定阈值，全部条件只读共同起点可观测的信息。规则不通过时保留原生输出。主比较为 `close_conflict_history` 对原生，各规则都报告改选次数、后续平均 IoU、失跟窗口新增／丢失恢复和稳定窗口新增低 IoU。

附带计算只用于解释恢复潜力的事后对照 `hindsight_recovery_bound`。它只在第二峰能新增恢复的失跟窗口选择第二峰。用回传表在本地复算后，两个固定分支最多覆盖 3 个新增恢复窗口，事后选择可同时保住原生已有的 6 个恢复。这个对照使用了后续结果。三条可在线计算的规则需要用服务器的缓存评估。

这批窗口按原生轨迹和真值选取，涵盖 19 个失跟起点和 28 个稳定窗口。结论适用于已消耗开发组的同起点短程诊断。完整视频误触发率和重复改选效果需要逐帧运行验证。程序只做 CPU 计算，读取 Stage-121 的历史框及 Stage-134 的响应、分支和结果表。新增搜索、训练和整段视频推理均为零。

## 运行

```bash
bash tools/run_stage135_peak_gate.sh
```

输出默认在 `output/stage135/cached_peak_gate_v1`。`stage135_results_*.txt` 包含汇总、逐窗口门控依据和运行记录。
