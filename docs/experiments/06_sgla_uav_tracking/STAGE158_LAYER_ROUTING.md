# Stage-158 等预算六选一与短程续跑

## 实验

在 Stage-137 的 47 个起点上，比较 L6 输出分别进入 L7、L8、L9、L10、L11、L12 的独立路径。共享首帧模板、搜索父框、裁剪和 L6 特征。每条路径在部署时只需要 7 个块、1 次预测头。报告中的六头计算用于离线枚举。匹配原 Stage-137 设备时复用其六组起点预测。换卡时在新卡重算所有起点预测，并在同一卡上完成各分支续跑。

以每层的预测框作为下一帧搜索状态，各自走原生 SGLA 32 帧。共 282 条短分支、9,024 次后继搜索。对照原生选择器、逐个固定块、以及由 Stage-155 同一源组划分的另一折选出的最佳固定块。GPU 评估以拟合折后 32 帧视频均值确定最佳固定块。用真值分别选当帧 IoU 最大、后续 IoU 最大、兼顾原生好框及恢复保护的块，用于测量空间。连续好框定义为连续三帧 IoU ≥ 0.50，连续低 IoU 定义为连续三帧 IoU < 0.20。主表列出后继 8／32 帧 IoU、恢复变化、各层使用数及逐视频剔除的最差结果。本轮使用已消费开发起点。

## 本地当帧结果

复算 Stage-137 的归档，两折各自在拟合组都选 L7。按视频平均，原生／这个固定对照／当帧真值最佳的 IoU 分别为 **0.5671／0.6394／0.7099**。在 19 个失跟起点中三个对照分别选中 0／5／8 个好框。在 28 个稳定窗口的起点，L7 保留 26 个原生好框。两折选 L7 依据是当帧 IoU，续跑对照会依据 32 帧结果重新评估。尚无六层后继结果。

## 运行和进度

同步代码后进入服务器仓库根目录，复用原 checkpoint 及 Stage-76、89、93、134、137 完整结果。可以使用 L20 或 L40，同一输出目录的续跑须保持该次运行身份。

```bash
mkdir -p output/stage158
nohup bash tools/run_stage158_layer_routing.sh >> output/stage158/run_stage158.log 2>&1 < /dev/null &
tail -f output/stage158/run_stage158.log
```

日志在各起点开始和完成时刷新，运行中默认每 10 秒显示搜索计数、百分比、已复用搜索量、耗时、ETA、当前 L7–L12 分支和第几个后继帧。可用 `STAGE158_PROGRESS_SECONDS` 改频率。每个起点的六条分支验证后作为一个缓存保存。续跑从已保存起点恢复进度，未保存的起点重新计算。按 `Ctrl+C` 退出 `tail -f` 可继续保留后台任务。

默认产物目录为 `output/stage158/independent_layer_continuation_v1`。`stage158_windows.csv` 给出逐起点的六层后续指标，回传 `stage158_results_*.txt` 即可复核。换卡续跑时给新目录指定 `STAGE158_ROOT`。后续耗时实验可以复用 `tools/experiment_progress.py` 显示进度。
