# Stage-170 固定冷却期的完整视频对照

Stage-169 的定点干预中，0304 跳过第 530 帧换层后，到观察窗结束均未失跟。0089 暂停 16 帧后在第 1194 帧达到连续三帧 IoU ≥ 0.5，到观察窗结束未再失跟。Stage-170 把暂停规则推广到 28 个开发视频的全部跟踪帧。

## 设计

原生 SGLA、共享门控加原提议、共享门控加成对排序为三组对照。实验组给两个换层策略分别加同一条规则。在第 t 帧实际换层后，第 t+1 到 t+16 帧只执行原生层，第 t+17 帧重新允许换层。被否决的提议无需再次计时。新视频从空的冷却状态开始。

两组冷却策略沿用 Stage-167 冻结的收益、退化、排序模型和门槛。每条轨迹使用自己的上帧预测框和历史。冷却期间记录本来会通过门控的提议与实际否决，所有组仍只执行一次裁剪、七个 Transformer 块和一次预测头。每个策略与它自己的无冷却对照在首个有效否决前须逐帧一致。

完整对照包含 140 条轨迹。运行身份与 Stage-167 完全一致时，按内容哈希复用 84 条对照，新增 56 条冷却轨迹。分配到其他兼容设备时，在同卡重跑全部五组。支持 L20／L40，输出目录绑定实际设备，已提交轨迹可复用。报告的调用数可核对计算量，包含归档时延的结果用于轨迹分析。

## 服务器运行

```bash
mkdir -p output/stage170
nohup bash tools/run_stage170_layer_cooldown.sh > output/stage170/run_stage170.log 2>&1 < /dev/null &
tail -f output/stage170/run_stage170.log
```

总体进度条覆盖缓存复用、门槛复现与完整跟踪，结束后打包 `stage170_results_*.txt`。

## 评价

对两个冷却策略分别报告相对原生和自身无冷却对照的整段 AUC、低 IoU、最长失跟和未恢复事件，同时报告剔除 0176 或 0304 的配对结果。开发门槛要求总体 AUC 优于两个对应对照、低 IoU 和未恢复事件不增加、保留对照已有的恢复，以及原稳定视频无新增失跟。报告实际换层和否决数，用于检查改善是否伴随策略退回原生。通过后冻结模型、门槛和冷却规则，再组织独立视频验证。
