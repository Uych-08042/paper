# Stage-79 确认集冻结与搜索尺度交叉回放

Stage-78 的固定限幅改善了 0304 晚期失跟，但 0204 第 664 帧仍有好候选时改选 q0，之后持续失跟。Stage-79 先冻结后续确认集，再用两个已知开发起点做最后一轮针对当前限幅的短窗诊断。 [Stage-78 结果](STAGE78_RESULTS_REVIEW.md)

## 确认集

使用服务器 VisDrone-SOT train 的完整文件目录清单。排除 Stage-27 的全部 24 个诊断组、Stage-31 的全部 14 个 fit／checking 组、Stage-76 的 12 个开发组及仓库记录中的已用组。其他试验、训练或人工看过结果的组可在冻结前通过 `STAGE79_EXCLUDE_FILE` 补充，文件每行一个源组前缀。分组沿用 `uavNNNNNNN` 前缀代理。

保留所有符合条件的组，每组取字典序第一段完整序列。至少需要 12 组。清单绑定目录清单指纹和排除来源哈希，重跑时仅接受相同清单。冻结读取帧名、帧数和标注文件是否存在，不读标注正文、图像像素或模型结果。Stage-79 GPU 只使用开发视频。确认集是 VisDrone-SOT 内部按源组预留的评价集，原 checkpoint 的预训练数据重叠未核验。

方法定型后才运行确认集，主指标为逐视频等权 success AUC，另报告低 IoU、最长失跟比例和原生稳定视频新增失跟。完整评价需同时报告原生单搜索 SGLA 与同四搜索预算的原尺度选择器。

## 固定短窗

| 视频与起点 | 裁剪尺度 | 起点强制候选 | 后继 |
|---|---|---|---|
| 0204 第 664 帧 | 原始、限幅 | 各执行 q0、q2 | 同尺度下冻结 PPO，至 691 |
| 0304 第 1075 帧 | 原始、限幅 | 两组都执行 q2 | 同尺度下冻结 PPO，至 1103 |

输入来自 Stage-78 首次裁剪变化前的缓存。先审计两组前缀和原动作，首帧重新生成两套四候选，保存每个公开框、PPO logit、概率、动作合法性、裁剪坐标和像素哈希。若固定候选与较早候选产生完全相同的公开框，按源 PPO 的去重约定执行等价序号，并保留原请求序号。

后继只接收自身预测，首帧后恢复各自尺度下的原 PPO。对照四条自然分支与 Stage-78 的实际框、动作和裁剪是否完全复现。允许 L20 或 L40 独立运行，换卡产生的复现差异应在解读时单列。预算为 4 套起点搜索、6 条短分支，共 672 次搜索、4,704 次 block 调用，零训练、零确认集推理。

先看 0204 限幅组 q2 是否仍有好框，再比较固定 q2 和固定 q0 的短续跑。若 q2 恢复稳定、0304 的同动作尺度收益仍在，才考虑设计一个可部署的尺度保护并进入完整开发视频消融。若 q2 已无好框，或选回 q2 后仍持续失跟，当前固定限幅不进入全视频验证。两种结果都结束在这两个锚点上反复调阈值的做法。

## 服务器命令

```bash
cd ~/workspace/paper
bash tools/run_stage79_cross.sh --freeze-only
cat output/stage79/confirmation_v1.json
```

清单默认依赖原始 Stage-27、31、76 的 manifest。若目录不同，用 `STAGE27_ROOT`、`STAGE31_ROOT`、`STAGE76_ROOT`、`VISDRONE_SOT_ROOT` 覆盖。若曾使用其他未归档的源组，先设置 `STAGE79_EXCLUDE_FILE` 再冻结。后台运行需要沿用同一组路径和排除设置。

```bash
nohup bash tools/run_stage79_cross.sh > output/stage79/run_stage79.log 2>&1 < /dev/null &
```

GPU 命令也会先检查并冻结同一清单。默认读取 Stage-76／77／78 的原始运行目录与原始 SGLA 权重，可通过 `STAGE77_ROOT`、`STAGE78_ROOT`、`STAGE79_GPU`、`STAGE79_ROOT` 或 `CHECKPOINT` 覆盖。续跑绑定运行指纹与物理 GPU，换卡新建 Stage-79 目录。完成后用 `cat output/stage79/run_stage79.log` 查看结果包路径。支持 `--pack-only` 校验和导出已完成的报告。
