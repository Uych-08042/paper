# Stage-191 网格好框一次写回的持续收益

Stage-190 在 `0173:503` 和 `0107:161` 的六种搜索输入中发现，CENTER 网格均有 IoU ≥ 0.5 的框，原始响应与 Hann 却都把同一个坏框排在第一。Stage-191 检验在这些状态当帧写回好框后，原生跟踪能否维持。

- `0173:503` 沿用四种写回父框；`0107:161` 沿用两个裁剪。每对共用一次 L9 搜索、模板、模型、父框和 CENTER 输出。第一条分支写回原生 Hann 首选框，第二条写回同一网格中真值 IoU 最高的框。IoU 并列按网格顺序选第一个，沿用 Stage-190 的最佳格点定义。
- 两条分支随后均恢复原生路由和选框，各自反馈预测框 128 帧。真值只用于原生首帧初始化、这一次上界选择和评估。换卡时两条分支同卡重测，报告 Stage-190 锚点是否复现和 Hann 续跑与归档轨迹的误差。
- `0173` 事件历史接入各自真实的第 502 帧写回框。Stage-188 的对照到第 630 帧，新实验续跑到第 631 帧，因此只在已有帧段核验归档输出。`0107` 在第 161 帧比较，沿用同一原生前史。
- 以原有的三帧 IoU < 0.2 判定失跟，三帧 IoU ≥ 0.5 判定恢复。报告首次再次低 IoU、连续好框帧数、末窗失跟、后 128 帧平均 IoU 差和安全挽救。六对来自两个事件，按事件解释。确认集继续封存。

若最佳框写回后仍很快失效，优先检查后续搜索状态及好框供给。若能维持，再检验可部署的候选重排，并在其他源组和稳定窗口上复验。真值选择只衡量一次写回的可达上界。

## 运行

需要服务器上的 Stage-188 缓存、Stage-189 和 Stage-190 输出、VisDrone-SOT 原数据以及原始 SGLA 权重。支持 L20 和 L40。预算为 6 次锚点搜索及最多 1,536 次续跑搜索，同一帧的完全相同写回框复用续跑。

```bash
mkdir -p output/stage191
nohup bash tools/run_stage191_grid_writeback.sh > output/stage191/run.log 2>&1 &
tail -f output/stage191/run.log
```

完成后脚本打印 `stage191_results_*.txt`，优先读其中的 `paired` 和 `branches` 两张表。
