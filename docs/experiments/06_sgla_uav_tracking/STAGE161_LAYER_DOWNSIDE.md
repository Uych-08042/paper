# Stage-161 相同换层预算下的退化预测

Stage-160 校准门槛减少了有害换层，同时拒绝了两次有效恢复。本轮固定 Stage-159 给出的候选块、可见特征及外层源组划分，检验额外预测退化幅度能否改善选点。

## 对照

- 保留原生、Stage-159 直接选层和 Stage-160 校准门槛。只按收益排序时，核对每折前 N 个非原生候选与 Stage-160 的实际换层一致。
- 使用 Stage-159 的 24 维特征，在另一折拟合每层的退化幅度。标签是 `max(0, 原生后32帧平均IoU − 该层后32帧平均IoU)`，六层共用 Stage-159 的岭回归和按源组等权做法。留出侧用 `预测收益 − 预测退化幅度` 排序，退化预测下限为 0，惩罚系数固定为 1。每折分别接受 64／4 个候选，与 Stage-160 逐折匹配。两种排序使用同一批候选，允许拒绝原提议并保留 L9。
- 另用后续真值，在每折预算内选取可带来正收益并保住原生恢复的候选，同时排除新增连续低 IoU。预算允许用少。这一事后参考只量化现有候选和给定预算的收益上界。

匹配排序是批量离线诊断，排序和预算均不使用留出真值。若风险排序在短程续跑中通过，再在拟合组内校准可逐帧执行的决策规则。重点对比相同 68 次换层下的后 32 帧视频均值、最差留一、恢复变化和新增连续低 IoU。复查 0176／163、0226／174，同时核对 0348／540、0080／171。

## 已完成的事后参考

基于核验过的 Stage-159 和 Stage-160 报告，事后参考在不超逐折预算的情况下保留 63 次换层，后 32 帧平均 IoU 为 0.608761。相对 Stage-160 +0.551 个 IoU 点，相对原生 +0.484 点，新增连续恢复 1 次，无丢失恢复或新增连续低 IoU。实际退化模型的留出评分尚待服务端特征。

## 运行

需要完整的 `STAGE159_ROOT` 和 `STAGE160_ROOT`，默认使用此前两阶段的服务端结果目录。只使用缓存，零 GPU 推理。运行日志沿用总体进度条，默认每 15 秒刷新。

```bash
mkdir -p output/stage161
nohup bash tools/run_stage161_layer_downside.sh >> output/stage161/run_stage161.log 2>&1 < /dev/null &
tail -f output/stage161/run_stage161.log
```

结果包位于 `output/stage161/matched_layer_downside_v1/stage161_results_*.txt`。`stage161_paired.csv` 给出同预算配对差，`stage161_folds.csv` 给出各折配额和实际换点数。
