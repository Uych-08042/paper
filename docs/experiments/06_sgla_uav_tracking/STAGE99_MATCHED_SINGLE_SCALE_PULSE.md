# Stage-99 共同状态下的一次尺寸调整与持续更新

## 问题与依据

Stage-97 的可信历史尺寸规则在25个恢复窗口中新增一次恢复、丢失两次已有恢复，总数21→20。Stage-98发现，两次损失的首次裁剪和输出分叉都发生在窗口内首次低IoU写入之前。当帧新框IoU还略高，损伤在更后的跟踪中出现。单靠错误写入计数，尚不能解释恢复损失。

本轮检验：一次早期搜索尺寸变化及其自身反馈，是否足以改变后续恢复；持续启用可信尺寸规则是否还会带来不同的结果。修改对象仍是SGLA的搜索区域构造，SGLA网络、首帧模板、四候选PPO和外观决策均冻结。

## 三组干预

| 组 | 共同起点帧 | 后续帧 |
|---|---|---|
| `control` | 原历史尺寸规则 | 原历史尺寸规则 |
| `once` | 一次启用Stage-97可信历史尺寸 | 恢复原历史尺寸规则，沿自身输出继续 |
| `continuous` | 启用Stage-97可信历史尺寸 | 持续按自身可信历史更新 |

原规则中q0／q2使用最新尺寸，q1／q3使用最近五个预测框宽高的对数中位数。可信规则只替换q1／q3尺寸，引用最近十二帧内最多五条有资格记录，至少两条，数量不足时回退原规则。中心均由本分支自己的历史预测生成。

`once`恢复的是尺寸计算规则。其第一帧产生的实际输出仍进入下一帧的预测历史和外观记忆，后续搜索继续沿自身状态推进。它没有跳回control轨迹。三组每帧都执行四次搜索；写入规则、选框规则和历史长度一致。

## 评价与解释

主要比较固定为`once−control`、`continuous−once`、`continuous−control`，分别报告原先未保留的4个事件和已保留的21个事件。恢复定义沿用来源：在原PPO恢复帧起至其后十五帧内开始连续三帧IoU≥0.5；窗口尾部包含完成判定所需的两帧。

同时报告尾段平均和末帧IoU、有好候选帧比例、低IoU帧比例、窗口末未恢复状态，以及规则激活、写入、父框变化和取整裁剪变化次数。统计先在同一视频内平均，再按视频等权汇总。尾段长度较Stage-97缩短，不能直接把尾段均值与Stage-97整窗均值相减。两组复用来源时，对齐恢复时刻须与原记录相同。

若`once`已丢失某次恢复，可说明一次尺寸变化及其后续普通状态反馈在该起点下足以造成损失；仍不能断言具体哪条记忆是唯一原因。若`once`保留而`continuous`丢失，则表明首次干预之后继续使用该规则及其引发的状态演变有额外影响。`continuous−once`包含后续状态和外观记忆分化，不能单独称为尺寸写入模块的纯效应。新增恢复也按同样方式解释。

产物为`analysis/stage99_decision.json`、`stage99_windows.csv`、`stage99_video_summary.csv`、`stage99_summary.csv`和75个分支NPZ。结果包包含decision及三表。逐帧查询、引用、父框、输出和预算留在NPZ中。状态为`COMPLETE_MATCHED_SINGLE_SCALE_PULSE_PILOT`，表示完成诊断，没有方法采用门槛或论文成功结论。

## 预算、硬件与续跑

每分支帧四次搜索，每次七个骨干块。逻辑搜索34,548次；训练更新、新完整轨迹、确认集推理均为0。

与Stage-97软件、权重、GPU型号和UUID身份一致时，复用control和continuous尾段，逐帧重建审核，仅once新增11,516次搜索、80,612个块调用。硬件变为另一L20或L40时，三组在当前卡全部重跑，新增34,548次搜索、241,836个块调用。记录与来源两尾段的最大框误差；换卡差异较大时，不能沿用旧卡的恢复增损解读。

计划绑定来源、代码和当前硬件。中断后使用同一身份续跑，已有分支校验后复用；中途换卡须指定新的输出目录。完成后`--check-results`仅核对产物，无新增网络推理。后台由nohup维持进程，计算节点或作业被平台回收仍会结束。

## 服务器运行

先同步本轮新代码，进入仓库根目录，激活`sglatrack-test`环境：

```bash
bash tools/run_stage99_scale_pulse.sh
```

默认输出目录为`output/stage99/matched_single_scale_pulse_v1`，使用原V1 checkpoint和逻辑GPU0。可通过`STAGE76_ROOT`、`STAGE89_ROOT`、`STAGE93_ROOT`、`STAGE97_ROOT`、`STAGE98_ROOT`、`CHECKPOINT`、`STAGE99_GPU`指定输入，通过`STAGE99_ROOT`指定新输出根目录。

断开连接后继续运行：

```bash
mkdir -p output/stage99
nohup bash tools/run_stage99_scale_pulse.sh > output/stage99/run_stage99.log 2>&1 < /dev/null &
tail -f output/stage99/run_stage99.log
```

完成后回传脚本打印的`stage99_results_*.txt`。需要重新打包时执行：

```bash
bash tools/run_stage99_scale_pulse.sh --pack-only
```
