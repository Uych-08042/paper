# Stage-86 同输出搜索中心干预

Stage-85 的运动候选在匹配历史上的供给增益很小，完整闭环 AUC 相对固定布局下降 4.54 点。Stage-83 全局保持旧中心也未通过。本轮测量一次搜索中心写入对后续轨迹的影响，作为设计局部更新机制的依据。

## 配对续跑

从 Stage-76 固定四候选 PPO 的 12 个开发视频、两个种子 2171／2172 取冻结历史。每条历史分三个时间段。在每段尾部留出 16 帧续跑空间，在可用起点中取预测框中心位移最大的帧，再在与它相距至少 16 帧的起点中取位移最小的帧。同分取最早帧。位移除以前一预测框面积的平方根。每个高／低位移组各 72 个窗口。选点仅使用预测轨迹，窗口不重叠的约束在同一历史内生效。

两臂共用第 `t` 帧已经发布的框及此前的预测历史。首次搜索在 `t+1`，`fixed` 用原布局，`midpoint` 将 q0、q1 的搜索中心从 `t` 帧中心移到 `t` 与 `t−1` 的中点。四个搜索框的尺寸与 q2、q3 保持一致，PPO 特征仍以原始发布历史为参考。两臂从 `t+2` 起用各自预测更新历史，按同一固定布局和冻结 PPO 续跑。两臂均用原生 V1 权重、首帧模板、解码与四次搜索预算。

共 144 对窗口、288 条短续跑、18,432 次搜索和 129,024 次骨干块调用。一次干预后的轨迹差包含后续闭环传播。16 帧窗口内持续低 IoU 使用原三帧规则，窗口末仍在失效只代表观察期内未恢复。

## 结果判读

- 主读数是高预测位移组内 `midpoint − fixed` 的续跑平均 IoU 和低 IoU 占比。另报低位移对照、首帧最佳候选及实际输出、窗口终点与失效指标。配对区间先在视频内合并窗口和种子，再按视频重采样。
- 首帧最佳候选与实际输出的差异用于检查候选供给和选择行为。随后区分在共同起点 IoU ≥ 0.5 时哪一臂独有失效，以及起点 IoU < 0.2 时哪一臂独有连续三帧达到 0.5。报告同时保留真实目标在起点处的位移，供离线判断是否牺牲真实运动。高预测位移可能来自目标移动、相机移动或误跳。
- 当轮两臂在同一张卡上运行。L20 和 L40 都可启动。若与 Stage-76 同型号，要求固定臂在窗口内逐帧复现来源框、动作和裁剪像素。跨型号时报告与来源的偏差，同卡两臂仍独立复算。
- 使用的是已消耗开发数据。确认名单只做源组排除。结果用于判断下一步是否值得设计条件化写入规则，属于机制诊断。

## 服务器运行

在仓库根目录激活 `sglatrack-test` 后执行。

```bash
bash tools/run_stage86_search_center.sh
```

脚本默认复用 Stage-76 的 `matched_four_candidate_horizon_v1` 根目录和原始 V1 checkpoint。路径或 GPU 逻辑编号可通过 `STAGE76_ROOT`、`CHECKPOINT`、`STAGE86_GPU` 指定。相同 GPU UUID、运行配置和计划可续跑。更换卡后通过 `STAGE86_ROOT` 指定一个新目录。结果 TXT 会写入 `docs/experiments/06_sgla_uav_tracking/results/`。已完成时可传入 `--pack-only`，校验报告和分支缓存再打包。
