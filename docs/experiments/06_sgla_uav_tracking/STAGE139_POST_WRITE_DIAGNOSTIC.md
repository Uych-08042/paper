# Stage-139 写回后的裁剪和响应诊断

Stage-138 的 0237／242 跨块框在起点 IoU 为 0.511，之后 32 帧全为 0。0089／1159 更早恢复，随后再次失跟。本轮定位在各自已发生的轨迹中，目标是否仍在搜索裁剪里，以及 SGLA 在这些裁剪里能否解出好框。 [Stage-138 结果](STAGE138_RESULTS_REVIEW.md)

## 固定窗口

沿用 Stage-138 的六个起点和五条分支。基于已缓存的父框与帧尺寸，复核后续 32 帧的目标中心覆盖、真值框与有效裁剪的重合比例、输入真值短边和低 IoU，合计 960 个分支帧。随后用原生 SGLA 重放每条分支的第 1–8 个后继状态。0089 的跨块真值最优分支首次出现连续三帧 IoU ≥ 0.50 后，找第一次连续三帧 IoU < 0.20 的起点，将其前一帧、当帧及后一帧并入同视频五组回放。重叠帧只记一次回放。

每次推理用档案中的预测父框和原有首帧模板。不同分支在同一帧父框完全一致时共用推理。回放预算为 240–255 个分支帧，物理搜索不超过 255 次。全程按缓存状态定位，框与响应的度量在前向后读取真值。使用同一张 L20 或 L40。同归档运行环境时校验输出框和所选层，换卡时仍校验裁剪与像素哈希并报告坐标误差。

## 判读

| 观察结果 | 操作定义 |
| --- | --- |
| 输出好框 | Hann 第一峰的框 IoU ≥ 0.50 |
| 网格有好框但没选中 | 第一峰框 IoU < 0.50，至少一个格点框 IoU ≥ 0.50 |
| 裁剪覆盖不足且网格无好框 | 全网格无好框，且目标中心在有效裁剪外或目标覆盖 < 90% |
| 裁剪充分覆盖但网格无好框 | 全网格无好框，目标中心在有效裁剪内且覆盖 ≥ 90% |

逐帧另列原始和 Hann 两套前五峰并集中的最佳 IoU。重点看 0237 从第一个后继帧起属于哪一类，以及 0089 恢复到复发之间何时换类。分类用于定位瓶颈。实际因果收益仍需修改输入或响应后对照验证。

## 运行

```bash
bash tools/run_stage139_post_write_diagnostic.sh
```

默认输出 `output/stage139/post_write_diagnostic_v1`，可用 `STAGE139_GPU` 指定逻辑设备。脚本校验结果并生成 `stage139_results_*.txt`，包含分组类别计数、逐帧响应、全 32 帧覆盖汇总与调用计数。
