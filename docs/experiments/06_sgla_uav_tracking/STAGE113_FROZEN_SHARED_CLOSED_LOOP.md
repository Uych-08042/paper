# Stage-113：冻结生成器与共享评分器的完整自身轨迹验证

固定日期：2026-11-15。状态：实现和本机测试完成，服务器正式实验待运行。

Stage-112在固定来源历史上改善了新候选的选择适配，但generated4/shared对q0仅增加0.000062 IoU，且两个训练种子一正一负。下一步需要回答：**这些模型沿自己的预测历史运行整段视频后，算法生成的搜索输入能否比固定布局和原生SGLA获得稳定收益？** 本轮停止增加候选数或重新训练，用完整轨迹直接检验这个问题。

## 1. 冻结来源与比较

绑定Stage-112 decision指纹`4622ef840a90ccfc658ff91b86652ac460a1371a3da9579e37b08425d8f3803f`，沿用其四个外层划分、四个生成包和fixed4/generated4各八个共享评分器，共复用20份模型文件。评分器为每候选64→32 Tanh→1 Sigmoid，训练种子2312/2313；标准化与全部参数保持封存版本。

28个开发源组，每组一段视频，包括历史12组和扩展16组。原来40个来源视频/种子单元只用于定位帧表及前序产物；本轮按视频去重，模型由该源组所属外层留出fold决定。生成器拟合/校准和评分器训练均不包含该fold的七个评价源组。整个来源流程已经用于开发，这不是独立确认；28个确认源组继续封存。

| 臂 | 搜索输入 | 选择规则 | 每视频轨迹数 |
|---|---|---|---:|
| native | 自己上一帧输出框 | 原生SGLA单搜索输出 | 1 |
| fixed_hann | 固定四布局 | 最大Hann峰值 | 1 |
| generated_hann | 算法生成四候选 | 最大Hann峰值 | 1 |
| fixed_shared | 固定四布局 | 对应fixed4共享评分器 | 2 |
| generated_shared | 算法生成四候选 | 对应generated4共享评分器 | 2 |

合计196条完整轨迹。四搜索臂预算相同，原生单搜索另列成本。shared臂的两个训练种子都保留，不按本轮表现挑选模型。主要比较`generated_shared_minus_fixed_shared`，同时必须对照native和generated_hann；fixed_shared−fixed_hann、generated_hann−fixed_hann、fixed_shared−native提供生成和选择环节的解释。

fixed与generated各使用自己的匹配训练评分器，因此主要比较检验“搜索生成＋匹配评分”的整体效果，不是只替换生成器而固定同一评分函数的纯因子效应。Hann两臂提供同一无训练选择规则下的输入对照。旧PPO不在本轮重新训练或作为选择器；PPO后继目标的新增价值需要后续单独匹配比较。

## 2. 自身历史、生成和冷启动

所有臂只用首帧GT初始化，首帧模板保持原生SGLA版本。随后每帧将**当前臂实际选中的框**写入自己的历史并提交给tracker.state；不使用旧轨迹父框、GT重置、oracle选框或额外恢复支线。

固定四布局沿用Stage-60：最新中心/最新尺寸、最新中心/最近最多五框的对数中位尺寸、前一个中心/最新尺寸、前一个中心/中位尺寸。候选父框用于确定搜索裁剪，搜索后仍由SGLA解码得到实际输出候选框。

生成臂沿用Stage-112的冻结算法：32维过去状态输入→岭回归中心/对数尺寸均值与条件误差尺度→经验校准范围内32个反向配对场景→保留q0、按软覆盖增益贪心分配其余三个搜索区域。q0始终为本臂最新输出框。四是本轮固定预算，不是候选数最优结论。

生成器输入只来自本条轨迹最近最多五个已选框、上一帧自己的4×24响应/几何特征、上一帧自己的选择和可信写入资格位。资格位按Stage-103的同一公开响应/几何规则重新计算，并在下一帧作为预测特征；**没有引入外观记忆重排或在线模板更新**。文件中保留`memory_write`字段只是为了与原输入定义一致，不能解释为本轮执行了外观记忆模块。

首个跟踪帧没有上一帧响应，生成臂统一使用固定布局，此时四父框相同。第二个跟踪帧开始使用冻结生成器，历史不足五框时沿用`online_input`的零填充增量与历史长度特征。原生成器训练采样从第5个跟踪帧开始，因此早期短历史属于额外曝光差异，必须在结果解释中保留；不根据本轮结果事后改变启动帧。

每帧先确定父框，再观测和评分；当前选择不会反过来改写当前生成输入。每视频的七条轨迹均保存NPZ/收据后，才读取后续GT用于评价。加载来源entry可携带标签，但rollout/forecast/choose不访问后续标签。测试已验证替换后续GT不改变动作和输出。

## 3. 调用、缓存与运行身份

每条完整轨迹仅初始化模板一次。帧内完全相同浮点父框共享一次SGLA搜索，仍保留四个逻辑槽位；相同取整裁剪但不同浮点父框不合并，因为映射可能不同。`executed`标记真正执行的父框，物理head/block调用据此加总，不把复制观测重复计费。

由既有帧表推算，28视频合计29,047个跟踪帧，七遍合计203,329帧次；逻辑搜索上限726,175，实际唯一搜索可因重复父框减少。每次搜索执行7个SGLA块；正式数量由scope审计。新完整轨迹共196次模板初始化，训练更新和新增模型为零。中断但未提交的轨迹从首帧重跑，重试计算不能当免费；报告计数为唯一已提交产物。

保存候选父框/输出、4×24特征、原始响应/尺寸/偏移图、层与12维块调用、选择分数、生成输入/均值/尺度/范围、可信资格和计时。审计逐帧重建父框、特征、选框、历史链及解码，NPZ和receipt分别绑定SHA。已完成轨迹复用并审计，不重复推理；未完成轨迹不接入别人的历史续跑。

首次运行支持L20或L40，绑定实际GPU型号/UUID、权重、配置与软件。五臂全部在当前设备新跑，不拿旧L20/L40成绩代替本轮控制。同根续跑必须同一运行身份，GPU/UUID改变时新设`STAGE113_ROOT`。换卡不必改实验代码或哈希。

每视频新native轨迹与Stage-103原native框对照：运行身份完全相同时要求误差0；首次换卡只放行GPU型号/UUID差异并报告框漂移，其他软件/权重变化仍拒绝。

`pipeline_ms`在图像读取后、提议前开始，包含提议/特征/SGLA搜索/评分/状态提交并同步GPU，排除图像读取、模板初始化和产物写盘，统计排除前十帧。原生臂也带审计特征计算，因此这是仪器化管线耗时，不能用它宣传部署速度或FPS。

## 4. 指标和预定判断

先在同视频内平均两个评分器训练种子，再按视频等权汇总全部28组，并单列历史12/扩展16组。AUC沿用仓库21个严格IoU阈值的success AUC，范围0～100；selected_iou等为0～1，不能混用单位。

视频bootstrap固定seed23130、20,000次。所有配对指标报告均差、中位、名义95%区间、胜平负、最差视频和最差留一；三个必要AUC对比的家族区间采用Bonferroni双侧分位数0.0083333/0.9916667。区间条件于已消耗开发队列及冻结模型，不涵盖重新训练/换样本的不确定性。

保护指标包括低IoU比例、最长失跟比例、原生可靠帧AUC、原稳定视频新增失败，以及每个参考恢复事件是否仍被匹配。失败沿用连续3帧IoU<0.2触发、连续3帧IoU≥0.5恢复；参考恢复后15帧窗口内找到连续3帧好框算匹配。generated_shared除对native，还逐种子对fixed_shared做稳定/恢复检查。汇总保护标记取任一种子触发，恢复丢失计数是两个种子的事件总数，不能与单轨迹臂不加说明地比较总数。

只有以下条件全部成立才标记`PROMISING_FROZEN_GENERATED_SHARED_CLOSED_LOOP_DEVELOPMENT`：

- 对fixed_shared、native和generated_hann的宏AUC均≥+0.5点，三个家族区间下界均>0，两个评分器种子在三个对比中各自均为正。
- 对native和fixed_shared，宏低IoU与最长失跟均不增加；原生可靠帧AUC配对名义区间下界≥−1点。无可靠帧支持时该项不通过。
- 任一种子均未破坏native稳定视频、同种子fixed_shared稳定视频，也未丢失两类参考恢复。
- 至少四视频同时出现生成裁剪改变和实际非q0输出，不以换了索引冒充实际干预。

否则为`REVIEW_FROZEN_GENERATED_SHARED_CLOSED_LOOP_DEVELOPMENT`，保留全部成绩与未通过项。PROMISING仍只是进一步开发依据，不是论文确认成功。结果后优先核对两种子、历史/扩展、供给与漏选，以及首次严重分叉和恢复事件；不只按平均AUC挑优臂，也不立即后验扩K/选seed。

```bash
cd ~/workspace/paper
mkdir -p output/stage113
nohup bash tools/run_stage113_closed_loop.sh > output/stage113/run.log 2>&1 < /dev/null &
echo $!
```

```bash
tail -f output/stage113/run.log
```
