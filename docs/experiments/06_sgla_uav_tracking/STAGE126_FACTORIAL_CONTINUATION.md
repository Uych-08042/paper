# Stage-126 当帧选框与下一帧备用搜索交叉对照

**正式 GPU 实验已完成。** Stage-125 的 0237 第 414 帧显示，当帧选到好框后仍可能失跟。第 525 帧显示，同一个框的后继也会受下一帧备用请求影响。Stage-126 在全部 346 个完整窗口中交叉控制这两个因素，检验各自的 31 帧影响。 [Stage-126 结果](STAGE126_RESULTS_REVIEW.md) · [Stage-125 结果](STAGE125_RESULTS_REVIEW.md)

## 固定设计

沿用 17 个已使用的开发视频、Stage-121 的实际触发前史和四候选。每个起点的提交动作取原评分和两类重训评分在两个固定种子下实际选过的槽位。动作确定后，分别计算下一帧禁止备用搜索和允许备用搜索的轨迹。允许组只放开分数差条件，仍要求提交槽位非 q0、中心间距达标、替换保持原有裁剪预算且备用裁剪与现有裁剪不重复。若允许组实际未换入备用裁剪，两路共用相同的轨迹。请求或禁止只施加于起点的下一帧，其后按原有 Stage-121 规则及各自历史推进。所有后续帧均用原 Stage-121 评分。

| 对照 | 计算方式 |
|---|---|
| 当帧提交效应 | 两组均禁止下一帧备用搜索，比较重训评分所选框与原评分所选框 |
| 备用搜索效应 | 对同一个已提交槽位，比较下一帧允许与禁止 |
| 两因素交互 | 比较换框前后，允许备用搜索的效应差 |
| 自然运行总差 | 比较 Stage-125 原来各自的自然请求与选框；总差可拆成禁止备用时的提交效应和两路自然请求增量之差 |

主指标为起点之后 31 帧的平均 IoU，同时报告低 IoU 帧数、下一帧候选最高 IoU 和实际所选 IoU，以及连续三帧保持 IoU ≥0.5 的起始偏移。起点的候选好框数量用于描述可用性。配对差按种子、起点与视频层级平均，视频等权；给出全体、改选动作、两动作均能实际换入备用裁剪的结果。标签用于评价。结果限于单次开发干预。无训练、完整轨迹或确认集推理。

相同 GPU 运行身份下复用 Stage-121/125 原续程，逐条核对历史、裁剪、原评分和 Stage-125 自然结果。服务器回传可重建 824 个起点动作、1,648 个逻辑对照格；至多 421 条短续程需要补算，最多 52,204 次新 SGLA 搜索，实际调用取决于裁剪能否替换。切换 L20／L40 或 GPU UUID 时，在当前卡重观测起点并重跑各对照续程，搜索上限 301,712 次。换卡新开输出目录，软件、模型及配置需与原绑定吻合。

## 服务器后台运行

将代码同步到保存了过往封存产物的服务器仓库。在实验环境的仓库根目录执行以下命令。

```bash
mkdir -p output/stage126
nohup bash tools/run_stage126_factorial_continuation.sh \
  >> output/stage126/run.log 2>&1 < /dev/null &
```

使用 `STAGE126_GPU` 选择 CUDA 逻辑 GPU，`STAGE125_ROOT` 指定 Stage-125 的封存目录，`STAGE126_ROOT` 另设输出位置。完成后日志打印 `stage126_results_*.txt` 路径。已完成的运行可以用同一脚本的 `--pack-only` 重新校验并打包。
