# Stage-142 等候选数量的全网格提取对照

0089 第 1165 帧的全网格最佳框 IoU 为 0.748，原局部峰并集的最佳框为 0.482。Stage-142 检查允许非局部峰格点入选，能否在相同候选数量下补回更多好框。 [Stage-139 结果](STAGE139_RESULTS_REVIEW.md)

## 固定比较

- 用 Stage-121 的 28 条原生轨迹、29,047 个跟踪帧为主开发样本，另报告 Stage-133 的 19 个失跟起点。Stage-139 的 240 个分支帧单列，包含 0089 复发附近。
- 两组共用预先保存的父框、裁剪、原始响应、Hann 权重、尺寸和偏移响应。原生框固定进入两组。其余候选按原始与 Hann 两图中较靠前的名次合并排序，名次并列依次按 Hann 名次和格点编号排。同一组内对 IoU >0.50 的重复框做抑制。局部峰组只从两图的局部极大值中提取，稠密组允许全部正响应格点。
- 两组按各自顺序最多取 8 框，再按每帧两组中较短者截成同样数量。另保留 Stage-133 的原／Hann 各前五峰并集作为历史参照，报告其实际数量。此参照不参与等预算主比较。

## 判读

好框定义为 IoU ≥0.50。重点看原生低 IoU 且全网格确有好框的帧，报告稠密组新增和丢失的好框覆盖。按视频计算覆盖率差和配对区间，同时给出帧数和支持视频数。直接判断候选集合能覆盖真值使用离线标注。

0089 第 1165–1166 帧报告候选格点、集合最佳 IoU 与是否保留全网格最佳格点。若能获得稳定的同预算召回增益，再使用冻结的候选集合验证定位质量评分。本轮仅 CPU 读取缓存，新增搜索、训练和状态写回为零。

## 运行

```bash
bash tools/run_stage142_dense_candidate_recall.sh
```

默认输出 `output/stage142/dense_candidate_recall_v1`。结果包包含分组、逐视频、失跟起点和分支重放表。
