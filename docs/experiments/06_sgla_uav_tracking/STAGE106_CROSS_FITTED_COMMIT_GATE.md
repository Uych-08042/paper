# Stage-106：从匹配后继收益学习提交条件

准备日期：2026-11-14。正式服务器结果尚未运行。

## 研究问题

Stage-105已证明，同一个当前观察、同一个发布框，只改变普通历史及外观写入，就能让部分后继窗口明显改善，也能造成严重损伤。例如0304／2172／pairwise第556帧，keep后31帧均值0.7984，改用pair提交后为0；而同视频1083起点，pair提交又使后继均值从0.1250改善至0.7252。因此下一步需要辨别何时应提交替代状态。

本轮问：**只用当前候选证据与自身过去，能否在留出的源视频组上预测“一次共同提交pair”相对keep的后继收益？** 固定SGLA、PPO、四候选生成、外观核验及记忆资格；新增小型CPU岭回归门控。先测可学习性，再决定是否值得执行重复门控的完整闭环。

这是对SGLA状态提交机制的探索。当前发布框仍由原四候选核验输出b4确定。门控判断的是下一步普通历史和外观提交是否采用同状态pair给出的b2；被选中的写入仍须满足pair自身资格，不强迫写入。普通历史同时决定后继裁剪、PPO时序输入及外观使用条件，不能称为纯中心作用。

## 两种匹配监督

每个锚点只产生一条样本，不按角色复制。两种门控使用相同合法样本、49维输入、权重、正则和决策阈值。

| 门控 | 目标值 | 用途 |
|---|---|---|
| future | `mean_IoU(t+1:last, both_pair) - mean_IoU(t+1:last, keep)` | 预测一次状态提交的真实后继效果 |
| myopic | `IoU(b2, GT_t) - IoU(b4, GT_t)` | 当前提交框质量监督的匹配对照 |

Stage-105四组在t帧发布的都是b4。因此myopic是**提交框质量代理**，不是四组当帧发布输出的奖励差。没有有效后继或任一目标缺失的锚点保留在清单中，但两种拟合共同排除；不可把缺失后继当成0。

门控候选处理共同限定为keep和both_pair。不再比较新几何／记忆子门控。只有提交确实改变几何框、记忆资格或写入描述子，且必要输入有限时才可触发；无变化、无支持模型或必要证据无效时保留keep。未选中的无效描述子不额外一律阻止门控。

## 线上可得输入

`online_features`的显式参数只有当前观察、当前描述子、首帧anchor、自身过去几何和已接纳记忆、当前帧号、核验模式、两项当前决定与固定设计。函数不接收GT、数据条目、角色、源视频编号、种子、未来框或标签。

| 信息 | 维数 | 定义 |
|---|---:|---|
| 几何 | 16 | b2−b4中心位移及log宽高差；两框相对上一自身框的位移；过去速度；相对匀速预测的偏差；相对过去中位尺寸的log宽高差 |
| 响应 | 6 | b4、b2的raw／Hann峰值及差值 |
| 外观 | 13 | 两框相对anchor及可用历史参照的分数与差值；逐参照差的最小／最大／标准差／支持比例；参照数与两个使用历史标志 |
| 写入 | 2 | 两项原有写入资格 |
| PPO | 7 | 两框的原PPO概率及差值；是否为PPO动作；概率熵及固定critic值 |
| 候选分布与模式 | 3 | 四候选中心离散度、log尺寸离散度、pairwise模式标志 |
| 运动方向 | 2 | 两框相对上一自身框的位移与过去速度的余弦 |
| 合计 | 49 | 严格固定的标量顺序见代码`FEATURES` |

几何中心量以最近预测框的面积平方根归一化。历史参照使用原规则的间隔、窗口与数量上限，只允许frame<t；没有有限参照时使用anchor分数并保留参照数量／使用历史标志。过去速度为最后两项自身中心差，只有初始状态时为0。无未来数据插值、GT归一化、序列编号编码或角色输入。

## 拟合与留出

按`uavXXXXXXX`源组逐一留出，同一源组的全部片段、种子、来源模式和角色都排除。每种目标最多28个模型，共56个CPU门控文件，不是56次SGLA训练。

训练权重依次对源组、组内种子、种子内来源模式、上下文内有效锚点等分。先用该次训练组的加权均值／标准差归一化，再解固定岭回归：

```text
z = (x - fit_mean) / fit_std
beta = (Z' W Z + 1.0 I)^(-1) Z' W (y - fit_mean_y)
predicted_gain = fit_mean_y + z beta
commit_both_pair = eligible AND predicted_gain > 0
```

权重总和为1；标准差小于1e-8的列设为1；截距不正则。无合法训练支持则返回keep。没有超参数搜索或验证组阈值调节。每个JSON绑定特征定义、设计、训练源组、训练条数、归一化、系数、训练输入指纹及自身指纹；拟合输入指纹不含被留出组的任何值。续跑复用与相同训练输入匹配的封存模型，不要求不同CPU再次求解得到逐位相同浮点结果。

## 评价

### 匹配后继效用

在每个留出组的既有锚点，按预测决定选择已有keep或both_pair分支的后继效用。这是一次提交干预的样本外估计：首步之后仍运行原核验器，不是每一步继续执行新门控。

六个对照：

1. keep：零干预效用。
2. always_pair：所有有资格且确实有变化的起点都共同提交pair。
3. myopic：当前提交框质量监督的门控。
4. future：后继监督的门控。
5. rate_expected：在同一序列／种子／来源模式的合法锚点内，按future的实际提交比例p进行均匀随机选择的解析期望`p*measured_delta`。它不读取标签确定p，但需要完整上下文的决定数，只是离线率对照，不能作为部署策略。
6. future_oracle：在合法起点按真实后继正收益选择，只是离线上界。

报告提交率、相对keep的后继均值IoU效用、有害提交比例、遗漏正效用、相对可执行oracle的遗憾。无资格起点所有处理均keep。缺失后继不进入效用均值。对比future与keep／always_pair／myopic／rate_expected，给视频组等权差、胜平负、中位、最差组与最小留一均差；不对重叠窗口制造独立样本置信区间。

汇总先平均同组／种子／来源模式的锚点，再平均模式、种子、源组；总体与历史12组／追加16组、matched／pairwise分别列示。追加16组也已经消耗，不能称独立确认。

### 原轨迹曝光

按80条原始自身轨迹顺序重建过去框和已接纳外观。每一步都由原规则更新记忆和普通历史；新门控的决定只记录，不回写历史。使用相应源组留出的模型。

报告各头合法率、提交率、训练特征逐列min/max范围外比例、最大绝对标准化值的均值及p95。范围外比例只作描述，**不额外作为线上回退阈值**。p95是各来源单位的p95再按既定层次宏平均，不是所有帧混池p95。当前提交框IoU差仅在两头预测完后附加在NPZ的`offline_current_commit_delta`，不影响输入、决定或记忆。

这部分没有新完整AUC、恢复率或稳定性通过结论。即使门控在这些窗口有收益，也仍需冻结后执行完整自身轨迹验证；反之本轮失败也只限制该固定小门控和输入，不证明线上条件不可能学到。
