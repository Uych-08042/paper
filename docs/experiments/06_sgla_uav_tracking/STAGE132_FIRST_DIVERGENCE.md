# Stage-132 搜索裁剪与轨迹首次分叉审计

Stage-131 全视频结果显示，缩边比原备用搜索低 2.5991 AUC 点。单槽放大比仅缩边高 0.1497 点，区间跨零，且丢失两次匹配恢复。本轮用完整轨迹缓存定位差异从哪一帧开始，以及当时两边的历史和裁剪前输入是否仍然一致。 [Stage-131 结果复核](STAGE131_RESULTS_REVIEW.md)

## 对照与读表

复用 28 段开发视频、种子 2312 和 2313。每段视频每个种子作两次配对，共 112 对。第一对是 Stage-121 原备用搜索与 Stage-131 仅缩边，第二对是仅缩边与第一位置单槽放大。两轮源轨迹来自同一 L40 运行身份。审计只读 CPU 缓存和标注，新增图像读取、搜索、训练和完整轨迹均为零。

逐帧检查首次父框变化、取整后的裁剪变化、选中槽位变化、输出框变化，以及下一帧备用请求和实际预测输入的变化。原始候选框坐标用于比较轨迹状态，IoU 和 AUC 沿用 Stage-131 的 SGLA 评价口径。当前帧输出相同且下一帧请求不同，仍然记录为反馈分叉。两边均请求但备用 q0 框不同，也会标记为下一帧待用输入差异。备用请求最终是否采用，由下一帧缓存的采用标记确认。

`matched_before_search` 要求最近最多五个已选框、历史预测器输入、当前备用请求及其采用标记、策略调整前的父框都相同。放大对照还要求两侧的缩边后、放大前布局相同。两边前史已经不同的行可用于追踪后果。匹配行才能判读当帧的搜索差异。

- `good_candidate_lost` 表示对照至少有一个 IoU ≥ 0.5 的候选，处理后四个候选都低于 0.5。
- `good_candidate_missed` 表示处理后仍有 IoU ≥ 0.5 的候选，但处理组输出低于 0.5，对照组输出达到门槛。若裁剪、父框、候选框及特征均相同的保留槽位，其最高分候选发生变化，可检查共享评分对候选集合变化的敏感性。
- `same_box_request_changed` 表示两组当前输出框完全一致，但下一帧备用请求不同。之后是否出现失跟或恢复差异，需连同整条轨迹检查。

固定重点包括缩边损失较大的 0070、0076、0174，放大后丢失匹配恢复的 0076／2312／1485 与 0085／2313／1478，以及放大收益集中的 0176。汇总保留所有 112 对。开发集中的分叉证据用于设计后续对照，不能单独证明修正策略在新源视频上有效。

## 运行与产物

在已有 Stage-76、89、93、121、131 产物的 Linux 仓库根目录运行。

```bash
bash tools/run_stage132_first_divergence.sh
```

默认输出目录为 `output/stage132/first_search_divergence_v1`，可用 `STAGE132_ROOT` 指定其它独立目录。运行脚本会打印结果包 `stage132_results_*.txt` 的路径。结果包含来源指纹与校验信息、配对汇总、每条轨迹首次事件、逐事件候选与覆盖数据、恢复匹配记录。程序会核对逐轨迹 AUC 和 Stage-131 的缩边对放大恢复清单，再发布结果。
