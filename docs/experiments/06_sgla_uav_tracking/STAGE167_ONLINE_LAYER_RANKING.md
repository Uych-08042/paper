# Stage-167 验证成对选层的在线完整轨迹

Stage-166 的同帧成对排序通过了固定起点的离线检查。后 32 帧平均 IoU 比四帧对照高 0.014 个点，剔除 0176 后高 0.022 个点。Stage-167 在相同的 28 个开发视频和源组划分上验证连续运行。

## 三组对照

| 方案 | 每帧选层 |
| --- | --- |
| 原生 SGLA | 原生选择器 |
| 共享门控加原提议 | 门控通过时用 Stage-159 的收益模型提议层 |
| 共享门控加成对排序 | 门控通过时用 Stage-166 的排序器在非原生层中选一层 |

每条轨迹用同一个首帧模板初始化，后续搜索由自己的上帧预测框确定。三组共用原生裁剪、L1–L6、一个 L7–L12 候选块、CENTER 头、Hann 窗和框解码。改动只发生在选择器挑选候选块之前。逐帧核对一次裁剪、一次选择器、一次预测头和七个 Transformer 块。同状态下核对两组门控及原提议一致。

## 在线门控

门控分数使用 Stage-159 给原提议层预测的收益减去 Stage-162 给该层预测的退化。收益模型使用最多 4 帧历史，退化模型使用最多 16 帧历史和趋势特征。历史长度未达到 4 帧时沿用原生层。门控通过后，成对排序组才用 Stage-166 的排序器确定执行层。两组各自推进轨迹后，实际触发次数可以不同。

每个外层折只在其训练源组内做逐源组内层留出。使用内层预测挑选一个门槛，使两组平均收益中的较小值最大，并要求两个方案在校准窗口均无新增持续低 IoU 或丢失原生恢复。零次换层是允许的结果。门槛在外层留出视频开跑前固定。完整视频上的开关逐帧判断，使用当帧 L6 和此前自身轨迹。

## 服务器运行

脚本使用已经完成的 Stage-159、165、166 缓存和 Stage-121 开发视频清单。支持 NVIDIA L20 或 L40，同一结果目录绑定实际 GPU 身份。每条完整轨迹保存后可复用。默认每 15 秒刷新总体进度条，输出完整报告。

```bash
mkdir -p output/stage167
nohup bash tools/run_stage167_online_layers.sh > output/stage167/run_stage167.log 2>&1 < /dev/null &
tail -f output/stage167/run_stage167.log
```

## 判定

报告整段成功率 AUC、低 IoU 比例、最长失跟、未恢复事件、实际换层次数及逐视频配对结果。对照已恢复的事件以该事件起点到恢复后 32 帧为核对窗口，检查成对排序组在窗口内是否达到连续 3 帧 IoU 至少为 0.5。通过条件包括总体及剔除 0176 后对两组对照的 AUC 均为正、未增加原稳定视频的失败、低 IoU 与未恢复事件不增加、保留对照恢复及实际发生换层。结果属于重复使用的开发集。通过后可冻结策略，再组织独立验证。
