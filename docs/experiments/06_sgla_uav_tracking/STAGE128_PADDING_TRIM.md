# Stage-128 保留图像覆盖的搜索裁剪缩放对照

**正式同帧对照已完成。** Stage-127 的 226 个覆盖充分、无好输出且输入目标短边不到 4 像素的起点中，185 个只有 q1 充分覆盖目标。这 226 点的 q0、q1、q2、q3 裁剪边长中位数为 188／5,712／156／371.5 像素。q1 有 205 点补边至少 90%，q0 为 10 点。 [Stage-128 结果](STAGE128_RESULTS_REVIEW.md) · [Stage-127 结果](STAGE127_RESULTS_REVIEW.md)

## 干预

每个搜索槽位继续使用 Stage-121 提供的原始位置和宽高。若由其产生的裁剪方形已超出图像长边，且包含真实画面像素，将其边长缩到图像长边。保留原先覆盖的全部真实图像矩形，中心只在实现这一条件所需时移动最少的像素。使用 SGLA 原有的裁剪取整和右／下补边规则核对，保留父框长宽比。规则只读拟使用的裁剪和画面尺寸，不读目标标注、得分或未来帧。未超限的裁剪沿用原设置。四槽上限不变。

在 Stage-125 的 346 个触发帧重放原裁剪和修正裁剪，匹配历史、图像、首帧模板和冻结的 SGLA、解码、原评分。相同运行身份复用旧输出，只重新观察未见过的改后搜索，同帧最多四次新搜索。更换 L20／L40 或 UUID 时在当前卡重跑匹配对照，每帧最多八次，同卡逐帧复用相同父框。仅含空白、未覆盖真实像素的原裁剪不触发这一规则。该设计检验缩放能否改善输出，对于已经搜错位置的起点只记录原有覆盖和结果。

主要看新增好候选与丢失好候选、最终选中框的改善和损伤，并记录最高 IoU、目标在模型输入内的短边、补边以及中心移动。报告全部 346 点、实际受干预点、Stage-127 的 226 个充分覆盖且输入目标过小的点。留存用近几次历史提交框重建的超限次数，供排查尺度膨胀来自历史反馈还是候选生成。此轮是同帧回放，未测量修改后完整视频的状态反馈。

## 运行

同步代码后在服务器实验仓库根目录后台运行。

```bash
mkdir -p output/stage128
nohup bash tools/run_stage128_padding_trim.sh \
  >> output/stage128/run.log 2>&1 < /dev/null &
```

同运行身份最多新增 1,384 次搜索，换卡最多 2,768 次。设置 `STAGE128_GPU` 选择 CUDA 逻辑编号，设置 `STAGE128_ROOT` 另开输出目录。日志会打印汇总和 `stage128_results_*.txt` 的路径。完成后的结果可用 `--pack-only` 重新校验打包。
