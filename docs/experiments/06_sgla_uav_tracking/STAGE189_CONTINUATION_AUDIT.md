# Stage-189 当帧选框后的轨迹持续性审计

Stage-188 的 `0173:502` 一次写回可把当帧 IoU 提至 0.860，完整续跑仍未达到安全挽救标准。`0107:161` 的候选当帧最高 IoU 仅 0.198。Stage-189 在存档轨迹中核查何时出现低 IoU、失跟开始于哪帧、是否恢复及恢复后是否再次失跟。

读取 Stage-188 已封存的决策、候选和续跑缓存，以及对应开发视频的原标注。对完整事件窗 `0107:161` 和 `0173:502` 报告原生和去重候选的逐帧结果，同一候选被几条规则选中时同时标注。每条分支接回原生锚点之前的历史，复用三帧 IoU < 0.2 为失跟和三帧 IoU ≥ 0.5 为恢复的原标准。另报告锚点到首个低于 0.5 之前的连续好框帧数，以区分即时纠正和持续跟踪。下一帧框中心偏差与尺寸比用于在失败点区分明显的定位和尺寸偏差。

原生失跟名册逐条记录锚点之前可用帧和锚点之后可观察帧，核查 `0331` 未进入完整事件窗的原因。窗末仍未恢复按截尾报告。实验只使用两个完整事件窗的分支缓存，全量原生轨迹只用于复核事件和入选条件。无新增图像读取、推理或训练。

## 运行

在保存 Stage-188 缓存及 VisDrone-SOT 训练集标注的服务器运行。使用 CPU 即可。更换原始标注目录时可设置 `VISDRONE_SOT_ROOT`。

```bash
mkdir -p output/stage189
nohup bash tools/run_stage189_continuation_audit.sh > output/stage189/run.log 2>&1 &
tail -f output/stage189/run.log
```

脚本打印 `stage189_results_*.txt` 文件的位置。优先看 `stage189_branches.csv` 中的 `highest_hann` 与 `history_position` 的连续好框帧数、首次低 IoU、确认失跟和恢复。用 `stage189_frames.csv` 核对误差出现在哪一帧。只有定位了后续退化的起点，才有实证依据安排下一次搜索状态干预；位移和尺寸统计本身只能定位框的误差表现。

## 结果

已核验回传结果的决策指纹、代码哈希和四张 CSV 哈希。按逐帧表复算了 10 条分支的连续好框、失跟事件及后效，并将候选指标与 Stage-188 交叉核对。本地核查基于回传文本。决策指纹为 `6fd02d8652fd71a15952e2a5eee677bf081966a810286bd5b2652db4271d25a0`。

| `0173` 写回分支 | 502 帧 IoU | 503 帧 IoU | 502 → 503 帧中心误差（真值尺度） | 失跟起点／确认 |
| --- | ---: | ---: | ---: | ---: |
| 原生 | 0.072 | 0.094 | 1.023 → 0.956 | 502／504 |
| 最高 Hann | 0.860 | 0.091 | 0.028 → 0.971 | 503／505 |
| 历史位置 | 0.837 | 0.094 | 0.034 → 0.964 | 503／505 |
| 未被选中的反向像素分支 | 0.855 | 0.093 | 0.016 → 0.968 | 503／505 |

三个高 IoU 写回分支的好框均只维持第 502 帧。第 503 帧中心误差已接近原生失跟输出，预测宽约为真值的 0.96～0.97 倍、高约为 1.14～1.15 倍。主要观测到的是中心跳偏，仍需核查目标覆盖和响应图才能定位跳偏来自搜索裁剪还是框解码。七条分支均未观察到恢复，至第 630 帧截尾。最高 Hann 的后 128 帧均值虽比原生高 0.02389，其后续 128 帧中 IoU ≥ 0.5 的帧数仍为 0。

`0107:161` 的两个去重候选当帧 IoU 约为 0.193～0.198，预测高度仅为真值的约 23%，同时存在中心偏差；原生和两条候选分支后续 128 帧均无 IoU ≥ 0.5 的帧，失跟至第 289 帧截尾。`0331` 原生第 338 帧开始失跟，第 391 帧视频结束，锚点之后只剩 53 帧，因此不满足完整 128 帧资格。

## 下一轮建议

固定 `0173` 第 503 帧的模板、权重和回放后的原生路由，分别使用第 502 帧的原生框和三个高 IoU 框作为搜索父框。逐个核对裁剪对真值的覆盖、CENTER 网格可解码出的最佳 IoU、实际 Hann 选框和所选格点。若目标覆盖不足，先检验搜索状态；若覆盖充分但网格没有好框，检验表征与回归；若网格存在好框但 Hann 没有选中，检验读出。可用 `0107:161` 作同样的供给对照。结果先作为个案诊断，确认集继续封存。
