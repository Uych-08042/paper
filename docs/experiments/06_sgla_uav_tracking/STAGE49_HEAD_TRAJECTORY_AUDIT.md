# Stage-49：原生 SGLA 预测头适配的冻结轨迹时序诊断

## 目的

基于已经完成的 [Stage-48](STAGE48_NATIVE_HEAD_STABILITY.md) 及其[结果复核](STAGE48_RESULTS_REVIEW.md)，先区分共有损伤、种子分岔和单种子收益的发生时刻，决定下一项训练或固定历史重放应针对哪个问题。

本轮为CPU缓存诊断：不训练、不读取图像、不调用GPU，不反序列化模型权重。原生SGLA仍是基线，Stage-48四臂、两种子的完整轨迹与原结论保留。脚本校验原模型文件的字节哈希与receipt；这与加载模型推理不同。

## 固定范围

先核对全部12视频、96条适配轨迹及12条原生轨迹，重算逐种子、逐视频和总体指标，与Stage-48已冻结的三张汇总表逐项比较。其他Stage-48表、特征、模型和更早来源沿原指纹链校验。

时序展开固定六个已经用于开发的视频：

| 视频 | 关注点 |
|---|---|
| `uav0000304_00253_s` | 普通监督和新增项均受损；原稳定视频的大量低IoU帧 |
| `uav0000307_04531_s` | 两种子共有退化，尺寸膨胀和失跟持续时间增加 |
| `uav0000226_05370_s` | 单排序2133与组合2132的灾难性退化 |
| `uav0000176_00000_s` | 组合2133显著改善、2132基本未改善 |
| `uav0000170_00000_s` | AUC改善但仅4／6帧低IoU的短失效对照 |
| `uav0000204_00000_s` | 不同种子和训练臂的成功／失败路径对照 |

每视频展开原生与4臂×2种子，共54条已有轨迹。它们是事后选择的开发案例，不增加独立样本，也不重新做方法通过／失败判定。

## 输出能回答什么

- 首次父框、实际取整裁剪、浮点输出及官方取整输出分歧发生在哪一帧。
- 首次失效、确认、恢复、最长失效持续多久，低IoU帧有多少；原生与适配模型是在同一时刻还是不同历史下失效。
- 父框／输出中心误差、宽高比例、裁剪覆盖率如何变化，异常尺寸是否在失效前已经出现。
- 固定同一视频时刻，其他臂与种子的自身轨迹处于何种状态。
- 在共享完整父框或共享取整裁剪的记录中，输出何时开始不同。
- 已记录训练步的裁剪前梯度范数是否超过原全局裁剪阈值。只读日志，不据此估计全部256步的裁剪频率或断言分支更新的因果机制。

几何探针另报“GT宽高置于预测中心”和“预测宽高置于GT中心”的IoU，沿用官方预测取整口径。二者是离线替换，不能相加成完整误差分解或用于在线控制。

## 固定时间与阈值口径

- 初始化图像索引为0，跟踪帧编号为1至N。时间线保留源图像文件名，避免与文件名编号混淆。
- 失效和恢复严格复用Stage-27规则：连续3帧IoU<0.2触发；连续3帧IoU≥0.5恢复。起点报告最初低IoU帧，确认点另列。
- 长事件为失效事件跨度至少30帧；其中允许有未达到恢复条件的中间帧，不等于连续30帧低IoU。
- 中心异常为输出中心误差≥0.5个GT面积平方根边长；尺寸异常为任一宽高比例>3或<1/3；覆盖异常为覆盖率<0.9。均另报连续3帧的起始时刻，仅供描述。
- 每起失效的局部排序窗口为前30帧至后30帧，报告中心／尺寸持续异常的最早局部起点。窗口开头已有任一异常时标记`left_censored`，不推断二者谁先发生。
- 每个失效起点、恢复起点、首次分歧／异常／长失效，以及固定视频四分位时刻形成锚点。输出前10帧、锚点当帧、后30帧的跨臂汇总与去重时间线；窗口在边界截断。

这些阈值均不进入策略，也不用于调整Stage-48成绩。时间上的先后不足以单独证明因果。

## 服务器执行

同步新增两个Python文件后，在仓库根目录运行。无需设置`CHECKPOINT`，无需重新collect、train或evaluate。

```bash
cd ~/workspace/paper
export STAGE48_ROOT="$PWD/output/stage48/native_head_stability_v1"
export STAGE49_DIR="$STAGE48_ROOT/analysis/trajectory_audit_v1"

python -B tracking/test_stage49_trajectory_audit.py
python -B tracking/stage49_trajectory_audit.py --input "$STAGE48_ROOT"

cat "$STAGE49_DIR/stage49_focus.csv"
cat "$STAGE49_DIR/stage49_onsets.csv"
```

完成状态为 `COMPLETE_CACHED_HEAD_TRAJECTORY_AUDIT`。首次执行会写入独立诊断子目录；同一命令重跑会核对来源与输出并复用，不改写旧实验文件。可用`--output_dir`指定独立新目录；不允许将原始输入、模型或轨迹目录当作输出。

## 解释边界与后续决策

缓存只有框、选层和峰值幅度，没有完整轨迹的响应位置及dense图；不能恢复Top-K召回，不能由中心偏移认定选中语义干扰物。共享取整裁剪也不保证浮点映射原点相同；跨臂同一时刻仍是不同的自身历史，不是匹配父框因果试验。覆盖率不代表可见性。

若共同损伤在父框尚接近原生时就出现，可选择少量共同父框的冻结预测头重放来核查当前输出；若主要在自身父框偏移后扩散，可设计纳入自身预测状态的匹配训练对照。须先结合实际输出判断，本轮不预设是哪一种，也不因顺序相关就宣布根因已证实。

5项纯NumPy测试通过：中心／尺寸几何探针、同裁剪但不同浮点父框、失效／确认／恢复边界、局部窗口截断与左删失、108条源轨迹夹具的完整校验／汇总／复用、原来源不改写、模型／缓存／报告篡改拒绝，以及内部重新封装但与轨迹不一致的汇总拒绝。测试显式禁止Torch／OpenCV导入；使用合成框和虚构图像路径。本机未持有完整服务器产物，实际Stage-49结果待用户执行。
