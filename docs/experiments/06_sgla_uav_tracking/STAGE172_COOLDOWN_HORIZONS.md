# Stage-172 跨视频换层、冷却与续跑时长诊断

Stage-171 在 0304、0176、0089 的定点结果中观察到，冷却有时挡住有益换层，有时能保护换层后建立的轨迹。0304 的第 11 帧也出现了后 32 帧略降与长期失跟消失同时发生的情况。Stage-172 检查这些现象在按在线记录取样的开发视频中是否复现。

## 起点与执行

从 Stage-170 的成对排序加冷却轨迹取样。候选范围是其余 25 个开发视频，排除用过定点诊断的三个视频。每个视频在实际换层和被冷却拦截的提议中各取至多一帧，固定种子 23172 的哈希顺序确定起点。两类均要求起点后至少剩 128 帧，选点和缺额处理只使用在线执行记录与视频长度。回传包中有 17 个视频实际换过层，16 个视频出现过否决，检查片尾约束后最多 33 个起点。

沿用 Stage-171 的四组配对。起点执行原生层或成对排序推荐层，随后开放门控或应用固定 16 帧冷却。四条分支从同一父框、裁剪和历史起步，之后各自用预测框推进。每帧一次裁剪、七个 Transformer 块和一次预测头。同设备要求自然分支精确复现 Stage-170。跨 L20／L40 记录复现差异。模型和阈值复用此前冻结校准。

## 评价

- `stage172_effects.csv` 同时给出起点后 32、64、128 帧的当帧换层效应、后续冷却效应及交互。
- `stage172_paired.csv` 对三个时长共用的完整有效窗口做视频等权汇总和视频 bootstrap。缺少有效标注的窗口保留在支持和分支明细里。
- `stage172_horizon_changes.csv` 区分两种变化。两尺度均至少相差 0.01 且方向相反，记为方向反转。短窗差小于 0.01 而长窗达到这一幅度，记为短窗遗漏。方向反转与近零变化分别报告。
- `stage172_anchors.csv` 保存选层时可见的门控分、提议层与实际排序候选、距上次换层的帧数和历史统计。分支表记录持续失跟和连续好框。比较用于判断后续是否值得学习干预时机。

这批视频属于已使用的开发集，结果适用于匹配短轨迹诊断。逐帧表随结果打包，续跑缓存保存在服务器的运行目录。

## 服务器运行

沿用发起 Stage-170 和 Stage-171 时的 `STAGE170_ROOT`、`STAGE171_ROOT`。默认目录与对应脚本一致。选择不同 GPU 时，用独立的 `STAGE172_ROOT` 保存结果。

```bash
mkdir -p output/stage172
nohup bash tools/run_stage172_cooldown_horizons.sh > output/stage172/run_stage172.log 2>&1 < /dev/null &
tail -f output/stage172/run_stage172.log
```

脚本显示总体进度条，完成后生成 `stage172_results_*.txt`。
