# Stage-82 同历史候选供给与选择诊断

Stage-81 的混合尺度方案从首帧运行时整体退化，但其候选供给统计与原布局来自不同的自身历史。Stage-82 将两种布局放到同一历史状态，分开测量候选质量与选择损失。 [Stage-81 结果](STAGE81_RESULTS_REVIEW.md)

## 固定样本和回放

取 Stage-81 的原尺度 PPO、混合尺度 PPO 两种历史。各含 12 个开发视频、2171／2172 两个种子，合计 48 条历史、54,100 个已记录状态。由已选原始框重建历史以及 Stage-81 限幅状态，扫描全部帧。对混合来源逐帧核对裁剪替换标志，并核对两来源活跃帧的原裁剪坐标。

只在混合规则实际替换 q1 或 q3 裁剪时回放。每个状态两种布局共享图像、模板、原始预测历史和冻结 PPO。先做四个原布局搜索，再对被替换的槽位做额外搜索。相同槽位直接共用候选框和响应。活跃状态实际调用五或六次搜索，单个布局逻辑上仍是四次搜索。GPU 前根据缓存固定活跃状态数和调用预算。两种布局的结果均不推进历史。

评价按原生公开框的 IoU 规则。GT 只用于推理后测量。报告两种来源各自的活跃帧结果和全帧配对差。未替换时两个布局按构造相同，配对差记为零。逐种子先平均，再对视频等权计算配对区间；活跃条件比较只纳入有活跃帧的种子和视频。

## 读数与停止条件

- 候选上界为四个公开框的最高 IoU。好候选支持为至少一个候选 IoU ≥ 0.5，同时报告新增和丢失好候选的帧。
- 选择损失为上界减去冻结 PPO 选中框的 IoU。对同一状态，选中 IoU 的变化等于候选上界变化加上选择损失的减少量。
- 将每种来源上与原 Stage-81 匹配布局的候选框及动作做逐帧桥接。换物理 GPU 可以生成同卡配对结果，训练建议还要求原布局来源与混合布局来源的对应结果精确复现。

只有两种来源都满足以下条件，才建议进入混合选择器训练。活跃支持至少 8 个视频，候选上界收益的 95% 视频配对区间下界大于零、至少 7 个视频为正，好候选支持净增加，并且选中 IoU 下降、选择损失增加。此条件是固定开发筛选。若候选上界未显示跨历史收益，结束当前混合布局。若主要只是收益小或局限于少数视频，保留结果用于论文消融。28 组确认集保持封存。新训练和新完整轨迹均为零。

## 服务器运行

```bash
cd ~/workspace/paper
mkdir -p output/stage82
nohup bash tools/run_stage82_same_history.sh > output/stage82/run_stage82.log 2>&1 < /dev/null &
```

使用已分配的 L20 或 L40。依赖 Stage-76、77、81 原始运行目录和原生权重。可用 `STAGE76_ROOT`、`STAGE77_ROOT`、`STAGE81_ROOT`、`STAGE82_ROOT`、`STAGE82_GPU` 和 `CHECKPOINT` 覆盖。续跑绑定同一物理 GPU 与运行指纹，换卡时新建 Stage-82 目录。

完成后用 `cat output/stage82/run_stage82.log` 查看结果包路径。包内包括两种来源汇总、配对区间、逐视频结果、范围审计和逐活跃帧结果。已完成目录可用 `--pack-only` 导出。
