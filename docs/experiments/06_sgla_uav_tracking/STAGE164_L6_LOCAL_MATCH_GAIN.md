# Stage-164 用 L6 局部匹配预测换层收益

Stage-163 的 16 帧趋势收益组相对四帧收益组下降 0.027 个 IoU 点，剔除 0176 后下降 0.028 个点。0176 第 163 帧的 L7 排名从 62 升到 21，两组均已选中。Stage-164 继续使用四帧收益历史，检验 L6 视觉特征是否能改善选择。

## 配对设计

复用 Stage-159 的 328 个起点、28 个开发视频、两折源组划分和后 32 帧分支结果，固定每点的原生层、原提议层及 Stage-162 的退化预测。两折分别换层 64 和 4 次。所有收益模型保留相同的 8 个四帧统计、源组权重、岭回归设置和监督目标。目标是每层相对原生层的后 32 帧平均 IoU 差值，留出源组的标签只参与评价。

| 组别 | 16 维视觉特征 |
| --- | --- |
| Stage-163 四帧对照 | 归档的模板池化、搜索 2×2 池化和随机投影 |
| 同次采集投影对照 | 用本轮 L6 token 重算上述随机投影并重新拟合 |
| 局部匹配 | 用当前搜索 token 匹配首帧模板中央区域，保留搜索网格 4×4 的区域响应 |

局部分支对 L6 模板和搜索 token 逐向量归一化。模板取网格中央一半宽度和一半高度，搜索的每个 token 取其中最大的余弦相似度。将搜索响应网格分成 4×4 个区域，每区取最大值，形成按空间顺序排列的 16 个特征。局部组和同次采集投影组使用同一裁剪、同一次前缀计算和相同维数。

每点校验裁剪哈希和图像尺寸，审计一次 L1–L6 前缀及零候选块、零原生选择器、零预测头调用。按实际 L20 或 L40 绑定运行，记录与 Stage-159 的显卡差异及投影重算误差。一套输出目录绑定同一运行身份，换卡后用新的 `STAGE164_ROOT` 恢复采集。完整结果复用已有特征缓存。

## 服务器运行

```bash
mkdir -p output/stage164
nohup bash tools/run_stage164_local_match_gain.sh > output/stage164/run_stage164.log 2>&1 < /dev/null &
tail -f output/stage164/run_stage164.log
```

脚本沿用 Stage-159 的数据根目录和权重设置，并读取 Stage-163 正式结果。总体进度条覆盖特征采集、两种特征各两折拟合和报告输出。结束后生成 `stage164_results_*.txt`。

## 进入在线验证的条件

保留 0176 第 163 帧和四帧对照已有的恢复，无新增持续低 IoU 或丢失恢复。局部匹配组需在全体视频和剔除 0176 后，均优于归档四帧对照及同次采集投影对照。达到以上条件后，使用仅由训练视频确定的阈值验证完整视频。若仍无收益，优先区分可改善候选本身缺失与换层排序错误，再决定是否改变候选提议。
