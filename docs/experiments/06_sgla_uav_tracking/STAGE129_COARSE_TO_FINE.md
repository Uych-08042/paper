# Stage-129 同预算粗搜与局部放大

Stage-128 保留了覆盖，但在 226 个目标过小的触发点中，修正后仍有 199 个的输入目标短边不到 8 像素。Stage-129 将粗搜覆盖和局部精度放到不同槽位，检验更强局部放大能否补出有用候选。 [Stage-128 结果](STAGE128_RESULTS_REVIEW.md)

## 四槽搜索

1. 从 Stage-128 的缩边布局出发。只有原布局中存在被画面长边限幅的裁剪，才触发局部放大。用限幅前边长最大的槽位作为广域搜索。
2. 保留该广域搜索和 q0。若广域搜索本身是 q0，则另保留 q1。沿用保留槽位的原预测框。
3. 在广域 SGLA 原始响应图中，过滤中心投影落到补边的格点。依分数从高到低找两个相互分开的高响应位置。局部裁剪边长为广域边长的四分之一并向上取整，最小 16 像素，两个中心间距至少为局部边长的一半。排除与现有裁剪重合的结果；可用位置不足时沿用其余原槽位。
4. 用这四槽输出运行同一冻结评分器。局部位置和尺度规则只用画面尺寸、裁剪坐标和当前广域响应，原首帧模板、SGLA 权重和候选评分器保持冻结。

保留广域槽位及常规槽位是实验设计。其余原槽位被替换后可能损失已有好框，正式结果将逐一报告新增和丢失。真实目标的搜索覆盖与输出 IoU 分别计量。

## 控制组与诊断组

346 个起点使用原始历史和图像，当前卡同时重放 Stage-128 四槽缩边对照与 Stage-129 布局。相同运行身份验证对照与 Stage-128 回传一致。实际最多新增 2,179 次 SGLA 搜索，其中包括对照、局部放大与额外诊断。粗搜方案部署时每帧最多四次搜索。

在符合局部放大条件的帧上，另用真实目标中心生成一个同尺寸的局部搜索。这一路只提供定位诊断，既不改变粗搜结果也不进入选框。分别汇报实际局部搜索覆盖 ≥90%、实际局部搜索输出 IoU ≥0.5、真值居中输出 IoU ≥0.5，以及真值居中成功但实际局部搜索覆盖不足的次数。真值居中也会受模板、可见性和 SGLA 定位误差影响，结果仅说明该种局部尺度在该中心的可用性。

主对照统计所有起点的最佳候选 IoU、最终选中 IoU、好框的增失；另列实际启用局部搜索组和 Stage-127 的固定 226 个输入目标过小组。尚未开展修改后的完整视频跟踪。

## 运行

同步代码后，在服务器实验仓库根目录后台运行。

```bash
mkdir -p output/stage129
nohup bash tools/run_stage129_coarse_to_fine.sh \
  >> output/stage129/run.log 2>&1 < /dev/null &
```

日志会打印汇总以及 `stage129_results_*.txt` 的路径。设置 `STAGE129_GPU` 可选择 CUDA 逻辑设备，换卡续跑时用 `STAGE129_ROOT` 另设输出目录。用 `--pack-only` 可重新校验并打包已完成的结果。
