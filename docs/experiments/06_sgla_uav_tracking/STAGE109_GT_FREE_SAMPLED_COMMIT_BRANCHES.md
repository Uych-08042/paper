# Stage-109：不按失败标签挑选起点的提交后继实验

日期：2026-11-15。本页保留运行前固定设计；服务器已完成960起点／1,920分支，结果见[Stage-109复核](STAGE109_RESULTS_REVIEW.md)。组合future未超过原future与简单控制，没有新增完整视频AUC或方法采用结论。

本轮回答：**在未按失跟、救援或未来收益挑选的新开发起点上，旧提交门控还能否选择出有益的几何与外观更新？** 同时积累这些起点的真实成对后继标签，供下一轮判断训练支持是否需要改进。

Stage-108组合future在259个旧诊断起点的后继效用为+0.013909，较原future增加0.001071，但低于always的+0.015469；收益集中0304／0176，扩展来源总体负，留组MSE变差。继续在这批起点上增加模型复杂度，难以判断新增价值是否能推广到其他状态。因此本轮固定旧模型，改变取证范围。它仍属于已经消耗的28组开发证据，独立确认集保持封存。

## 1. 固定来源与抽样

- 绑定Stage-108决策指纹`e8cf2e2928d42715b69956355858e04d2952eedd0b0b4ac05c7c541a1d9397a9`，并检查Stage-103／106及其完整来源。
- 来源为Stage-103的40个视频／种子上下文，各含`four_matched`与`four_pairwise`，共80个模式上下文。使用Stage-106曝光缓存里的线上`eligible`资格：当前两种提交确有变化，且所需观测有效。
- 只保留具有完整32帧后继窗口的起点：跟踪编号`t=1..n-31`。末尾31帧不纳入，不能据此验证末尾失效保护。
- 排除Stage-106已有259个标签的**身份**，只看视频、种子、模式、帧号；不看原标签值、角色或收益。排除仅表示标签已经可用，不能称为独立留出集。
- 每个上下文从剩余池均匀无放回抽取最多12帧，固定全局seed2309，具体PCG64种子由上下文身份的SHA256生成。池不足12则全取，池为空则保留零支持记录，不从其他条件补齐。
- 抽样函数只接收帧号、线上资格、已有标签身份、上下文身份及固定设计。它不接收GT、失败事件、IoU、误差、门控分数或新分支结果。
- 抽样池、已排除身份、选中帧、随机种子、纳入概率`q/N`先写入`manifest.json`，然后才启动新搜索。

本轮的总体是“各来源上下文中剩余、符合线上资格且有完整窗口的状态”，不是所有视频帧。新旧窗口可以重叠，来源之间也没有变成独立确认数据。按上下文固定配额，结果先在各视频／种子／模式内平均，再按模式、种子、源组汇总；不混合所有帧，也不计算把相邻窗口当独立样本的置信区间。

## 2. 同起点成对后继

沿用Stage-105已验证的实际搜索、状态重放及一次提交干预接口。每个起点首先重放来源历史与过去被接受的外观描述，再进行一次共享的四候选搜索。

| 分支 | 当帧公开输出 | 当帧进入后续搜索的几何与外观 | 后面31帧 |
|---|---|---|---|
| keep | 原四候选核验输出 | 原四候选核验提交 | 原四候选核验，使用自身历史 |
| both_pair | 与keep完全相同 | 换为原pair决定的几何与外观写入 | 原四候选核验，使用自身历史 |

两条分支只在起点的提交动作上不同。不是在32帧中持续使用pair，也不是持续执行所评价的门控。首帧输出、过去历史、记忆起点、模板和原SGLA权重相同；原PPO与核验参数冻结。

在线特征与四个冻结门控的分数／动作，在新分支标签计算前保存为独立缓存。若当前硬件重算后的资格与原采样缓存不同，保留该起点、如实记录；门控不具资格时保持keep，不后验换样。为保留匹配证据和固定预算，仍采集两条分支。

标签为：

- `future = mean_IoU(both_pair[t+1:t+32]) − mean_IoU(keep[t+1:t+32])`，只在有效GT帧上计。
- `myopic = IoU(当帧pair框) − IoU(当帧公开四候选框)`，是当帧提交框代理标签；两条分支当帧的公开输出本来相同。
- 同时保存后继低IoU比例、好候选供给、末帧IoU和有效帧数。缺少有效后继标签时保留缺失，不填零、不删样。

GT仅用于开发结果评价，不能进入抽样、门控输入、状态推进或测试期动作。

## 3. 冻结门控和对照

复用Stage-106的49维baseline与Stage-108的129维relation_mode，各有future／myopic两个头、28个留组模型：合计112个已有模型，新训练0。

比较9个政策：keep、always_pair、离线future_oracle、两种表示各自future／myopic、两种表示各自的同率随机期望。阈值固定0，不调分数、配比、特征或超参数。

主要比较为`relation_mode__future − baseline__future`；必要控制是旧myopic、自身myopic、always、自身同率期望、keep。按all／historical／expanded和all／两种模式分别报告。每个上下文的同率期望使用该future门控在新样本的实际放行率，不读取标签；期望效用解析计算，future_oracle只能作离线上界。

结果将回答冻结门控在新抽样状态的局部选择能力，并提供后续训练数据。它**不产生新的完整视频AUC，也不提供方法采用门槛**。即使主要差值积极，仍要检查对always／myopic／同率、模式和来源分层、严重负例及支持率；之后才决定是否以这批标签设计新训练阶段。若多数样本的两种提交无有效差异，也应保留并报告，不能再按结果筛选。

## 4. 计算、硬件与续跑

每个32帧起点实际新增搜索为`4 + 2×31×4 = 252`；逻辑分支记账为`2×32×4 = 256`，两分支共享初始4次搜索。按每次搜索7块计。模板初始化不计入搜索调用，沿用原Stage-105口径；本轮没有部署速度结论。

上限为960起点、1,920短分支、241,920次新搜索、1,693,440次搜索块调用。这是完整产物去重后的设计预算；中断后重做尚未保存的计算会增加实际耗时／调用。实际池不足时预算随manifest缩小，不以满额为通过要求。每起点存point／predictions／keep／both_pair四个NPZ及各自收据。已有封存缓存会复用，中断发生在尚未保存的点或分支则重做该项。

首次运行接受L20或L40，记录GPU型号、UUID和软件／权重／配置身份；同一输出目录续跑必须相同运行身份。换卡或UUID变化时使用新的`STAGE109_ROOT`，不混写。除GPU型号与UUID外的来源运行差异直接拒绝。keep和both_pair都在当前卡同一运行中实测；若与Stage-103来源硬件不同，来源keep误差只作迁移诊断，不能声称逐字节复现旧卡。运行身份完全一致时要求整条keep窗口复现来源。

## 5. 服务器执行

先同步包含本轮代码的仓库，在仓库根目录、原`sglatrack-test`环境执行：

```bash
cd ~/workspace/paper
bash tools/run_stage109_sampled_commit.sh
```

默认写入`output/stage109/gt_free_sampled_commit_branches_v1`。支持`STAGE76_ROOT`、`STAGE89_ROOT`、`STAGE93_ROOT`、`STAGE103_ROOT`、`STAGE106_ROOT`、`STAGE108_ROOT`、`STAGE109_ROOT`、`CHECKPOINT`及`STAGE109_GPU`覆盖路径／卡号。原权重默认`output/checkpoints/train/sglatrack/deit_distilled/sglatrack_ep0297.pth.tar`。

远程断开后继续运行：

```bash
mkdir -p output/stage109
nohup bash tools/run_stage109_sampled_commit.sh > output/stage109/run.log 2>&1 < /dev/null &
echo $!
tail -f output/stage109/run.log
```

`nohup`不延长平台的作业时限或GPU租期。同卡中断后重新执行原命令；换卡时例如：

```bash
export STAGE109_ROOT="$PWD/output/stage109/gt_free_sampled_commit_branches_l40_run2"
bash tools/run_stage109_sampled_commit.sh
```

完成会先检查结果与所有缓存／收据／来源哈希，再自动打包`stage109_results_<UTC>_<pid>.txt`，含decision和8张表。只重新校验并打包：

```bash
bash tools/run_stage109_sampled_commit.sh --pack-only
```

脚本不自动commit／push。回传生成的结果TXT即可；服务器的完整NPZ、收据和来源目录继续保留。
