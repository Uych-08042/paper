# Stage-105 共同起点的几何与外观提交交叉干预结果

Stage-105完成259个共同起点、1,036条真实短分支。相同过去、相同当帧发布输出下，只改一次提交就能改变随后真实搜索，并在部分窗口取得明显收益。这支持把搜索历史提交作为值得独立修改的SGLA机制；同时存在严重反例，尚不能一律提交pair框，也没有建立新的完整视频收益。 [固定协议](STAGE105_MATCHED_STATE_COMMIT.md) · [原始结果](results/stage105_results_20261114T140833Z_654656.txt) · [Stage-104结果](STAGE104_RESULTS_REVIEW.md)

四组仅在起点`t`改变提交：keep维持原四候选核验；geometry_pair把同状态pair框提交普通历史；memory_pair用pair选择及原资格决定外观写入；both_pair同时改变两者。四组`t`帧发布框相同，`t+1`后恢复各自原规则，窗口最多32帧。

识别的是首步提交方式的总后继作用。普通历史同时影响父框、PPO时序特征和外观资格，且之后记忆与几何仍耦合更新；不能将几何组效果唯一解释为裁剪中心变化。起点包含离线丢好／补好和既有失败／恢复角色，是条件诊断，不是可直接上线的触发器。

## 参考恢复没有补回

恢复表136行表示34个“起点×来源×参考事件”上下文的四组记录，不是136次独立恢复。它们对应17个参考事件身份：four_matched12个、four_pairwise5个；PPO与pair参照可能指向相邻的同一物理恢复。

每个处理有23个完整观察上下文、11个右截断上下文。全部四组均没有匹配恢复；所有17个参考身份都至少有一个可完整观察的起点，也均未补回。右截断不能算完整失败，0176／251的局部好转也不能替代321等更晚参考的判定。

本轮专门追踪已丢失参考事件，keep在这些参考上本来就没有恢复。因此它也没有完整验证保住已有恢复的能力，需在后续完整轨迹与正向恢复对照中补齐。

## 下一步的实际缺口

本轮已给出部分状态下“改变一次提交→真实后继候选与跟踪改善”的机制证据。下一步可以转向可部署的提交条件原型：独立决定何时允许新输出更新普通搜索历史，并共同处理外观写入及相关时序状态的一致性。

该条件必须用当前／过去可观测量，在fit源组确定；不能直接使用本轮GT丢好／补好角色作为线上触发。然后做完整开发轨迹的同预算对照，同时保留原pair、冻结PPO与原生SGLA。简单提高margin、要求参照一致、遇到冲突就一律pair提交，均尚无充分依据。

本次仅归档复核，未新建Stage-106或修改冻结代码。最近完整AUC仍是Stage-103，确认集继续封存，没有新增方案通过完整能力保护。
