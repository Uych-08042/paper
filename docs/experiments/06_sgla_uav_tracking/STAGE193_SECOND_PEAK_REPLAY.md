# Stage-193 同裁剪分离第二峰的一次写回

Stage-192 的真值选择在四个源组实现安全挽救。其中三个有好框的挽救窗口，首个好格点在 Hann 全网格排序中均排第 2。Stage-193 检验使用实际可提取的第二响应峰后，这些挽救能保留多少，稳定性会付出什么代价。此前 Stage-135／136 已测试带门槛的第二峰及全视频结果，本轮在预先冻结的跨源组名册上检验单次替代动作。

## 对照与指标

- 沿用 Stage-192 的全部 16 个失跟窗、36 个稳定窗。固定原生父框、模板与即时选层。一个 CENTER 前向同时得到 Hann 首选、分离第二峰和用于离线诊断的网格最佳框。
- 第二峰使用 Stage-28 和 Stage-136 已有提取规则。取 3×3 邻域局部极大值，按 Hann 加权分降序，遇同分按格点索引。候选框与更高响应已保留框的 IoU 高于 0.5 就剔除。没有第二峰则保留 Hann 首选。第二峰提取不读取真值。
- 三个起点各自写回一次，按原生跟踪后续 128 帧。在与 Stage-192 完全相同运行身份下复用已核验的 Hann 和网格最佳框轨迹，并核验锚点与后效。如果第二峰的框与任一分支完全一致，也复用该轨迹。另卡运行时在同卡重放全部对照。
- 逐窗报告第二峰是否可用、当帧 IoU、首二峰分数比、恢复及新增失跟。分失跟窗和稳定窗汇总对 Hann 的后效，以及复现的真值挽救、独有挽救和剔除最佳源组后的效应。另报排除 `0173`、`0107` 的结果。网格最佳框是参照，不参与第二峰选择。确认集继续封存。

本轮覆盖选中第二峰的收益与损害；只有两者均确实存在且可跨源组辨别，才进入在线选择验证。

## 运行

需要 Stage-192 及其来源缓存、原始数据和 SGLA 权重。支持 L20、L40。每个窗口只需一次锚点搜索，与 Stage-192 同运行身份时至多新增一条续跑。

```bash
mkdir -p output/stage193
nohup bash tools/run_stage193_second_peak_replay.sh > output/stage193/run.log 2>&1 &
tail -f output/stage193/run.log
```

脚本打印总体进度，并在完成时显示 `stage193_results_*.txt` 的路径。

完成 52 次锚点搜索与 5,888 次新增续跑。全部 52 个锚点复现 Stage-192，Hann 对照归档框误差为零。已核验四张 CSV 及决策指纹，并复算分组汇总。决策指纹为 `b2e425200d456c40ad82b4e0e42255a70bbdc02dab415679fcbfc07a05372a17`。

第二峰复现 `0173` 和 `0204` 的挽救，后效分别 +0.549 和 +0.774。没有独有挽救。`0091` 的第二峰当帧 IoU 0.591，却几乎没有后效增量，网格最佳框则为 +0.695。`0176` 的第二峰与真值不重叠，未复现网格最佳框的挽救。`0348` 仍丢掉原生恢复，后效 −0.528。排除 `0173`、`0107` 后再去掉最佳组，失跟窗后效转为 −0.0378。

用回传表事后复算 Stage-135 原有的仅分差门槛（次峰分数至少为首峰 80%）。52 窗中会触发 8 个失跟窗和 1 个稳定窗，保住两个挽救，拦下本轮全部严重事件伤害和新增失跟。均值分别为 +0.0834 和 −0.000093；这个计算只涉及一次写回。Stage-136 的完整开发视频上，同一门槛仍让 AUC 由 63.9605 降至 61.0823，并使两个原生稳定视频新增失跟。

## 下一轮建议

继续固定这批窗口和原生裁剪，以仅分差的旧门槛作为对照。优先检验预先定义的同网格分离峰候选池能否补回 `0091`、`0176` 一类漏掉的后效挽救，同时保留稳定窗并报告实际候选数量与统一搜索预算。候选池里的真值选择只估计上界。若新增峰也不能稳定补回挽救，收敛第二峰这条路线，不再围绕现有几个视频调整门槛。若补回空间足够，再按源组留出检验可部署的选框条件。
