# Stage-176 同起点六层续跑与事件保护

Stage-175 用原生层和排序推荐层比较失跟与恢复，看到个别起点的替代有益或有害。Stage-176 在相同输入上比较六个候选层，测量避开有害排序层和改善原生续跑的空间。

## 样本与执行

纳入 Stage-175 全部五个严重事件风险起点、三个阻止未恢复失跟或挽回恢复的起点，并按固定哈希在每个有普通窗口的源组抽取一个普通起点。普通起点抽样仅使用标识。另加入 Stage-173 的 0304 第 526 帧和 Stage-174 的 0348 第 438 帧。按起点去重后共 26 个起点、16 个源组。

每个起点恢复相同模板、历史及父框，分别执行 L7、L8、L9、L10、L11、L12 中的一层。此后各分支反馈自身预测框并统一用原生 SGLA 选层。保持原档的窗口长度。核查每帧一次裁剪、一次选层、七个 Transformer 块和一次预测头。运行身份相同时重用经过哈希核验的 Stage-175 原生及排序分支，并核对旧起点指标。运行身份有设备差异时六条分支同卡重跑。

## 判读

每层报告起点 IoU、32 帧和共同窗口平均 IoU 差、新增失跟、丢失恢复以及窗口末是否未恢复。定义受保护候选需同时满足三项条件。无新增失跟。无丢失恢复或新增未恢复。相对原生的 32 帧及共同窗口平均 IoU 各自最多下降 0.01。

有益的受保护替代要求共同窗口平均 IoU 提升至少 0.01，或避免未恢复失跟，或挽回恢复。分别报告有害排序层能否由另一非原生层安全替代、各源组是否有有益替代，以及纳入原生层后按平均 IoU 选择的普通与受保护事后上界。独立查看哈希抽样的普通起点、未作定点诊断的源组以及完整 128 帧窗口。样本包含按先前结果富集的案例，统计只描述这些状态的候选空间。

## 运行

使用原始 checkpoint 和 Stage-170、173、174、175 的输出目录。更换 GPU 运行身份时使用独立的 `STAGE176_ROOT`。

```bash
cd ~/workspace/paper
mkdir -p output/stage176
nohup bash tools/run_stage176_layer_event_sweep.sh > output/stage176/run_stage176.log 2>&1 < /dev/null &
tail -f output/stage176/run_stage176.log
```

脚本显示总体进度并支持缓存续跑。完成后生成 `stage176_results_*.txt`。优先查看 `stage176_layers.csv` 的逐层标签及 `stage176_headroom.csv` 中的保护对照。
