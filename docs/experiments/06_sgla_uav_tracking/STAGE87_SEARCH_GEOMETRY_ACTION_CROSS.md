# Stage-87 搜索几何与 PPO 首次动作的交叉诊断

Stage-86 在 `0147` 看到未移动的好候选 q2 被放弃，整体高预测位移组的低 IoU 增加。Stage-87 复用其全部 144 个窗口，分开测量候选搜索几何变化与首帧改选对后续跟踪的作用。每个窗口用相同首帧模板、起点发布框和冻结 PPO。两种动作均来自该窗口在 Stage-86 的实际预测。

| 条件 | 下一帧候选布局 | 写入并继续的槽位 |
|---|---|---|
| FF | 固定 | 固定布局 PPO 所选 |
| FM | 固定 | 中点布局 PPO 所选 |
| MF | 中点 | 固定布局 PPO 所选 |
| MM | 中点 | 中点布局 PPO 所选 |

FF、MM 直接复用 Stage-86。FM、MF 在同一槽位取对应布局的实际解码框。若这个框与任一已有分支的写入框完全一致，则复用后续轨迹。其余分支从写入后的下一帧起按原固定布局和冻结 PPO 续跑 15 帧。未移动槽位 q2、q3 的框要求两布局一致。固定槽位比较的是同一索引，q0、q1 的候选位置可以不同。

主要读数为高预测位移组的 16 帧平均 IoU 和低 IoU 占比。分别报告 `MF − FF` 的同动作几何效应，以及 `MM − MF` 的中点布局内改选效应，两者相加为 Stage-86 的总差异 `MM − FF`。另外报告逆向分解、交互、首帧 IoU、后续 15 帧 IoU 和持续低 IoU 指标。种子和窗口先在视频内平均，区间按 12 个视频重采样。低位移组是对照。FF、MM 是原 PPO 行为，FM、MF 是受控续跑。

共 576 个条件。实际新增续跑数由缓存中的写入框决定。在每个需要补跑的窗口，用当前设备复现 Stage-86 的两个首帧候选集、动作和输出，再开始新分支。新增每支 60 次搜索，每个通过桥接的窗口另计 8 次。无训练，沿用已消耗的开发视频，确认集不参与。

## 服务器运行

在仓库根目录激活 `sglatrack-test` 后执行。

```bash
bash tools/run_stage87_action_cross.sh
```

默认复用 Stage-86 的 L20 缓存。若本次分到另一张 L20，可以新建 Stage-87 运行并通过首帧复现检查。已开始的 Stage-87 绑定 GPU UUID。若只分到 L40，先用单独的 `STAGE86_ROOT` 在 L40 上生成两组缓存，再用对应的 `STAGE86_ROOT` 和新 `STAGE87_ROOT` 运行 Stage-87。可以传入 `--prepare-only` 单独生成首帧表和新增续跑计划，该模式只读缓存。完成后脚本把结果打包为 TXT。
