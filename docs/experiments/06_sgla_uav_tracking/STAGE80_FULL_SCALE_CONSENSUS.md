# Stage-80 完整轨迹尺度保护消融

Stage-79 显示，0204 在限幅后仍有好候选，但 PPO 的近分动作翻转会使错框进入后继状态。0304 在同一候选序号下仍有尺度收益。Stage-80 固定一项保护规则，在 12 个开发视频上从首帧开始完整评价。 [Stage-79 结果](STAGE79_RESULTS_REVIEW.md)

## 固定四臂

| 臂 | 搜索次数／帧 | 配置 |
|---|---:|---|
| `native_sgla` | 1 | 原生 SGLA，使用上帧原始输出框 |
| `original_ppo` | 4 | 原尺度历史，冻结四选一 PPO |
| `limited_ppo` | 4 | Stage-78 尺度限幅，冻结 PPO |
| `guarded_ppo` | 4 | 同限幅与 PPO，加入候选一致性保护 |

所有臂使用同一原生 SGLA 权重、首帧模板和完整视频，不做重置或训练。尺度限幅沿用过去五帧已限幅尺寸的逐轴对数中位数及 1.25 倍上限，中心保持不变。只在限幅历史相对同轨迹原始历史实际改变至少一个取整裁剪时考虑保护。原始裁剪只计算坐标。

在至少三个去重后合法候选存在时，取与 PPO 首选的 logit 差不超过 `log(1.10)` 的候选，即首选与其概率之比至多 1.10。若至少两个候选满足，计算每个候选与其他全部合法候选的平均浮点框 IoU。只有最一致候选相对 PPO 首选的均值至少增加 0.20 时才换框。保护只使用已有公开框、PPO 分数和取整裁剪，替换后的框进入下一帧状态。两个阈值是本轮固定的原型选择。

将固定规则应用于 Stage-79 已存的两个限幅首帧，0204 由 q0 改为 q2，0304 保留 q2。这只检查两个已知输入上的决策，完整轨迹可能到达不同的状态。

## 样本、预算和判据

原生单搜索一条轨迹，三个 PPO 臂各两个既有种子。合计 84 条完整轨迹、338,125 次搜索和 2,366,875 次 block 调用。所有对照在同一张卡运行，同时报告原生和原尺度 PPO 对 Stage-76 缓存的框及动作差异。28 组确认集只保留 Stage-79 指纹引用，本轮推理为零。

种子先在视频内平均，视频再等权。主比较为保护组相对原尺度 PPO 的 AUC。开发门槛要求至少提高 0.5 AUC 点且视频配对 bootstrap 95% 区间下界大于 0，保护组 AUC 不低于仅限幅组，低 IoU 比例和最长失跟比例不劣于原尺度 PPO，且原生无失跟视频中没有新增失跟。另报告保护触发与替换、可靠帧 AUC 和每个视频的结果。只有通过开发门槛才考虑在冻结确认集上评估同一原型。

## 服务器运行

```bash
cd ~/workspace/paper
mkdir -p output/stage80
nohup bash tools/run_stage80_guard.sh > output/stage80/run_stage80.log 2>&1 < /dev/null &
```

使用已分配的 L20 或 L40。启动依赖 Stage-76、77、79 的原始运行目录及原生检查点。可用 `STAGE76_ROOT`、`STAGE77_ROOT`、`STAGE79_ROOT`、`STAGE80_ROOT`、`STAGE80_GPU` 和 `CHECKPOINT` 覆盖。续跑复用已经提交的整视频缓存，需同一运行指纹及物理 GPU。完成后用 `cat output/stage80/run_stage80.log` 查看结果包路径，支持 `--pack-only`。
