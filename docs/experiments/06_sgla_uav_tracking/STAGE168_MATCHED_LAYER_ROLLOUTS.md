# Stage-168 区分单次换层与持续门控的影响

Stage-167 在 28 个开发视频上完成 84 条轨迹。成对排序的完整轨迹 AUC 为 62.598，原生为 63.961，原提议为 62.383。成对排序在 0304 和 0080 引入新失跟，在 0089 和 0176 丢失原提议组的恢复。

## 核对窗口与起点

| 视频 | 参考事件帧 | 类型 |
| --- | ---: | --- |
| 0304 | 554、1091 | 两组换层策略的失跟 |
| 0080 | 200 | 原提议组失跟，两组换层策略同帧失跟 |
| 0089 | 1182 | 原提议组恢复 |
| 0176 | 158、744 | 原提议组失跟及恢复 |

从事件帧往前 32 帧，在原提议和成对排序各自的 Stage-167 轨迹中，选择实际发生换层的最早与最晚起点。某个窗口缺少换层时在报告中记录。每个视频额外取最早一次在线换层，同视频、同历史、同帧的重合起点只跑一次。事件窗口根据已观察到的结果固定，属于开发集事后诊断。

## 同状态干预

每个起点固定首帧模板、上帧框、最多 16 帧自身框及 Hann 峰值。使用同一搜索裁剪执行以下五组，并最多续跑 64 帧。

| 分支 | 起点之后 |
| --- | --- |
| 原生层 | 始终执行原生选层 |
| 原提议层单次干预 | 后续恢复原生选层 |
| 成对排序层单次干预 | 后续恢复原生选层 |
| 原提议持续门控 | 后续按 Stage-167 原提议组运行 |
| 成对排序持续门控 | 后续按 Stage-167 成对排序组运行 |

起点由实际发生过换层的缓存帧提供。每个分支从同一状态重新计算候选；起点应用相应候选时同时报告原门控是否通过。续跑使用实际 Stage-167 门槛。每帧核对一次裁剪、七个块及一次预测头。相同运行身份下，持续组在自己的历史状态上须逐框、逐层复现源轨迹。换卡时记录复现偏差。

## 运行与解读

```bash
mkdir -p output/stage168
nohup bash tools/run_stage168_matched_layer_rollouts.sh > output/stage168/run_stage168.log 2>&1 < /dev/null &
tail -f output/stage168/run_stage168.log
```

脚本读取服务器上的 Stage-167 逐帧缓存及冻结模型来源，支持 L20／L40，显示总体进度条，并在完成后打包报告。已提交的分支缓存可复用。

逐点检查单次换层相对原生分支的平均 IoU、低 IoU 和持续失跟，再比较持续门控组相对单次组的变化。若只有持续组出现新增失跟，再核对它在起点后的实际换层次数。恢复窗口另统计事件时点起连续三帧 IoU 达到 0.5 的情况，以区分短暂贴近与恢复。结果用于决定优先验证单次干预保护还是连续换层限制。
