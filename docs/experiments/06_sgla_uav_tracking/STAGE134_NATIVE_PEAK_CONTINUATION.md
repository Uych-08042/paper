# Stage-134 原生 SGLA 候选改选与短程续跑

Stage-133 的 19 个失跟起点均保有目标中心，其中 11 个能从同一响应网格解出 IoU ≥ 0.50 的框。Hann 加权峰与原始响应峰各取前五，合并后保有其中 6 个起点的好框。Stage-134 检查从同一张响应图里换一次框，收益能否传到后续帧。 [Stage-133 结果复核](STAGE133_RESULTS_REVIEW.md)

## 实验设计

使用 Stage-121 原生轨迹与 Stage-133 已审计的 19 个失跟起点。稳定对照在每条开发视频上最多取一个起点，要求原生起点和后续 32 帧均达到 IoU ≥ 0.50。取最接近视频中点的合格窗口，同距取较早者。两组起点均从已归档轨迹确定，适用于开发诊断。

| 分支 | 起点写回的框 |
| --- | --- |
| `native` | 原生 SGLA 输出 |
| `hann_runner_up` | 去重后的第二个 Hann 加权响应峰，无第二峰时沿用原生输出 |
| `peak_pool_oracle` | 原始响应与 Hann 加权各取前五峰，合并后取当帧 IoU 最优框 |
| `dense_oracle` | 整张响应网格中当帧 IoU 最优框 |

四组共用一次起点搜索的裁剪、模板和响应。Oracle 组只在该帧使用真值来估计候选潜力，若与原生输出同 IoU 则保留原生输出。每组从各自的输出框出发，在后续 32 帧逐帧使用原生 SGLA 单搜索。所有组保留首帧模板和原生权重。每个窗口 129 次物理搜索，整个实验最多 6,063 次。

## 结果判读

- 看失跟起点的当帧好框数、随后平均 IoU、低 IoU 帧数，以及是否出现连续三帧 IoU ≥ 0.50。记录较原生新增和丢失的连续好框段。
- 比较有限候选与稠密网格的结果。有限候选能持续救回时，优先研究如何选峰。只有稠密网格能持续救回时，先改进候选提取。当帧 IoU 提升却很快丢失时，继续检查输出写回后的状态演化。
- 检查稳定窗口中改选导致的退化。第二峰的运行不依赖真值，但本实验在预定窗口强制换框。实际采用仍需验证在线触发和完整视频表现。

同一次运行的全部分支在同一张 GPU 上重测。若 GPU 与 Stage-121 的归档设备不同，仍核对起点裁剪并报告原生分支与归档轨迹的框误差。汇总表单列本次原生起点仍满足 IoU < 0.20 的窗口。恢复比较均以本次实测的原生分支为对照。相同运行环境的续跑按窗口复用已校验的缓存。

## 运行

在有原实验缓存、权重与帧文件的服务器仓库执行。

```bash
bash tools/run_stage134_native_peak_continuation.sh
```

脚本按当前环境使用 `STAGE134_GPU`，默认逻辑设备 `0`。输出默认在 `output/stage134/native_peak_continuation_v1`。运行后生成 `stage134_results_*.txt`，包含汇总、逐窗口结果、搜索计数和运行校验信息。逐帧 IoU 另存 `stage134_timeline.csv`。
