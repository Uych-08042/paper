# Stage-130 保留备用候选的单槽局部放大

Stage-129 的两个局部搜索能补出好框，但六个原有好框损失都来自被覆盖的备用槽 q3。Stage-130 在同四槽预算下保留 q0、q3 和广域搜索，只使用一个槽位做局部放大。 [Stage-129 结果](STAGE129_RESULTS_REVIEW.md)

## 固定对照

复用共 346 个起点、17 个视频的同一历史、图像和原始 SGLA 预测，只重组已观察的候选。保留 q0、q3 和广域槽位。当广域槽位与 q0 或 q3 重合时，额外保留 q1。265 个已有局部搜索的触发起点各有两个实际观察过的位置。其余起点使用原布局。比较 Stage-128 缩边、Stage-129 双局部，以及三个单局部组。

| 单局部组 | 如何选局部位置 |
| --- | --- |
| 第一高响应 | 使用 Stage-129 先选出的局部位置 |
| 第二高响应 | 使用 Stage-129 后选出的局部位置 |
| 位置投票 | 用 q0 和 q3 的预测框中心投票，哪个局部裁剪覆盖更多中心就选哪个；票数相同则选第一高响应 |

位置投票只读取已保留候选的预测框和两个待定位置的裁剪坐标。若在线使用，先执行三个保留搜索，再执行选中的一个局部搜索。未选的局部框和真值都不参与该决定。与全体候选相关的特征用重组后的四个预测框重新计算，原评分器保持冻结。分别记录好候选的增失、最终好框数量和原先选到好 q3 的起点是否被重新错选。

## 先从回传核对候选集合

已用 Stage-129 的逐框 IoU 直接复算。第一和第二位置固定策略各得到 18 个有好候选的起点，均是原 13 个全保留并新增 5 个。在 226 个原小目标起点上各补出 3 个。若事后用真值在两个已观察位置中选更好的一处，最多可得 21 个好候选起点，包括新增 8 个。这只是两种位置上的事后上限。位置投票和最终选框必须读取服务器缓存中的预测框及评分特征。

## 运行

同步代码后，在服务器实验仓库根目录运行。该轮复用 Stage-129 的观测及 Stage-121 的历史，不读图、不开 GPU，也不训练。

```bash
bash tools/run_stage130_preserve_q3.sh
```

汇总和 `stage130_results_*.txt` 的路径会直接打印。可用 `STAGE130_ROOT` 指定输出目录。
