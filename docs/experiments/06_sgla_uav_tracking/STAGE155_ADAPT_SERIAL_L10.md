# Stage-155 只训练供串行路径使用的 L10

Stage-154 显示，冻结权重直接串接 L9 → L10 只在 19 个失跟起点中新增 1 个当帧好框。Stage-155 测量让一份 L10 副本专门学习接收 L9 的特征后，能否改善同计算量下的输出和后续恢复。 [Stage-154 结果](STAGE154_RESULTS_REVIEW.md)

## 训练

- 以 28 个 VisDrone-SOT 开发视频的源组做两折，每折 14 组拟合、14 组验证。划分用固定种子，由源组名确定。每个评估起点只使用另一折的数据训练出的 L10。
- 从 Stage-121 原生轨迹取搜索父框。训练视图要求目标中心位于裁剪有效区域，且原生选中 L9。每源组均匀采样最多 32 帧，再从其余原生 IoU < 0.50 的可用帧中均匀采样最多 16 帧。缓存原生 L9 输出与相同裁剪坐标下的训练标注。
- 从原 checkpoint 复制 L10，固定原生模型全部参数和缓冲区。训练只更新副本参数，每折 AdamW 192 步，批量 8，学习率 1×10⁻⁵。沿用 CENTER 的真值热图格点选取框和 GIoU、L1、focal 监督。保存梯度与权重哈希，核对原生网络保持冻结。

## 评估

复用 Stage-154 的全部 47 个起点。三组使用相同模板、父框、裁剪和预测头，在起点分别执行 L9、L9 → 原 L10、L9 → 适配 L10。每路写回各自的框，此后均走原生路径 32 帧。原生与冻结加算两组在相同运行身份下核对 Stage-154 轨迹。

重点比较适配 L10 和原 L10 在相同块数下的当帧 IoU、后继 8／32 帧平均 IoU、连续好框恢复及稳定窗口新增低 IoU。另以原生 SGLA 衡量是否有净收益。三组共 4,653 次评估搜索，其中在起点追加 94 次 L10。本轮使用已消费的开发源组，结果适用于这些短程干预。

## 执行

同步代码后在服务器仓库根目录的 `sglatrack-test` 环境执行。需要原 checkpoint、VisDrone-SOT 图像及 Stage-76、89、93、121、134、154 的完整产物。首次使用可见的 L20 或 L40，并在该卡上完成训练和三组评估。同目录续跑按已提交的模型和分支缓存继续，换卡时使用新的 `STAGE155_ROOT`。

```bash
mkdir -p output/stage155
nohup bash tools/run_stage155_adapt_l10.sh > output/stage155/run_stage155.log 2>&1 < /dev/null &
```

默认输出目录为 `output/stage155/isolated_l10_adaptation_v1/`。完成后回传其中的 `stage155_results_*.txt`。
