# Stage-138 跨块候选写回与短程续跑

Stage-137 发现 3 个失跟起点可以从其他块标准输出取得原块有限峰池缺少的好框。本轮验证这三个框写回后能否减少后续失跟，同时检查跨块最高 Hann 峰导致的稳定窗口损害是否持续。 [Stage-137 结果](STAGE137_RESULTS_REVIEW.md)

## 固定窗口

失跟起点为 0085／1541、0089／1159、0237／242。稳定对照为 0080／645、0147／1113、0349／408，这三个点均为跨块最高 Hann 峰将原生好框换为 IoU < 0.50 的案例。两组均按已知结果选定，适合机制检验。发生率需要完整视频或独立样本评价。

| 分支 | 起点写回框 |
| --- | --- |
| `native` | 原选块原生输出 |
| `peak_pool_oracle` | 原选块两套前五峰并集的当帧真值最优框 |
| `dense_oracle` | 原选块全网格的当帧真值最优框 |
| `cross_layer_top1_oracle` | 六块各自标准输出中的当帧真值最优框，同分保留原生 |
| `cross_layer_max_hann` | 六块中 Hann 最高峰对应的标准输出框 |

起点框使用同一 L40 上已核对的 Stage-134 和 Stage-137 缓存。每个分支写回一次，随后在同一张 L20 或 L40 上独立接回原生 SGLA 32 帧。各分支使用同一首帧模板，后续裁剪由自己的上一帧结果决定。整轮共 30 条短分支和 960 次新搜索，起点新增搜索为零。同卡时复核前三个分支与 Stage-134 的坐标和层选择，换卡时记录差异并以本次重跑结果作配对对照。

## 结果判读

主要比较跨块最优和原块有限峰池的 32 帧平均 IoU、低 IoU 帧数、连续三帧 IoU ≥ 0.50 的首个起点及末帧 IoU。原块全网格分支用于对照原块当帧最优框的后续表现。真值组使用真值选择起点框，后续逐帧为原生推理。跨块最高峰的稳定窗口结果用于检查错误写回风险。样本量为 6，用逐窗口结果判读正负例。在线补块频率和持续跟踪收益仍待验证。

## 运行

```bash
bash tools/run_stage138_cross_layer_continuation.sh
```
