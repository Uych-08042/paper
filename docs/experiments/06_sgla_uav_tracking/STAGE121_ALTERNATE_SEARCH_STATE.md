# Stage-121 单帧备用搜索状态

状态：**代码已实现，服务器完整轨迹待运行。** 本轮检验当帧输出和下一帧搜索分配能否分开处理，减少偶发错框导致的持续失跟，并保留原有恢复。

## 固定干预

从 Stage-113 的 `generated_shared` 出发。当前帧仍照常发布共享评分器选中的框。下一帧读取上一帧自己的观测，当选中框来自非零槽位、比标准搜索输出 q0 高不超过 0.05 分、两框中心距离至少为两框中较大的面积平方根时，提出备用搜索。以该 q0 的中心和宽高构造原尺度规则下的搜索裁剪，替换下一帧第 4 个槽位。只有备用裁剪与原四槽位的取整裁剪都不同，且被替换槽位在原银行中唯一时才实施。

第 1 个槽位仍是从已发布框出发的标准搜索，第 2、3 个沿用原生成器。备用框有效期为一帧。触发帧的发布框、历史特征与写入资格照旧，备用框须在下一帧参与同一共享评分才可能成为新输出。SGLATrack 的权重、首帧模板、CENTER 解码、四槽位上限、生成器与评分器均冻结。决策在跟踪中只读取自身预测，真值用于首帧初始化和事后统计。

0.05 和 1 个目标尺度为本轮单一固定设置。作为归档支持核对，Stage-120 已存的 778 个决策点中，492 个满足分差条件，其中好 q0 被错换的 21 点里满足 14 点，正确救援的 8 点里也满足 4 点。现有表未记录按本轮定义归一化所需的两个框面积，不能由此重建完整触发。抽样含旧压力点，这些计数也不代表全轨迹触发率或净收益。该核对未用于改阈值。

## 对照及判据

使用 Stage-113 的 28 个已消耗开发视频。主比较为 `alternate_shared` 对 `generated_shared`，两种评分器种子均纳入。另与 `fixed_shared` 和原生 SGLA 对照。按视频先平均种子，再做配对 bootstrap，报告 AUC、低 IoU 比例、最长失跟、原生可靠帧 AUC、候选供给和恢复事件。逐轨迹记录请求／实际替换／备用槽位获选次数、首次替换帧和物理搜索量。发生首次替换以前，两组的框、裁剪、响应、评分和选择须一致，首次替换时实际调用数须相同。全程每帧最多四次搜索，轨迹分叉后因裁剪重复数可能不同，实际调用总数分开报告。

开发门槛要求主比较 AUC 至少 +0.5 点且配对区间下界大于零、两个种子均正、最长失跟减少、低 IoU 比例不升。还要求相对三个对照均无原稳定视频新增失败和丢失匹配恢复，相对原生的可靠帧 AUC 区间下界不低于 −1 点，总 AUC 不低于原生和固定共享。通过仅表示开发结果值得再验证。

当前 GPU 的完整运行身份（包括 UUID）与 Stage-113 一致时，复用 140 条已封存对照，新跑 56 条。换卡时，三组对照与新策略在同一张现用卡上重测，共 196 条；单个输出目录续跑须保持同一运行身份。确认集未接入本轮。

## 运行与回传

在具有原检查点、Stage-76/89/93/112/113 原产物、VisDrone-SOT 和 L20/L40 的服务器上，从仓库根目录执行：

```bash
bash tools/run_stage121_search_state.sh
```

默认使用 CUDA 逻辑索引 0；可用 `STAGE121_GPU` 指定索引，用 `STAGE121_ROOT` 指定独立结果目录。完成后打包 `output/stage121/alternate_search_state_v1/stage121_results_*.txt`，包含决策、策略、配对、逐种子视频、调用账本和恢复对照。已有完整运行可用 `bash tools/run_stage121_search_state.sh --pack-only` 重新校验和打包。
