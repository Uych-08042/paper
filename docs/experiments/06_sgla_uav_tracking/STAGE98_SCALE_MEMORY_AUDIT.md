# Stage-98 尺寸写入、引用与首次分叉审计

Stage-97 的自身可信历史尺寸方案新增一次恢复，同时丢失两次原有恢复。其实际裁剪已发生变化，且在平均 IoU 为 0 的窗口中仍多次写入尺寸。Stage-98 利用已有缓存检查这些写入如何进入后续引用，以及影响发生在分叉前还是分叉后。

## 样本与来源

绑定 Stage-97 决策 `54a55559198296e8ed7d8ca719dcc4aa5ac5d7929e413c621ebf56ab337aead3`，审计全部 25 个固定事件、50 条分支、6,324 个分支帧。包含新增恢复的 0226／2171、丢失恢复的 0307／2172 与 0076／2172，以及其余事件。

control 和 trusted_scale 的窗口起点相同。分别从原 G 来源轨迹重建起点前的历史框和尺寸记录，再以各分支保存的输出逐帧更新。引用必须来自当前帧之前，且重建的父框、尺寸引用、裁剪、写入资格和尺度变化标记必须与 Stage-97 缓存一致。窗口 IoU、末帧 IoU、恢复匹配时刻及写入计数也重新核对。

## 诊断读数

记录两组第一次父框、裁剪几何、裁剪像素、浮点输出框、取整输出框和选择槽位的差异。另定位第一次丢失／新增好候选，以及 control 有好输出而新组低 IoU、或相反的时刻。好框阈值为 IoU ≥ 0.5，低 IoU 为 < 0.2，沿用既有协议。

每帧记录是否接受尺寸写入、写入时的 IoU、输出尺寸误差、q1 搜索父框尺寸误差、目标在 q1 输入中的像素大小和覆盖率，以及最终选中框的 Hann 响应。尺寸误差定义为宽高比例的绝对对数均值。低 IoU 写入与尺寸误差分别记录，因为位置错误时也可能输出接近目标的宽高。

逐条引用记录来源帧、是否来自窗口前缀、来源帧的 IoU 与尺寸误差。统计低 IoU 记录被读取的帧数和次数，便于区分反复引用少量错误记录与持续新增记录。

control 中的写入计数表示按相同资格可接受的诊断记录，其实际历史尺寸使用全部最近预测框。trusted_scale 的尺寸记录才进入新增规则的引用。因此两组的引用计数应按各自机制解释。

## 固定历史上的引用屏蔽

对 trusted_scale 当前实际使用的每条尺寸引用，分别屏蔽该记录，用同一历史、同一帧与原规则重新计算搜索父框。规则可能补入更早记录，或因不足两条记录而回退到原历史尺寸。

记录屏蔽是否改变父框、是否改变取整裁剪，以及 q1 的尺寸误差和目标覆盖率如何变化。几何重算不读取新图像，也不改变后续历史。没有对替代裁剪重新推理，因此这些读数无法直接说明屏蔽后会选到什么框或能否恢复。

若错误记录被反复引用且屏蔽会改变裁剪，可进一步在少量匹配起点验证其后继影响。若损伤先于错误写入，或删除记录几乎不改变输入，应继续检查尺寸估计与选择反馈。当前审计不修改 Stage-97 的门槛和规则。

## 服务器执行

在原仓库同步新文件后，激活 `sglatrack-test` 并执行。

```bash
bash tools/run_stage98_scale_memory_audit.sh
```

默认输入为既有 Stage-76、89、93、97 根目录，可通过对应的 `STAGE*_ROOT` 环境变量指定。CPU 运行，新增图像读取、GPU 推理、训练与确认集推理均为零。

默认输出为 `output/stage98/cached_scale_memory_audit_v1/`。回传脚本打印的 `stage98_results_*.txt`，其中包含 decision、事件表和分支汇总。逐帧与引用明细保留服务器。完成后可用 `bash tools/run_stage98_scale_memory_audit.sh --pack-only` 再次校验打包。

本机两项 CPU 测试通过，覆盖错误写入与窗口前引用、屏蔽后的裁剪变化、引用篡改拒绝、恢复指标重建、全流程重复发布、无效标注处理和零新增网络调用。Bash 语法检查通过。真实缓存仍在服务器，当前 SSH 认证未通过，正式审计待执行。
