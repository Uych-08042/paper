# Stage-187 相邻裁剪预测框一致性

Stage-186 发现，相邻的取整窗口可能改变 Hann 选峰，实际移动方向也尚未形成稳定规律。Stage-187 检验同一图像位置在多个不同裁剪中得到预测支持时，选中该位置能否保留后续跟踪效果。

## 固定候选和选择规则

- 复用 Stage-186 的 19 个变化点和 8 个稳定窗口。使用当前裁剪和已有的等尺寸邻域对照。原生参照及 0348 的尺寸对照继续保存在来源备档。
- 用相同的取整左上角和边长识别重复裁剪。每个窗口只保留浮点中心最接近基准的一个实际输出，等距时按来源分支顺序选取。保留删除的分支名单，并检查去重会不会去掉唯一一次安全挽救。
- 每个候选都是原图坐标下已有续跑的预测框。三个策略使用同一个去重池。当前裁剪保留基准输出，最高响应取最大 Hann 峰，跨裁剪一致性取与其余候选的平均 IoU 最大的框。一致性相同优先保留当前裁剪，再比较 Hann 峰和中心距。选择阶段只用预测框、搜索位移和响应。

## 评价

核对缓存中每个预测框与其续跑起点完全一致，再读取已观测的后效。比较第一后续帧 IoU、整段窗口平均 IoU、受保护挽救、恢复损失与窗末失跟。报告完整 128 帧、稳定对照和既往未覆盖事件的结果，分组配对，给出移除最大收益源组的敏感性。预设评价以原生参照判定挽救和伤害，同时记录当前裁剪本来获得的挽救。此实验复用历史诊断候选和续跑，无额外搜索、图像读取或训练。

## 运行

```bash
bash tools/run_stage187_crop_consensus.sh
```

运行只需要 Stage-186 完整缓存目录及现有 Python 环境。结果包位于 `output/stage187/crop_consensus_v1/stage187_results_*.txt`。若只有 Stage-186 回传文本，可用 `--bundle` 核对起点、去重后池大小及两个基线的挽救与伤害人数；一致性需要存有实际输出框的 NPZ 缓存。

已从 Stage-186 回传核验 27 个窗口的 189 个符合条件的分支，去重后为 134 个裁剪。15 个完整变化窗口中只有 3 个存在安全挽救候选，当前裁剪选中 1 个并在另一个窗口出现事件伤害，最高 Hann 选中 2 个且无事件伤害。8 个稳定窗口两种基线均无事件伤害。跨裁剪一致性的实际结果需读取服务器缓存。
