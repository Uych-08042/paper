# Stage-174 同放行预算的长窗退化监督

Stage-173 中，门控与排序层对齐后，取样组短窗有害放行从 2 降到 0，放行总数从 33 降到 13，未恢复事件仍为 5。0304 第 526 帧的 L11 仍被放行，随后在 554 帧失跟。Stage-174 检验较长窗口的监督能否在固定换层配额下改进风险排序。

## 起点与续跑

从 Stage-170 的其余 25 个开发视频抽样。每视频在实际换层、冷却否决及原门控拒绝的非原生提议三类中各取至多两个起点。采用固定哈希顺序，同一视频同一类的两个起点至少间隔 32 帧，且每个起点之后至少有 128 帧。排除 Stage-173 已评估过的全部起点。三个已知定点视频的全部源组退出分析拟合与主评估，单列 Stage-173 的六个原起点用于复查。

从同一历史父框和响应状态出发，各在起点执行原生层和 Stage-167 排序器推荐的非原生层。两条分支随后各自反馈预测框，并统一使用原生 SGLA 续跑。每帧核对一次裁剪、七个 Transformer 块和一次预测头。32／128 帧均只用完整有效窗口，续跑期间无需 GT 参与决策。用完全相同运行身份时逐点核对原动作框和门控输出，并复算六个定点的 Stage-173 后效。

## 拟合与固定配额

三组共用 Stage-167 的短窗收益预测和排序候选。`frozen32` 使用该排序层原有的 32 帧退化模型。`refit32` 和 `refit128` 用相同的岭回归、输入和分组权重重新拟合，只改监督窗口。输入为 27 维历史与视觉状态、原生层和排序层的独热编码。监督目标为对应续跑窗口 `max(0, IoU_native − IoU_ranked)`。沿用 Stage-159 的源组两折划分，按 fit 源组等权，留出折只打分和评估。三组各按收益减风险分数取留出折中排名最高约 40% 的点，配额四舍五入且三组完全相同。配额只用于这轮离线比较。

严重退化定义为 128 帧平均 IoU 至少下降 0.05，或窗口结束时多出未恢复失跟。有益动作要求平均 IoU 至少提高 0.01 且无严重退化。比较严重有害放行、未恢复失跟、有益放行以及按源组等权的 IoU。至少有三个源组出现严重退化，且长窗组相对两个短窗对照都减少严重有害放行、保持有益放行、不增加新增未恢复放行并提高 128 帧均值时，才支持后续校准在线门槛。配对区间用于描述留出结果。三个定点视频单列，决策分数对照其所属留出折的分数截点。

## 运行

使用原始 checkpoint 和 Stage-170／173 输出目录。若本次 GPU 运行身份与此前 Stage-174 不同，使用独立的 `STAGE174_ROOT`。

```bash
cd ~/workspace/paper
mkdir -p output/stage174
nohup bash tools/run_stage174_long_horizon_risk.sh > output/stage174/run_stage174.log 2>&1 < /dev/null &
tail -f output/stage174/run_stage174.log
```

脚本记录总体进度，支持逐分支续跑。结束后生成 `stage174_results_*.txt`，其中 `stage174_summary.csv` 与 `stage174_paired.csv` 为主对照，`stage174_targeted.csv` 为已知案例复查。
