# Stage-153 难帧串行加算一个 Transformer 块

比较原生 SGLA 与自适应深度 SGLA。在同一帧沿用原生选择器选出的后段块，当选择器难以区分前两名时，取这个块的输出继续通过下一个物理编号的块。例如原路由选 L9 时，加算路径为 L1–L6 → L9 → L10，然后接原归一化、CENTER 预测头和 Hann 解码。已有 Stage-137 的额外块从同一份 L6 特征并行取候选。本轮从被选块的输出串行加深。 [Stage-137 结果](STAGE137_RESULTS_REVIEW.md)

## 路由规则

- 原生分支固定先计算 L1–L6，然后执行一个选中块，总计 7 块。
- 自适应分支以选择器前两名分差为难度信号。第 1–32 帧积累分差。从第 33 帧起，用之前最多 64 帧分差的第 25 百分位作门槛。当前分差严格小于门槛，且选中 L7–L11 时才串行加一块。选中 L12 时直接输出。
- 模板、搜索框取法、裁剪倍率、权重、原选择器、预测头和输出解码均沿用原生 SGLA。每帧仍只有一次搜索裁剪和一次预测头调用。每组均把本组输出作为下一帧状态，首帧以原标注初始化。
- 分差是选择器不确定性的可观测代理。门槛计算只用本组历史分差，未使用 IoU 或人工难度标签。保留现成权重后的串联输入属于本轮需要验证的设置。

## 对照和输出

在同一张 L20 或 L40 重跑 28 个 VisDrone-SOT 开发视频，预计 56 条完整轨迹、58,094 次搜索。校验每一帧的裁剪、选择器、头部及 Transformer 块调用数。两组第一次加算以前逐帧输出须一致。来源运行身份相同时，原生组须复现 Stage-121 的原生框和被选块。

报告成功率 AUC 的逐视频配对差及 95% 区间、低 IoU 比例、最长失跟比例、未恢复事件和原生稳定视频新增失跟。报告加算帧数、每帧平均块数，以及按视频统计的中位数和 P95 跟踪耗时。耗时含裁剪、推理、解码和两组共有的观测开销，剔除前 10 帧并排除读图。该两组设计测量整个自适应加算规则相对原生的净收益。相同额外计算预算下的触发选择价值需用另一个对照回答。

## 执行

同步代码后，在训练服务器仓库根目录的 `sglatrack-test` 环境执行。需要原 SGLA 权重、VisDrone-SOT 图像，以及 Stage-76、89、93、121 的完整产物。首次可用 L20 或 L40，两组在同一卡上运行。换卡后续跑时用新的 `STAGE153_ROOT`。

```bash
mkdir -p output/stage153
nohup bash tools/run_stage153_adaptive_depth.sh > output/stage153/run_stage153.log 2>&1 < /dev/null &
```

默认目录为 `output/stage153/serial_one_block_v1`。完成后回传其中的 `stage153_results_*.txt`。
