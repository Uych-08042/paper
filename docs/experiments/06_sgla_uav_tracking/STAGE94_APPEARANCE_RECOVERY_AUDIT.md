# Stage-94 筛选历史外观的恢复诊断

Stage-93 在 28 个开发源组上比原 PPO 平均高 0.74 AUC 点，区间跨零。原 PPO 的 25 次恢复有 4 次未在规定窗口内匹配到。Stage-94 用原轨迹和同一帧的候选检验：到原 PPO 恢复时，筛选历史这条轨迹是还有好框却选错，还是四个候选都已经缺少好框？在有好框的情况下，屏蔽哪次历史写入会改变选择？

## 样本和对照

- 固定 Stage-93 L20 结果指纹。重算并核对全部 25 次原 PPO 恢复，保留 21 次匹配事件作为对照。四个未匹配事件来自 `0147`（2172）、`0226`（2171）与 `0307`（2171，两次）。
- 每个事件从 PPO 失跟起点前 32 帧开始，至原恢复帧后 15 帧窗口最后一次可能的连续三帧恢复判定，按视频边界截断。另从完整轨迹记录首次换框、首次输出差异、裁剪几何差异和裁剪像素哈希差异。首次差异给出时序线索，损伤可能在审计窗口前已累积。
- 同帧对照包含原 PPO 自身输出、筛选历史输出、在筛选历史当前候选上保留该帧 PPO 选择、使用固定首帧外观，以及依次屏蔽一条当前实际参与打分的历史引用。屏蔽后重新执行原引用规则，因此可能补选更早的已写入特征，也可能回退到首帧外观。
- 各替代动作固定当前图像裁剪、四个候选、PPO 提议与已有写入，计算后立即丢弃。替代动作不改变下一帧，也不重写后续记忆。GT 仅用于记录 IoU、候选是否可用和恢复时间。完整确认集封存。

## 产物和判断

| 文件 | 内容 |
|---|---|
| `stage94_events.csv` | 每次事件的恢复对齐、首次伤害换框和候选不足时刻，以及窗口平均 IoU 差 |
| `stage94_frames.csv` | 每帧原 PPO 和筛选历史的最佳候选 IoU、实际选框、写入与引用、固定首帧对照 |
| `stage94_reference_drops.csv` | 被屏蔽的写入帧、当时 IoU、重选的引用和选框、当前帧是否从低 IoU 变为良好 |
| `stage94_decision.json` | 来源、代码与表哈希、事件数、零训练和零新推理预算 |

关注两种证据。若同状态保留 PPO 或屏蔽单条引用就能从 IoU < 0.2 变为 IoU ≥ 0.5，先定位该次决策或写入。若筛选历史四个候选都达不到 0.5，而原 PPO 同帧有好框，先回查裁剪分叉及其前序状态。将实际输出 IoU 差分解为同状态选框差和不同状态下的 PPO 输出差，重叠的事件窗口不合并为显著性检验。单帧回放无法验证整段是否恢复，也无法单独证明反复切换的闭环影响。

## 运行

在服务器仓库同步新脚本后，使用原 `sglatrack-test` 环境执行。脚本只读 Stage-76、89、93 缓存及已封存的开发标注条目，无需分配 GPU、加载模型或打开图像。目录与 Stage-93 不同时用 `STAGE76_ROOT`、`STAGE89_ROOT`、`STAGE93_ROOT` 指定。

```bash
bash tools/run_stage94_recovery_audit.sh
```

默认输出 `output/stage94/appearance_recovery_audit_v1/`。先回传脚本打印的 `stage94_results_*.txt`，它包含决策和全部 25 个事件。逐帧和引用屏蔽两张明细表保留在同一目录，供按事件复查。
