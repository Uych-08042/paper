# Stage-92 短时历史外观诊断

Stage-91 的固定首帧外观保住了 `0091` 的原 PPO 恢复，却漏掉了 `0147` 的备选恢复。在同一组 158 个候选对上，Stage-92 检验此前已接受的框能否提供外观增量。保留原 SGLA 权重、候选布局和冻结 PPO 的后续行为。

## 四项对照

外观仍使用位置编码前的 patch 特征与 Stage-91 的前景池化。每次计算备选减原 PPO 的外观相似度。分数为正时切换，沿用原有数值容差。

| 对照 | 比较的参考外观 |
|---|---|
| 固定首帧 | Stage-91 原首帧目标框 |
| 近期历史 | 前 12 帧内最近的最多 3 个已接受框，帧间至少相隔 3 帧 |
| 筛选历史 | 同一时间范围、配额和间隔，只取通过预测可靠性检查的已接受框 |
| 首帧与筛选历史 | 首帧相似度差与筛选历史相似度差各占一半 |

可靠性检查沿用 Stage-89 的 0.50 归一化中心距离和 0.05 Hann 差作为固定尺度。入选的历史框相对上一输出中心移动不超过 0.50，Hann 峰值距当帧最高值不超过 0.05，且没有分差 ≤ 0.05、位置相差 ≥ 0.50 的不同候选。所有筛选只用历史预测，不看当前帧或后续标注。历史框的可见覆盖按 Stage-91 规则检查。少于 2 个有效历史框时回退到固定首帧。历史相似度是对各已归一化描述子的余弦相似度取均值。

## 预算与评价

只重放每个起点的两个已知候选槽位，以及历史参考帧的已选槽位。每窗口至少 2 次、最多 8 次原生搜索，总量上限 1,264 次。两组共有的历史帧只执行一次搜索。逐槽核对框、裁剪、响应特征和调用预算。固定首帧的两个分数也逐窗口复现 Stage-91。无需复算完整候选集，已有动作对由 Stage-89 冻结。

主读数为冲突组相对固定首帧的后续 15 帧平均 IoU 和低 IoU 帧比例。同时报告相对保留 PPO 的结果、排序 AUC、历史可用率、实质收益或损失的切换，以及两种独有恢复。按源组汇总。无训练、无新增续跑，确认集封存。本轮在固定轨迹上观测一次切换，持续在线更新另需验证。

## 服务器运行

同步代码及仓库里的 Stage-89、Stage-91 结果包，激活 `sglatrack-test` 后在仓库根目录运行。

```bash
bash tools/run_stage92_recent_appearance.sh
```

默认读取 Stage-76、Stage-89 缓存及原始 checkpoint。优先用原运行的 L20，其他 GPU 也必须通过候选和固定首帧分数复现检查。运行目录绑定卡的 UUID，换卡使用新 `STAGE92_ROOT`。完成后脚本打印结果 TXT 路径。
